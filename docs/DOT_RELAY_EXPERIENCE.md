# dot 面板：轻量传话与反馈体验

## 产品边界

面板不是第二个 AI 执行器。它保存用户消息，通知当前已加入的 dot，展示 dot 经插件发布的文字、进展与实际执行回执。理解要求、是否查资料或做事、如何使用工具仍在 dot 侧。面板不调用第二套模型、不复制私人 dot 历史、不通过浏览器代替 dot 执行业务任务。

本轮在已有双向、无模式对话基础上优化日常操作和故障恢复。真实原生宿主的模型判断和响应时延不能由本地浏览器测试代替；本功能也不宣称实现附件、语音、原生记忆或每个 token 的实时输出等全部原生 dot 能力。

## 从进入对话到收到回复

**进入。** 房间只有一个有效双向 dot 时，输入框显示它作为默认接收对象，可以直接打字；有多个时明确选择。用户主动清除对象后不自动选回。对话默认使用专注布局：桌面保留房间导航，隐藏不相关的监控、目标表单和任务侧栏；手机优先留出消息及输入空间。“管理视图”可以随时切回原有管理入口，不移除旧 CPJ 或任务用途。

**发送。** 点发送后立即出现待发送气泡，输入框立即腾空并保留焦点，可以继续补充，而不是等一次保存及多项状态查询全部完成。每次真实发送具有独立消息标识，重复相同文字的两次明确发送也不会被错误合并；同一次传输重试使用原标识。

**连续说。** 同一个 dot 和项目中的连续发送沿用原话题，后续消息需要前一条服务端标识时依序发送。用户不必每次点回复或重复 @。点击“新话题”另开话题；选择明确回复、切换项目或其他 dot 不会错接旧话题。

**看反馈。** 日常只展示一条来自实际记录的状态：等待接收、已送达 dot、dot 正在回复或处理、等待继续反馈、已回复、需要关注等。不再把旧提醒投递状态和已完成回帖同时放在消息下。HTTP 接收不等于模型已读，状态不声称模型常驻在线。

**继续追问。** 收到回复后继续在原话题交流。消费者说明要求在工作关键步骤和最终结果前核对新消息，读取补充或纠正；这不等于浏览器能抢占模型回合或任意终止正在运行的命令。

## 回复阅读与 UI

正文支持安全的 Markdown 标题、列表、引用、代码块和表格。代码块及整条消息可复制，长代码、表格在自身区域横向滚动。远程图片不会自动加载，原始 HTML 和脚本不会执行，危险链接不会成为可执行链接。

任务状态、操作 ID 和回执仍保存，但收进“查看执行记录”；用户先看到 dot 说了什么，而不是先阅读任务管理面板。阶段性系统收件提示弱化展示。输入框随内容增高；保留中文输入法保护、桌面 Enter 发送与手机换行行为、键盘焦点及安全区。

消息更新不整块替换正在阅读的 DOM。代码区、展开详情、输入框草稿与光标尽量保持；用户选中文本时延后该段渲染，上翻阅读时保持可见位置，新消息不强行拉到底部。关闭详情支持原生 Escape 与点击遮罩。

## 增量回复不是伪造流式

新增 `collaboration(action="dot_update")`，允许当前绑定 dot 更新它自己尚未结束的阶段性回复。请求带原 message_id、expected_version 和稳定幂等键，提交完整的当前正文。服务端返回新的 update_arguments；旧版本不能覆盖新文字，重复传输不能插入第二条回复，已经最终结束的回复不能重新打开。

dot 可先用 `dot_message(complete=false)` 发布真实的初步内容，再通过 dot_update 补充同一条回复，最后 complete=true。面板只展示实际收到的更新，不用假打字动画伪装模型正在生成 token。普通回复不能作为执行成功证明，实际任务仍需原始工具终态和结果校验。

## 可靠发送与恢复

浏览器使用独立于管理按钮的内存发送队列。网络中断、超时或 HTTP 成功但缺少有效回执时，先按原 client_message_id 查询服务端是否已经保存；已保存则接回原消息，不重发正文。确实尚未确认时最多进行三轮有界恢复，之后保留原消息的显式重试入口，不无限循环。

一条消息异常不会擦掉正在编辑的下一段草稿。 同一话题有未确认的前序消息时，依赖它的后续消息保持顺序；一条失败消息不会阻塞另开的独立话题。已经进入服务端的消息在浏览器断线后仍保留。未到服务端的消息和草稿暂存在页面内存，**不写入 localStorage/sessionStorage，也不承诺关闭标签页后恢复**；离开页面且存在未发送内容时提示确认，重新联网后继续传输。窗口内切换房间保留对应内存状态，退出登录和授权可见性变化时清除，不让迟到响应把旧私有内容写回。

服务端另外维护未消费消息的恢复提醒。只有原授权、房间、dot 和原生订阅仍有效，才向原订阅补一次通知；同一个 dot 的多条待办合并唤醒。默认退避 30/120/600 秒、最多三轮；收到 dot 确认或阶段更新后延长等待，最终处理过的消息不再恢复。恢复不创建新业务任务、不重跑原操作、不恢复已暂停订阅，也不绕开 HTTP 410/413 或回调策略的永久拒绝。沿用项目共享通知频率预算。

## 减少同步成本

对话页使用只读 `/api/collaboration/relay-sync`：一次获取新消息、最多 24 条已展示消息的最新版本和紧凑连接状态。无需每次重复请求完整目标、探针、策略详情和多个逐条回执，加入说明等长文本也不会反复传输。

有新交互或正在反馈时约 1.5 秒核对，空闲约 5 秒；错误时指数退避，后台标签页不持续拉取，回前台和恢复网络时立即核对。请求有超时和同一页面内的并发保护。这个间隔是面板同步节奏，不是对真实 dot 生成速度的保证。

## 验证入口

`tests/test_collaboration_dot_relay.py` 覆盖版本化回复、重复与乱序、最终回复不可改写、跨 dot/连接拒绝、只读批量同步隔离、离线待办恢复、接受通知但未消费、重启后恢复次数、暂停/撤权和永久拒绝、共享通知预算。

`tests/test_collaboration_dot_relay_flow.py` 使用真实隔离 Hub、MCP、Chromium 和 WebKit，注入服务端已保存但响应丢失、离线恢复、无效成功回执与迟到授权响应；核对不重复发言、连续消息上下文、输入焦点、富文本安全、回复原位更新和原有管理入口可达。

原有普通双向聊天、聊天到真实 Agent 文件/命令操作再回到聊天，以及旧 CPJ/委托流程继续回归。测试消费者只是用于验证传话协议，不冒充真实原生 dot。最终验证数量、被测提交及真实宿主未验证范围记录在本轮验收附录。

### 运行时设置与验收语义补充

- **凭据来源存在不等于已登录。** clean runtime 的 credentials 默认启用复用，configured 仅表示有环境变量、配置位置或 agent socket，未验证真实账户。UI 应显示“已配置来源／未验证登录”，明确每一项作用与关闭选择；不能把 clean 误写成完全无主机凭据。省略字段保留同模式的既有选择，切换模式后返回 clean 会恢复默认值，应在确认摘要中显式说明。
- **保存、加载、连接与执行版本分别显示。** runtime panel 测试已有 pending_reload 与 applied、离线 profile=null、配置 CAS、原操作回执恢复及在途命令保持旧运行时的断言；设计不应把保存成功当作正在执行命令已改模式，也不需要重新启动在途命令。
- **隔离证据只对当前操作有效。** Docker 合成检查区分 verified_for_operation、workload outcome 与 cleanup pending；未知 create 不猜容器名删除或换新 ID 重跑。CI YAML 中存在强制容器验收步骤只能证明门禁配置，不证明本轮实际通过。
- **测试平台和断言力度必须实标。** managed runner 是 POSIX-only 测试；runtime_hardening 的 FIFO 场景在非 POSIX 返回，不是 Windows 通过。validation_lifecycle 的相对路径用例实际上注入拒绝 guard，仅证明执行前拒绝的次序，不能单独作为真实路径穿越防线验证。settings_center 的 coalesced 命名用例执行顺序 GET，只证明缓存，不证明并发请求合并。运行时11文件全文3154行回执 （内部研究记录），未执行测试。

### 操作续接、通知与任务确认的设计约束

- **取消等待不等于取消工作。** 操作续接测试覆盖超时、断连与单读者取消后原操作继续，UI 应同时提供“停止等待”和有明确后果的“取消执行”，查询终态沿用原操作身份。compact 结果已结束但尚未取回证据时，应“查看结果”，不能循环等待或重新执行。`test_operation_continuation_integration.py` 是 POSIX `/bin/sh` 临时栈，不是 Windows 或生产验收。
- **收到完成提示不等于读取结果。** completion event 是最小化、可过期的通知，需按链接重读当前原回执；unknown/cancelling/reconnecting 不属于完成。callback accepted 不证明助手读取、回复或任务完成；测试回调更不启动真实工作。撤权或目标变化后的扣留不表示既有效果已回滚。
- **确认必须展示所确认的原问题与范围。** owner task 的“可以”在多问题或话题切换后可能歧义；跨渠道应显式绑定确认码与原问题，过期、取消、已更改方案不可被礼貌回复复活。owner continuation confirmed 仍不满足主机工具审批，不可合并成一个“已授权”徽章。上下文缺失提供原文读取入口，不展示为完整历史。
- **背压要解释原因而非伪装离线。** 原生历史同步被拒绝后的暂停、退避和 metadata probe 与控制帧可达性不同；列表应区分历史同步延迟、当前连接和实际任务进度。内存压力可允许小读写但拒绝命令，不应只用全局“不可用”覆盖能力差异。
- 以上补充来自 14 份测试 / 3459 行逐文件语义研究（（内部研究记录）），没有执行测试。`owner_task_context_flow` 与 `collaboration_delivery_flow` 的 legacy UI 场景不能补齐当前 room 视觉缺口；后者注释中 shipped module 与实际 legacy fixture 路径也需在验收文档中澄清。

### 最终测试证据校准原则

- 快照执行允许返回明确“不支持”；此分支通过不证明该平台实际完成 COW 快照。安全 MCP 隧道、SSH 与存储场景也必须分别注明模拟服务和真实系统工具边界，不能沿用文件名作验收结论。
- 长期订阅寿命文档模拟只证明预期算法，不代表线上订阅已具备无限续期；旧协议矩阵使用冻结 wire 形状和当前二进制，不是真实历史版本兼容实测；FakeStore 的 base64 可逆替身不构成真实加密安全证据。
- 知识维护的后台任务来源、调度与结果状态应单列，不能当作用户主动执行或当前主任务占用；只读原回执恢复不应被展示层错误引导为申请写权限。
- 本轮静态全文覆盖是设计输入完成度，不是产品通过率。后续发布门禁分别记录真实当前页面、替身 UI、合成协议、真实本地进程、真实目标平台、外部服务与生产只读证据，任何一列的通过都不能替另一列打勾。

## 1. 结论：停止补丁式美化，先重新组织工作

当前问题不是缺一个好看的按钮，也不是再换一套灰色。面板同时承载运行控制、项目开发、聊天、协作、身份授权与系统维护，但用户在同一视觉层级里接触到过多不同生命周期的对象。多轮优化已经完成不少控件与响应式修复，继续按旧设计逐项追加 CSS，只会把更复杂的状态包在更精致的盒子里。

建议保留现有路由、服务端权限与持久操作协议，先完成四项结构调整：

1. **按用户下一步组织页面**：需要处理什么、在哪里继续、哪些只是背景信息。总览不再做所有统计的容器。
2. **对象、状态、操作分离**：电脑在线不代表任务执行；已保存不代表已生效；消息送达不代表工作完成；Hub 可用不代表更新器收尾完成。
3. **一个组件一个视觉所有者**：共享组件处理形态、键盘与反馈，功能模块只提供数据、内容和允许的动作。不再让同一控件在多个样式文件末尾被补写覆盖。
4. **把真实完成标准写成场景**：没有溢出不等于好用；截图生成不等于看过；旧界面 fixture 通过不等于当前界面被测。

这不是重写框架的授权，也不建议先引入大型 UI 库或编辑器。优先在既有零外部前端依赖体系内实现可验证的小步迁移。

## 2. 证据口径与范围

全仓 Git 受管基线为 **1,486 个文件**。每个路径在配套台账中分配审阅域和审阅级别，不能把路径计数当成逐行语义证明。

- `semantic-read`：正文语义阅读，有对应职责或发现。
- `partial-semantic-read`：只深入了明确范围，剩余仍待复核。
- `static-classified`：读取结构、导入/导出、测试/标题等并分类，不宣称全文深读。
- `generated-reference`：生成物关联到源文件及生成入口，不在压缩产物上重复设计。
- `blocked` / `pending`：明确未完成，不能从无发现推论无问题。
- 运行证据另外记录环境、页面、视口、状态、断言和结果。上述任意静态级别都不代表运行通过。

旧文档的 1,133 项测试、此前 WebKit 重复轮次与旧生产只读检查属于历史证据，不计入本轮通过数。`dist` 中历史包、旧截图、运行日志不当成当前页面源码，也不为扩大覆盖率解包复制；本轮仅盘点其边界。凭据、个人浏览器资料和生产数据库不在研究输入范围。

## 3. 旧方案需要修正的决定

依据 `UI_UX_OPTIMIZATION_DESIGN.md` §3、§6、§7 与该文 §10–12 的实施记录，本轮不重复要求已经落地的配置胶囊、命令入口、权限下拉、工作台分隔条等改动。

| 旧思路 | 本轮决定 | 原因 |
| --- | --- | --- |
| 一律调浅输入边框以更精致 | 保留可辨认的控件边界；颜色只在已测对比与实际背景下调整 | 旧文 §11 已记录弱边框回退，不能再次引入同一退化 |
| 所有恢复按钮统一叫“重试” | 区分“查询原结果”“继续原操作”“重新执行” | 传输失败不证明业务未执行；最后一个动作可能产生新副作用 |
| 删去所有“不是/不会”等解释 | 删除重复正常说明，但保留决策时的范围、费用、删除与未知结果提示 | 渐进披露不能变成隐瞒后果 |
| 所有首屏必须看全统计+最近操作+项目 | 首屏只保证当前主要任务和下一步，辅助信息允许纵向展开 | 320px、缩放、长文案下强塞内容会牺牲可读性 |
| 点击数减少40%即完成 | 测完成率、定位下一步时间、误操作与草稿保留；点击数为辅助 | 必要身份和权限确认不应为减少数字而移除 |
| CSS冲突候选为0代表统一 | 建立源所有权、最终 computed style 和交互合同 | 合法响应式覆盖不应清零；扫描器也无法证明所有视觉冲突不存在 |
| 只要全绿测试就“全站完成” | 每个页面标明真实路由/fixture、角色、状态和平台 | 历史替身、静态断言与真实页面有不同证明能力 |

## 4. 信息架构：让用户按任务进入

### 4.1 导航原则

先不删除现有深链接。建议用四个稳定分组，保持已打开对象与返回位置：

- **工作**：总览、项目、CLI 会话、协作房间。项目工作台从项目进入，保留旧入口别名。
- **运行**：电脑、VPS、操作记录与队列。运行视图关注执行位置、当前活动和故障恢复。
- **接入与权限**：客户端连接、成员与角色、访问配置。把“连接”与“具有什么权限”分开解释，不把 OAuth、PAT、Profile、Role 合成同一个概念。
- **设置与维护**：个人偏好、实例设置、更新与备份。始终显示当前作用域与管理者。

桌面可展开分组；窄屏用同一可搜索导航抽屉，不再造第二份路由目录。命令面板、面包屑、导航和页面标题共用路由注册表。显示名允许简短，术语别名用于搜索而不是让每页各起一个名字。

### 4.2 对象关系

`空间 → 项目 → 工作目标` 是上下文，不等于授权。电脑是执行位置；VPS 是经指定项目 Agent 连接的远端目标；CLI 会话是原生历史；房间是多人/多助手沟通上下文；工作项是持续推进记录；操作是一次实际调用。页面可以关联这些对象，但不得把计数或状态直接互换。

全局顶栏固定展示空间与当前页面。项目级页面额外显示项目、执行位置、环境；发起执行前的目标摘要不可仅藏在 tooltip 内。身份/空间/项目改变后，旧响应与旧确认失效，不能把统一外壳当成共享所有缓存的理由。

## 5. 页面模板与逐任务流程

### 5.1 总览：工作入口，不是监控墙

首屏只保留“需处理”和“继续工作”两块，随后是最近项目/会话。需处理卡仅列当前真实阻塞或待用户决定的事项；没有事项时显示安静的正常说明，不制造红黄告警。每项必须有对象、具体原因、核实时间和一个对应动作。

首次使用引导仅在实际未完成时显示，用户可收起；已经接入但选择暂不连接外部客户端不应永久显示失败。费用估算移入可展开摘要，明确不是账单；缺数据用一个范围说明，不重复堆叠多个“未记录”。技术调用名放详情，摘要用用户动作和项目。禁止把“未观测到”自动解释为“没有”。

### 5.2 项目、电脑和 VPS：统一实体列表，保留不同含义

默认项目列表服务于“找项目并继续”，不展示所有管理按钮。每行：名称、可区别的设备/路径、运行可用状态、继续/打开与更多菜单。桌面提供列表/卡片视图，记住偏好；移动不强迫同一行塞下所有按钮。路径在同名冲突时必须可辨认，复制为明确按钮，不依赖悬停。

电脑显示在线性、最后观测时间和能力状态，单独展示版本是否支持所需能力。VPS 保留主机密钥验证与项目绑定要求；首次连接要清楚区分“尚未信任主机”“认证失败”“Agent 不可达”，不能为减少一步而默认跳过主机验证。

详情抽屉按概况、能力/权限、维护分层。删除/撤销与更新不挤在日常打开动作旁。维护动作说明具体目标与影响，不用统一“确定吗”。

### 5.3 工作台：先明确编辑与执行边界

标题区固定目标项目与当前文件；工具栏按文件操作、查找/Git、执行输出分区。宽屏使用可调目录树/编辑区，窄屏通过明确“文件/编辑/输出”视图切换，保留同一草稿、滚动位置和未保存标识。

输出面板的“正在运行/已结束/结果待查询”独立于网络连接状态。用户阅读上方日志时不强制滚底，显示“有新输出”。复制/下载输出须说明当前已加载范围；截断仍可恢复则提供原操作分页，不可恢复则如实说明，不提供无条件重新运行按钮。

Diff 默认逐文件，标明快照来源和新旧行号。长行允许局部滚动；颜色之外使用增删符号。不要把编辑器重构为大型 IDE 作为本轮统一界面的前置条件。

### 5.4 CLI 会话：一条对话主线，目标与待处理动作清晰

新对话选项目后进入草稿，首条消息才创建真实会话。配置胶囊在发送前可见，但不能成为辨认目标的唯一入口。历史过滤与当前发送目标明确分开。所有审批卡统一展示动作、工作目录、风险与允许范围，再给允许/拒绝。

会话目录、模型设置保存、消息发送、附件上传分别持有状态；不能用一颗“在线”圆点代替。列表新消息不重置阅读和选区。删除网页记录与停止原生进程不同，必须在动作名称及说明上保留区别。

### 5.5 房间：对话为主，工作和投递为关联视图

房间顶栏保留参与者、项目范围与连接入口。主区不同时铺开成员矩阵、投递诊断和工作列表。工作摘要与来源消息相互跳转，详情在侧面打开；移动使用可返回的全屏详情，不把背景继续暴露给键盘。

每个工作摘要展示一个主要执行阶段、一条最需要处理的原因及对应动作；若同时存在待用户输入或授权，与执行进度并列保留待办入口，不能让运行中掩盖用户待办。消息接收/助手读取/执行/成果投递仍作为独立证据保留。聚合状态是展示投影，不写回真实状态。微信三步向导可以减少重复文案，不能删除服务端需要的本人、范围和绑定确认。

### 5.6 接入、成员、设置、审计：少入口重复，不能少作用域

连接页默认提供当前连接与下一步，协议高级选项按需展开。授权预设显示最终项目/能力/期限摘要，禁止自动纳入桌面控制或未来项目。成员角色编辑先预览权限差异，再保存并读取生效值。

设置中心是索引和受控编辑入口，不是复制所有模块配置的新数据层。统一字段呈现：名称、当前有效值、来源、作用域、编辑入口、保存/生效状态。保存和生效分开，409 保留草稿并显示冲突比较，不直接重试覆盖。

审计与队列使用统一筛选工具栏和详情结构，但不是同一数据集。队列数字显示计数对象、权限范围、截断及更新时间；审计导出标明当前页/当前筛选及上限。不要把“当前窗口”伪装成全量。

## 6. 统一状态语言与动作协议

| 实际情况 | 主文案 | 主要动作 | 必须保留的信息 |
| --- | --- | --- | --- |
| 正在只读加载 | 正在读取… | 可取消等待 | 旧结果如保留必须标时间 |
| 已提交持久请求 | 已提交，等待执行 | 查看进展 | 原请求/操作身份 |
| 已执行但响应丢失 | 结果待确认 | 查询原结果 | 不允许换键重放 |
| 排队等资源 | 等待可用资源 | 查看等待原因 | 排队不计作正在执行 |
| 明确失败且无未知副作用 | 未完成：具体原因 | 修正后重试 | 重试目标与是否新操作 |
| 配置保存但节点未应用 | 已保存，等待生效 | 检查生效 | 保存值与有效值分别显示 |
| 数据不完整/旧版本不支持 | 暂无法确认 | 查看原因/刷新读取 | 不转成 false 或 0 |
| 权限撤回 | 此操作已无权限 | 返回可访问范围 | 清除敏感旧内容，禁止继续 |
| 升级业务已可用、更新器收尾待恢复 | 服务可用；更新收尾需处理 | 查看恢复步骤 | Hub版本、更新器状态、提交阶段各自独立 |

视觉状态采用正常、进行中、等待、需处理、失败、未知六类外观映射，原始业务枚举完整保留在详情。warning 不等于 failure，unknown 不等于 idle。所有状态映射由领域适配器产生，不能在页面内凭字符串包含关系猜测。

按钮动作契约建议包含：`kind(read/submit/recover/destructive)`、作用对象、预期版本、pending状态、取消语义、成功判据、未知结果恢复入口。统一组件只处理展现与事件生命周期，服务端仍最终判定授权；禁止前端“便利”层扩权或隐式发起副作用。

## 7. 组件与 CSS 所有权

逐步收敛到：PageHeader、EntityList/EntityCard、FilterBar、StateNotice、EmptyState、FormField、SaveBar、ScopeSummary、DetailDrawer、ConfirmSheet、OperationTimeline、CopyValue。每个组件只拥有一份结构/键盘合同和一份样式来源。

迁移顺序：先盘点现有 CP 原语与调用者 → 建立代表性示例 → 将一条用户路径接入 → computed style/交互对照 → 删除该路径失效覆盖 → 再迁移其他路径。不能一次清空 styles.css 或改变全部选择器；生成文件只由既有构建入口产出。

组件分三层：语义令牌（颜色/字号/间距/层级）、共享原语（操作和焦点规则）、领域组合（项目/工作/连接）。聊天与房间可保留阅读密度和布局差异，但不应各定义一套按钮风险级别或保存反馈。浏览器扩展与 MCP Apps 有独立宿主尺寸与生命周期，统一语义而非强行加载整个面板 CSS。

视觉规格：正文优先14–16px、辅助信息不小于12px；44px作为触屏产品目标，桌面可采用紧凑控件但须满足相邻目标与键盘可达。页面标题/主体/操作顺序固定，主要按钮每个任务区通常一个。状态不能仅靠颜色。阴影、渐变、动画不作为解决认知负荷的主要手段。

## 8. 可访问性和响应式验收

以 WCAG 2.2 AA 作为评估目标，而不是本轮已认证结论。重点：文字和必要控件边界对比、焦点可见且不被粘性条遮挡、重排、标签与错误关联、状态消息、键盘操作。AA目标尺寸最小值与例外不等同于“所有元素44px”；44px是本产品触屏偏好。

- 表单错误同时靠近字段并在提交摘要可定位；不只弹 toast。
- 异步保存/复制用适当 live region，流式文本不能每个token重复播报。
- Modal 有标题、初始焦点、焦点限制与退出/恢复位置；非模态详情不能伪装成模态。
- 视觉 Tab、导航链接和筛选按钮区分语义；真正 tablist 实现方向键与选中状态，不能仅添加 role。
- 320/390/768/1024/1366/1440 宽度，以及200%缩放、短横屏、软键盘、长中文/英文/路径均纳入场景。目标不是机械断点数量，而是主要动作不被遮挡、局部滚动有边界、草稿与焦点可恢复。
- reduced-motion、forced-colors、更多对比度、浅深色各有真实检查；最终需实体 iOS/Safari、Firefox、Windows与读屏器验收，模拟视口不得冒充。

规范依据（本轮查询官方来源）：[WCAG 2.2](https://www.w3.org/TR/WCAG22/)、[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)、[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)、[APG Modal](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)、[APG Tabs](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。这些指导组件行为，不能替代代码现场验证。

## 9. 实施分期与完成门槛

| 阶段 | 范围 | 可交付件 | 退出门槛 |
| --- | --- | --- | --- |
| P0 设计冻结 | 状态/动作词典、路由对象关系、组件所有权 | 本文决策映射到具体文件和场景 | 无未决安全语义冲突；unknown/recover不再模糊 |
| P1 主路径 | 总览→项目→工作台/会话；需处理事项→原操作结果 | 一条完整任务路径，而非全站换色 | 桌面/窄屏/键盘/断线/草稿场景通过；没有授权扩张 |
| P1 信任与维护 | 保存/生效、队列计数、升级收尾、连接恢复 | 同一状态语言及领域适配器 | 原结果可恢复、状态有来源，未知不算成功 |
| P2 跨模块统一 | 房间、设置、权限、审计、端侧应用 | 共享原语、替换旧覆盖、帮助术语同步 | 每个迁移模块有源/生成物/测试闭环 |
| P2 平台与易用性 | 平台矩阵、读屏、首用任务观察 | 可复查验收和问题回流 | 未测平台明确标缺口；不得用静态检查代替 |

这里 P0 指设计先决条件，不声称发现了已证实的最高危安全漏洞。每批提交应只迁移一个行为闭环，保留回退入口但不回退用户数据。发布/部署另行授权。不得把原更新器未提交修复混入 UI 批次。

### 10.2 本轮测试研究给出的具体新增场景

以下是**后续实施验收计划**，不是本轮已运行结果：

1. 提交后丢响应，双击、切页返回、重连：同一意图仅一条业务记录，只查原receipt，参数变化不自动换键。
2. 配置PUT成功而Agent离线/旧revision：显示已保存但未生效，保留原有效值；上线后读回才切换。
3. A账号慢响应在B登录后到达：B的DOM、toast、存储、表单均不出现A内容或错误，旧成功不得关闭B弹窗。
4. 编辑/上传/未知回执期间401：权限重验通过才恢复原上下文，撤销即清除，503只重试认证不重发业务。
5. 每条当前路由分别制造加载、失败、空、旧缓存、新结果五态；空态和无权限不同，迟到结果不替换新页面。
6. 真实200%缩放/文字放大与320px窄屏：主操作不裁切、焦点不被sticky遮挡、只允许局部内容滚动。
7. 键盘开启菜单→表单→确认→异步通知，逐层关闭：Escape只关顶层，背景不可聚焦，来源消失时落合理焦点。
8. 中文IME、200字符中英路径、emoji与组合字符：Enter不误发送，SSE不丢选区，路径完整可复制且正确转义。
9. 当前cr-room在真实隔离SSE下丢ACK并重连：仅一个持久消息、原ID、下一条草稿保留，撤权旧响应不恢复内容。
10. NVDA/VoiceOver操作登录、错误摘要、加载/成功/确认：名称角色值正确、流式消息不抢读、status不逐token刷屏。
11. 固定数据/字体/时间的视觉基线：浅深色、多宽度，变更留diff并人工签核；截图存在不是断言。
12. 外观/偏好保存后刷新、重登、跨标签冲突：提示与读回一致，本机偏好与账号偏好归属清楚。
13. 普通用户/管理员/只读/撤权访问管理业务页：无权动作不出现，必要禁用原因可用键盘和触摸读取，无路径泄露。

15. 权限预览允许但节点离线或容器隔离未知：显示“策略允许／运行环境未核实”，不能将许可当可执行，也不能将unknown一律写成程序不可用。
16. 发布commit后更新器promotion失败、恢复后已有新确认写：保持原操作证据并展示收尾待恢复；禁止通用回滚引导，fake Docker/real SQLite用例不当作真实部署UI证据。

### 10.3 功能设计应输出的最小交付契约

每个后续实现PR附：当前痛点证据 → 设计前后流程 → 主要状态及允许动作 → 权限/数据边界 → 文件所有权和生成链 → 正反场景断言 → 真实运行结果与平台缺口。不要再用“做完所有视觉优化”作为无法验收的一个大任务。

推荐先做一条可感知闭环：**总览发现需处理 → 进入原工作/操作 → 看到准确原因 → 完成允许的下一步 → 返回原页面且草稿未丢**。若这一闭环不顺畅，先不扩散新的卡片和动画。

### 11.1 总览低保真结构（建议，不是当前截图）

桌面

“继续”优先返回上次明确打开且仍有权限的对象；没有确定上下文时显示可选择列表，不能擅自选择项目并发送消息。需处理栏可能为空，不用常驻的0计数撑版面。正在运行但不需要用户动作的任务放背景活动，不混入待办。

### 11.2 页面密度与控件规则

- PageHeader：标题、最多一行用途说明、一个主要创建/继续动作；长技术说明移详情。
- FilterBar：搜索、最关键两个筛选，其他过滤折叠；折叠后保留生效筛选数量及清除入口。
- EntityRow：名称 → 关键区分信息 → 状态 → 主动作 → 更多；移动改两行，禁止把长路径挤掉按钮。
- DetailDrawer：标题/对象固定，内容滚动，底部仅本次表单动作；诊断默认收起，但遇到错误时提供直接入口。
- 状态与数量必须说明对象：运行中的操作、等待资源的操作、未读消息分别计数，不使用模糊“任务N”。
- 复制成功不代表保存；保存成功不代表部署；加载成功不代表连接可执行。控件反馈文案必须使用其真实结果。

### 11.3 呈现适配器建议（新增设计，不是现有API）

```text
ViewState
  identity: 当前用户/空间/项目/对象版本
  activity: idle | queued | running | finished | unknown
  attention: none | input_required | approval_required | recovery_required
  outcome: unknown | succeeded | failed | partial
  observed_at, source, coverage
  primary_action: 明确动作kind、对象、当前允许条件
  details: 原始业务阶段、原请求、可见诊断
```

activity 不覆盖 attention；outcome 不能从 HTTP 200 或 connected 推出。当前服务端字段由领域适配器映射，是否新增字段须经过协议兼容审查，不要求为统一UI重写所有后端。客户端映射后的状态只能展示，不可代替服务器权限校验或回写成功。可见状态随权限变化立即失效；后台持久工作则按其授权和生命周期继续，不因离开页面被取消。

### 11.4 明确暂不做

不为了统一把 CLI 原生历史迁入 Hub 主库；不以“轻量UI”为由删除完整操作编号和诊断入口；不把所有设置变为远程可写；不默认开启浏览器/桌面控制；不重写所有房间消息协议；不删除旧兼容测试；不将本轮发现顺手混入更新器恢复补丁。

# CodePier Agent 生命周期管理

CodePier 1.9.0 的命名迁移在原运行时升级完成后独立执行，见 [迁移说明](CODEPIER-MIGRATION.md)。默认安装的目录和服务名会迁移；只保留配置身份、权限及历史语义，不把必要的路径字段变化说成配置逐字节不变。以下 v1.7.0 过程说明保留原运行时生命周期背景。

v1.7.0 在设备节点页补齐受管 Agent 的版本、更新、重启、卸载和修复升级链路。该能力只面向已登录的面板管理员，不作为公开 MCP 工具暴露，也不会让普通项目授权控制 Agent 自身。

> 本版本在本地完成实现、故障注入与回归测试；本轮没有部署生产环境。Linux、macOS、Windows 的服务适配代码均已实现，但真实操作系统服务的最终验收应在对应目标机执行。

## 本机命令入口（2026-09-17）

节点的 **完整管理** 中新增 **命令升级 / 卸载**，可以为离线节点生成带校验和目标身份检查的本机命令，不依赖安装票据，也不会调度任何远程操作。安装和更新后的管理入口为 `codepier-agent upgrade`、`codepier-agent uninstall`、`codepier-agent status`，Windows 使用 `codepier-agent.ps1`；agentctl 仅为兼容入口。升级保留配置；卸载要求明确确认，服务未停止或授权项目位于安装目录内部时拒绝删除。本机卸载不要求 Hub 在线。

本地任务、原生终端会话、未完成生命周期计划会阻止命令维护；新版本 Agent 还会在本机安装锁存在时拒绝新操作。请在目标电脑自己的终端执行，不要让 Agent 通过自身远程 Shell 卸载自己。完整参数、旧版本修复和边界见 [Agent 安装](AGENT_INSTALL.md)。下述 ACK、排队与审计语义专指原有面板远程生命周期按钮，不是本机命令的完成语义。

## 页面中的节点状态

每个节点会显示：

- 当前 Agent 版本与 Hub 目标版本；
- 是否由一键安装器管理、系统服务类型和管理状态；
- 最近一次更新、重启或卸载操作及时间；
- 当前允许的生命周期动作；
- 旧版本、离线、服务缺失或上次切换失败的明确原因。

“卸载本机 Agent”和“仅移除面板记录”是两个独立操作：

- **卸载本机 Agent**：移除目标电脑上的 Agent 服务、运行时、配置、状态和日志；Hub 中的节点身份、项目映射和审计记录继续保留。
- **仅移除面板记录**：只删除 Hub 中的节点身份；不会触碰目标电脑上的 Agent，也不会删除项目文件。存在项目映射时仍需先移除映射。

两种操作都不会删除授权目录中的 任何已授权的项目文件。

## 一键更新流程

1. 面板管理员点击“更新 Agent”或“重新部署”。
2. Hub 检查节点必须已启用、在线、明确声明相应能力，且该节点没有其他未完成操作。
3. Hub 创建带幂等键和审计记录的持久设备操作，通过现有加密 WebSocket 通道下发。
4. Agent 从当前 Hub 同源地址下载由 Hub 生成的 Agent 包；禁止重定向，限制压缩包大小，并核对声明的字节数和 SHA-256。
5. Agent 只接受白名单中的 `agent/`、`shared/`、安装器、生命周期助手、依赖文件及公开部署脚本；拒绝路径穿越、符号链接、重复成员、未知文件和超限解压内容。
6. 新运行时先写入独立候选目录，创建自己的虚拟环境、安装依赖并执行导入检查。此阶段不会覆盖正在运行的版本。
7. Agent 将“已准备”结果写入本地持久 outbox；Hub 保存结果后回 ACK。
8. 收到 ACK 后，Agent 才把切换交给独立于当前服务的系统任务：
   - Linux：`systemd-run` transient unit；
   - macOS：`launchctl submit` 独立 job；
   - Windows：临时计划任务。
9. 独立助手停止旧服务，等待旧 Agent 退出，原子交换 `runtime`，启动新服务并检查服务确实保持运行。
10. 若新服务启动或检查失败，助手停止异常实例，恢复上一运行时并重新启动；失败版本保留为 `.runtime-failed` 便于排查。

更新只替换 `<安装目录>/runtime`。以下内容保持不变：

- `config.json` 与连接密钥；
- 本机授权目录和任务配置；
- Agent 状态数据库、历史和待补传结果；
- Agent 日志；
- 独立 Python 与 `uv`；
- Hub 节点、项目映射和审计记录。

更新成功后，上一运行时保留在 `.runtime-previous`。后续更新会替换该备份，而不是无限累积。

## 重启与卸载

### 重启

重启使用同一持久操作、ACK 后交接和独立系统任务链路。设备仍有文件修改、Shell、测试或桌面操作时，Hub 和 Agent 都会拒绝重启，避免把正在执行的任务强行截断。

### 卸载

卸载必须在确认框中准确输入完整节点名称。ACK 后独立助手会：

1. 停止并删除 systemd、launchd 或 Windows 计划任务服务定义；
2. 等待 Agent 进程退出；
3. 删除一键安装目录，包括运行时、配置、状态和日志；
4. 保留安装目录之外的全部项目文件；
5. 保留 Hub 中的节点、项目映射与审计记录。

卸载完成后节点会显示离线。需要恢复时，在该节点点击“修复 / 升级”或重新生成安装命令，在原目标电脑执行即可复用同一节点身份。

## 旧版 Agent 的一次性修复升级

v1.6.1/1.6.2 的一键安装节点尚未声明远程生命周期能力。节点页会显示“修复 / 升级”，而不是冒险猜测服务路径。

执行新生成的命令时，安装器会：

- 验证本机已有运行时和系统服务结构完整；
- 使用一次性票据重新取回当前节点凭据；
- 确认票据中的 `device_id` 与本机配置完全一致；
- 保留授权目录、任务及其他本机配置；
- 在候选目录安装并检查新运行时；
- 通过同一原子切换与启动检查完成升级。

若现有目录不完整、不是受管系统服务，或票据属于另一节点，安装器会停止并保持原文件不变。手工源码运行的 Agent 不会被远程猜测或强行卸载；请先按一键安装方式迁移。

## 操作状态语义

面板中的生命周期操作显示“成功”，表示 Agent 已完成下载/准备，并且 Hub 已保存结果、ACK 已交接给独立系统任务。真正的最终状态以节点重新上线后上报的版本和管理状态为准。

正常更新/重启会经历短暂离线。若长时间未重新上线：

1. 查看节点卡片最后一次管理错误；
2. 在目标电脑检查系统服务和 Agent 日志；
3. 点击“修复 / 升级”重新生成同节点安装命令；
4. 不要删除项目目录；修复流程只需要 Agent 安装目录和同一 Hub 节点身份。

## 并发、幂等与权限

- 生命周期接口只接受面板管理员会话、CSRF 和同源检查；
- 三个动作不出现在 MCP `tools/list`，普通 PAT/OAuth 项目授权不能调用；
- 浏览器为每次动作保留稳定幂等键。网络结果不确定时再次点击会核实原操作，不会创建重复更新或卸载；
- 同一节点有任何活动操作时，不允许开始生命周期操作；生命周期操作开始后不能中途取消；
- 离线节点不排队等待未知时间，必须重新上线后发起；
- Agent 只回传不含本机路径的管理摘要，独立 Python、`uv`、安装目录等内部路径不会写入 Hub 节点详情。

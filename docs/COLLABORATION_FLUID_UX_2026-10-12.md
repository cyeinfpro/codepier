# 协作中心：流畅交互与产品化设计

日期：2026-10-12。实现基线：`471a30ec5438117677768674b5f46558b6cd15df`（1.27.4）。本说明描述前端实现与本地验收方法，不代表已经发布或部署。

## 产品原则

协作中心的主路径保持为「进入房间 → 连接助手 → 持续交流 → 查看任务与结果 → 返回原对话」。普通交流不要求用户预先选择聊天或任务模式；监控、消息回执、技术诊断和授权维护作为次级信息，不与对话争夺主界面。

Apple 的 [Designing Fluid Interfaces（WWDC18）](https://developer.apple.com/videos/play/wwdc2018/803/) 强调响应速度、交互可中断、方向可改变和空间一致性。本实现借鉴这些原则，不复制系统外观，不把大量毛玻璃、阴影或长动画当作流畅性的替代品。下列时长是本项目参数，不是 Apple 规定，也不是原生弹簧物理仿真。

## 已发现的热路径与处理

### 输入与选区

原实现监听整个 document 的 `selectionchange`，只要选区折叠就调用消息时间线更新。输入框的光标移动和中文输入法也会触发这条路径。现在只记录消息区真实文本选择，在该选择结束时补齐被延后的消息更新；输入框光标与输入法事件不再触发历史重绘。

输入框自动增高改为同一动画帧内合并，缓存元素、文本和宽度。一次测量只读取一次 `scrollHeight`；窗口宽度变化由 ResizeObserver 触发重算。离开工作区会清除监听、观察器和未执行的动画帧。

### 消息索引与不可变更新

`collaboration-runtime.js` 用 WeakMap 保存「消息数组 → ID 索引」。消息内容、回执均未变化时，合并返回原数组并保留原消息对象；存在实际变化时才复制索引和排序。不能只比较消息版本：同版本的接收回执仍可能变化。

POST 确认、断线后的原请求核验和同步流统一走不可变合并。特别是发送确认不能再原地 push / Object.assign / sort，否则页面可能误以为数组没有变化，出现发送成功却延迟显示、回复来源查找不到等问题。晚到的确认只更新原发件箱所属房间，不写入新房间。

### 增量呈现与真实执行证据

每个消息节点分别记录消息对象、必要的显示上下文、引用的父消息、执行证据投影和是否仍待补齐。未变化的节点不重新生成 HTML、格式化时间或解析 Markdown。引用内容变化会同步更新对应引用，不必重建整条历史。

任务执行证据独立于消息正文。服务器回执、结果保存状态和证据新鲜度即使没有消息版本变化，也会更新对应卡片。证据从近期变为过时不能被缓存掩盖；「插件接收」「执行结束」「结果保存」「用户验收」保持不同含义。

选中文字、按住按钮或在详情内编辑时，不替换正在操作的节点。延后更新不能被记录为完成；交互结束后，即使服务器没有新消息，也应再次补齐。

### 滚动与隐藏视图

用户跟随最新消息时，不读取每一行的几何尺寸。用户阅读历史时，通过一次视口测量与二分查找确定滚动锚点，增量更新后补偿位置，不把用户强拉到最底部。

任务、进展与监控详情保留 DOM 和草稿，但隐藏视图不重复生成记录。进展筛选保留原按钮，卡片按消息 ID 更新，保留未变化的卡片和焦点。房间列表的相同源数据不再次解析。

本实现不是完整的虚拟列表。用户主动加载的历史节点仍保留，以避免破坏文本选择、查找、引用定位和可访问性；万条以上历史的有界虚拟化需要独立设计和验收，不能将本轮千条测试扩展为该场景已经通过。

### 网络与导航

点击当前房间或当前项目范围不重新装载工作区。相邻导航引起的元数据读取共享正在进行的请求，并采用四秒合并窗口及末尾补刷；界面切换本身不等待该窗口。原实时同步、显式刷新、服务器权限校验和 visibility token 清理仍然生效。

首次装载在 overview 确认允许后，将授权目录读取与时间线、房间、成员和策略读取并行，减少一段不必要的串行等待。缓存只用于呈现与重复读取合并，不作为新的权限证明。

## UI 与交互规范

### 信息结构

主导航只有「对话」「任务与结果」「连接」。监控与异常从任务页进入。房间名称、环境和助手关系集中在紧凑标题区；单项目时不再重复展示整条项目切换栏，添加已授权项目仍可从房间菜单进入。异常状态需要可见，安静状态不反复占据提示条。

桌面保留房间侧栏、主要对话和按需出现的详情面板；手机改为完整宽度的当前视图，返回原对话时保留输入内容、选择范围与阅读位置。连接设置继续使用 1.27.4 的集中授权与分层维护流程，不退回旧版表单。

### 视觉系统

使用现有语义化浅色／深色颜色，不依赖固定白底。控件、卡片、外壳的基础圆角为 10 / 16 / 22 px。选中房间以轻边框与低强度阴影表达；主发送按钮有明确对比度，次要操作不竞争视觉优先级。输入、选择框、复选框、抽屉、进展卡和错误提示保持一致的排版与焦点表达。

正文和滚动内容使用实色表面，不在长消息上叠加 backdrop blur。消息操作保留键盘和触屏可达性，不依赖鼠标悬停才可发现。

### 动效

| 场景 | 参数 | 约束 |
| --- | --- | --- |
| 按钮按压 | 90 ms，轻微缩放 | 不推迟 click；禁用按钮不响应 |
| 颜色反馈 | 140 ms | 只改变控件颜色、边框，不动画化全局布局 |
| 新消息 | 180 ms，6 px 位移 | 仅跟随末尾且少量新增；历史批量加载不逐条播放 |
| 详情切换／抽屉进入 | 220 ms，短距离淡入位移 | 动画不锁住输入与导航 |
| 手机房间列表进入 | 240 ms，短距离横向位移 | 维持原焦点、遮罩与 inert 边界 |

Web Animations 辅助函数允许替换正在播放的动画并清理旧实例。页面退出会取消动画，不保留多余的合成层。系统开启减少动态效果时，CSS 与脚本动效均关闭；原生滚动不被强制改为平滑滚动。

### 可访问性

保持真实输入框，保护中文组合输入。可见焦点使用明确轮廓；窄屏／粗指针提高常用控件触摸区域。支持强对比度和 forced-colors 选中态。主导航可用方向键移动；`Ctrl/Cmd + Shift + K` 聚焦房间搜索，不占用全局已有的 `Ctrl/Cmd + K`。Escape 遵守弹层优先级并恢复合适焦点。

## 安全与兼容边界

优化保留 1.27.4 的微信／Telegram 分项同意证据、明确项目与联系人范围、撤销与凭据世代、附件分享边界和结果回传逻辑。没有自动批准新权限，没有重发未知结果的业务操作，没有修改生产账号或订阅。

呈现缓存均在内存，不把草稿或私密正文新增写入 localStorage/sessionStorage。权限投影变化仍先清理历史、详情和待处理视图，再重新读取允许内容。卡顿优化不能以延迟撤权、伪造进度或跳过确认换取。

## 可重复性能回归

`tests/test_collaboration_fluid_ui.py` 检查输入热路径、隐藏面板、合并语义和减少动态效果；`tests/test_collaboration_fluid_cache.py` 用仅注入到测试页的接口验证千条消息的渲染边界，生产代码不暴露调试状态。

在隔离 Chromium 和 WebKit 中，比较 471a30e 原模块和本轮模块：同一帧模拟 100 次输入／选区事件时，时间线更新调用从 100–101 次降为 0，输入高度读取从 200 次降为 1；保留 1,000 条进展消息、执行 100 次隐藏视图刷新时，任务和监控记录各从 100 次生成降为 0。

千条消息测试还验证：无变化消息及无关心跳为 0 次消息渲染；单条执行证据变化或过时为 1 次；修改被引用正文只重新呈现父消息和相应引用消息。发送 POST 确认立即可见，不依赖下一次轮询。

这些是可复现的代码工作量计数，不是生产网络延迟、用户侧 INP 或端到端 FPS。不能据此宣传“整站快了 99%”或保证所有设备达到 60/120 fps。

## 上线前仍需独立验收

本地浏览器验收不能替代真实部署的性能追踪。正式发布前应使用同一候选源码重新执行发布门禁，并在目标设备和实际网络上测量冷启动、长历史、输入延迟和滚动帧时间，确认服务端与传输链路是否仍存在瓶颈。低性能手机、万条历史、真实微信／Telegram 宿主及生产网络不是本轮合成测试的覆盖范围。

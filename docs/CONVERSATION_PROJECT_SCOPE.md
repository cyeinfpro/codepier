# 房间添加项目并授权执行

房主在房间选择项目后，面板先只读核对当前项目、环境、现有助手及连接能力。确认区列出项目、环境、助手、读取/修改/执行能力、项目 Agent 与目录、回传位置和到期时间。点击一次“添加并授权”同时保存房间关联和这个助手的新项目执行范围；单个助手无需再选，多名助手时明确选择目标助手。

连接没有所需项目/能力、原助手没有执行许可、环境不同、原范围失效或原目标为未明确支持的 VPS 时，面板显示原因并禁用提交，不把仅加入房间显示为可执行。此流程不创建凭据、不扩大连接权限上限，不改变宿主审批要求。Shell 使用执行账号的操作系统权限，并非项目目录沙箱。

## 范围证据

- 新记录保存在 conversation_project_scopes，按房间和助手递增版本，保存确认摘要及 SHA-256、房主身份、项目/设备/目录快照、原 dot setup 和 policy 版本、连接、能力、执行目标、回传房间与期限。
- 确认后不可重写该记录；撤销是显式状态变化，重新确认产生新记录。
- 有效期不晚于原 policy、助手位置及原 policy 创建后的七天。本流程不继承外部频道的 until-revoked 语义。
- 新任务将其实际采用的范围记录 ID、版本与摘要冻结到请求证据中。房间关联本身不是执行授权。
- 旧任务、旧批准快照、dot 初始 policy/checkpoint 和订阅过滤器保持不变。旧任务不能因后来添加项目而扩大。
- 当前连接权限、项目映射、原 policy/助手状态及新范围证据在创建工作、领取和执行新步骤时重新核验。目录、设备、能力、期限或撤销变化立即阻止后续步骤。

任务仍以原助手的项目话题为锚点；新范围允许该任务建立对应新增项目的工作项，结果回原话题。没有创建、扩大或重建宿主事件订阅。

## 失败、重复与撤销

项目关联、范围记录与审计在同一事务内保存。版本或摘要过期、项目数量上限、连接权限不足等失败会整体回滚。重复点击复用幂等键；并发不同请求只有一个相同预览能成功。重放旧回执仍校验当前授权，撤销或到期后不能重放为成功。

“项目范围与上下文”显示新增项目授权，房主可撤销。使用该授权的任务停止后续步骤，正在运行的操作请求取消并保留真实回执；撤销不等于证明所有在途操作已经停止。原来不含该范围的任务不受此撤销影响。

旧 conversation-project API 的无 authorization 请求仍只建立关系，作为兼容入口保留；不会返回 execution_authorized=true。

## 验证

专项单元测试覆盖原子保存、只读预览、同键/不同键并发、旧任务不扩大、当前权限交集、目录/设备变动、撤销、到期、原 policy 变化、不可改写证据和原订阅不变。

回环 HTTP/Agent 测试使用临时数据库、项目、凭据和 Agent，覆盖 CSRF、回执幂等，以及新增合成项目的真实文件写入/读取、Shell 命令和原话题结果。Chromium/WebKit 测试覆盖一次范围确认、无助手阻塞、取消/返回、草稿与历史保留、并发版本和撤销。测试不代表真实 dot 宿主已同意或上线，也不改变任何生产房间的权限。

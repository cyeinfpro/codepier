# 依赖输入与安装锁

## 文件放在哪里

开发者审核的六组直接依赖放在 `requirements/requirements*.in`：Hub、Agent、stdio 桥、开发测试、独立 MCP 兼容测试、工具。组内的相对 `-r` 引用仍在同一目录解析。

根部 `requirements*.txt` 是现有安装器、Dockerfile、CI 和旧更新器引用的带哈希锁文件。为了保持这些公开入口兼容，它们仍保留原路径。本次整理只移动输入文件，不改变依赖版本、不重新解析、不安装依赖。

## 维护方式

仅在单独审核依赖升级后运行 `python scripts/lock_requirements.py`。该工具从 requirements/ 读取输入，把生成的锁写回根部；`--check` 只比较，不替换。它依赖已有 uv，不能因检查失败自动安装工具或切换不可信源。

完整源码 ZIP 包含这些开发输入。面板更新 ZIP 不包含它们，以兼容已经安装的旧更新器的明确路径名单。两个包都保留原运行依赖锁与安装入口。

# 微信本人任务与长期连接

## 一次确认的范围

微信扫码登录只建立服务端凭据；联系人配对只验证对方能接收和发送消息，不自动等于房主。原绑定必须已明确允许回复，才能完整回传进度和结果；未允许回复的绑定应由用户明确重新建立允许回复的绑定，任务授权不会偷偷打开通道外发。需要真实项目工作时，由登录面板的房主在原绑定上明确确认“微信本人任务”。确认页冻结显示的原项目、环境、话题、dot、执行目标、读写执行能力与预算。范围变化使旧确认失效。

确认只建立该联系人到该 dot 的独立授权记录，不新建或扩大 MCP grant，不限制主聊天使用同一 grant 的其他正常能力。普通工具不因此取得微信任务范围外的执行许可，宿主必须沿返回的 task_request 和受管 claim/execute/heartbeat/result 通路工作。宿主、交易、文件外发、凭据和其他高风险操作的审批不被代替。Shell 仍使用 Agent 账户权限，不是 OS 沙箱。

原消息保留 external_channel 来源；服务器通过独立持久证明返回 verified_external_owner。只有批准后收到、带可核对创建时间的新原始本人消息能够取得 task_request。旧积压、引用、附件、群聊、回声、陌生联系人和消息修订不生成新执行授权。已执行请求被修改或删除后，旧任务不能继续新步骤；用户应发新的明确请求。

## 到面板撤销为止

新绑定可明确选择 until_revoked；旧数据库迁移仍保留 timed，不批量升级既有绑定。本人任务确认同时允许原绑定、原 dot 位置和原委托范围持续到撤销。存储保留原时间字段用于旧模式兼容，长期模式不靠远未来日期或不断修改版本模拟永久授权。

每次接收、工作读取、领取、执行、结果及外发仍校验当前身份、项目映射、目标、凭据世代和撤销状态。任务 goal、租约及单操作超时仍有限。没有运行时心跳的工作不能把“长期授权”当成无限执行期限。

原累计 100 次委托预算默认保留。可另行明确选择原额度的滚动 24 小时预算；这只在新的本人授权中生效，累计 uses 仍永久记录，不重启清零。达到预算是额度阻塞，不是授权过期，不自动加钱或扩大单任务预算。

撤销通道停止新入站、执行及外发；仅撤销本人任务许可保留已允许的普通聊天。撤销后的旧任务和未发送结果不能继续回传。已经发送到平台的数据无法收回；已经启动的 OS 进程须遵守原有有界停止协议，不能声称点击撤销就已强制杀死进程。

## 平台登录失效与恢复

本地长期授权不保证腾讯登录令牌永不失效。上游注销、失效或 -14 响应会暂停可用性；不伪造 refresh token，也不绕过平台重新扫码要求。

同机器人、同房主可从现有账号发起明确的重新扫码。扫码过程中冻结账号版本、世代、原话题和完整绑定快照；暂停、撤销、换身份或范围变化会中止接受。新扫码结果不自动证明原联系人身份。

接受替换后，旧 poll fence、上下文和待发送旧世代数据被隔离；原本人许可保留为 pending_revalidation，原绑定转为 pairing。只有原 peer 再发送新的 CPW 码并由面板核对激活后，才恢复原能力与预算范围。不同 peer 不能继承原授权；pause/resume 不能跳过此验证。配对码过期可在原绑定重新生成，不必撤销永久许可或重新登记项目范围。

恢复后的新世代不会重放旧消息或旧任务。发送响应未知的分项仍需核对，不能为了“不断线”盲目补发。

## 宿主订阅与消息回传

CodePier 通道、dot 范围、微信登录与宿主事件订阅是不同层。原生事件订阅目前仍返回有限有效期和 refreshBefore；宿主需要通过原接口续订同一已批准范围。服务端不能单方面延长宿主授权，也不能将 webhook 接受当作模型在线、已读或执行成功。OAuth 的更新同样由原宿主连接管理，不能由微信消息创建新凭据。

经过验证的本人请求支持阶段回复、真实任务进度和最终结果回到原微信消息；附件仍需逐份已有分享许可。最终审计以真实 operation 和投递回执为准，accepted 不代表用户收到或已读。

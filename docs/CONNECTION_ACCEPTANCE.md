# ChatGPT 连接改进与能力隔离验收

版本：1.25.0，2026-10-10。本文记录本批代码与分阶段证据；正式发布状态以 Releases 与同一提交的完整 CI 为准，发布不证明实际部署。旧 v1.24.0 的测试不算作本批通过。

## 用户可见变化

| 项目 | 实现与验收边界 |
| --- | --- |
| 批量读取 | read 的 batch 操作，一次最多 8 个同项目、同工作目录文本文件；每项有 SHA、续读位置与独立错误。完整 MCP JSON-RPC 包装预算 128 KiB。受保护路径、符号链接、硬链接及授权检查不放宽，拒绝不自动重试。 |
| 分层连接状态 | 分别显示当前授权、Hub 发现、实际 tools/list、真正成功的只读调用和 Agent 在线声明，并保留时间戳与适用范围。ChatGPT 内部工具扫描/客户端缓存不可见时明确 unknown。 |
| 接入向导 | 选择已有 Hub/Space/授权/项目；区分 ChatGPT 登录、CodePier 授权和模型 API。最小验收是对已授权 README 的真实只读调用。向导不创建新凭据，不把“在线”当成成功执行。 |
| 版本与刷新诊断 | 服务版本、工具契约版本、当前目录 hash、最近实际调用证据分别呈现。没有客户端 hash 时不猜缓存状态；指导用户刷新后再做只读确认，不宣称自动刷新客户端。 |
| 断线与任务生命周期 | 网络断开不等于任务失败。API/界面保留原 operation ID、输出游标和安全 next_call；未知结果先读原回执，不自动重新提交业务操作。撤权、明确拒绝、锁定或策略禁用停止。 |
| 官方私有 Tunnel | 提供官方 Secure MCP Tunnel 配置生成、字段校验和人工启动指南；仅生成文本，未安装、启动、连接或验证凭据。公网 OAuth Hub 路线保留。私有 Tunnel 不适用于公开插件发布，也不自动穿透 OAuth 或绕过宿主限制。 |
| Codex / computer 分离 | Hub/Agent 分别识别模型/CLI 与原生桌面能力；原生阻断缺省 false，与模型禁令独立；仅已有 computer 授权及本机白名单可用，明确禁用保留，旧 Hub/Agent 元数据保守处理。原生 app-server 启动不是 model turn。仍受 scope、允许应用、项目 owner/root、TTL、原生审批和撤权约束。 |

进一步接口与操作说明见 [ChatGPT 接入](CHATGPT.md)、[核心工具](CORE_TOOLS.md)、[长任务](LONG_OPERATIONS.md)、[能力策略](EXECUTION_CAPABILITIES.md)。

## 已记录的验证

这些是分阶段定向结果，不相加冒充独立用例总数，也不代表整仓全矩阵。

- 批读与 schema：121 项通过，含 32 项新测试；独立错误、路径边界、SHA、Unicode 和完整包装预算。
- Tunnel 配置生成：78 项通过，全部为离线模拟。
- 能力分离：267 项定向通过、36 项明确未选择；另 48 项原生边界模拟通过。没有实际执行受禁桌面或模型。
- 连接 HTTP 接口：5 项通过，覆盖路由、协议、授权范围及 CSRF。
- 连接证据/恢复与已有边界：一次 67 项回归通过。首次真实 Hub/Agent 测试发现完成后请求 payload 已清空，导致只读证据漏记；已修复为完成事务后使用原内存请求记录最小证据，并用 payload 已清空回归覆盖。
- 原生投递最终发送复验/公平性/排序/取消与旧审计：48 项通过。
- Gateway：58 项协议/隔离/取消/状态测试通过；另 1 项真实 HTTP/1.1 loopback 连接复用测试通过（1.15 秒）。该测试不是公网、ChatGPT 或完整性能对照。
- operation 完成 Events：53 项真实 Store + 内存 receiver 测试通过；事务故障注入证实结果与 outbox 同时回滚。即时唤醒另一次 44 项事务/竞态回归通过，覆盖回滚不唤醒、事件风暴合并、关闭/重启和丢醒边界。

## 最终增量验证与保留边界

- 修复后的真实 Hub/Agent 批读、逐项拒绝与只读证据通过。真实 read-only fixed grant 的 probe=true 返回 INSUFFICIENT_SCOPE 且没有新增操作；probe=false 可用，带 computer 授权的合成原生 provider 正向通过，不使用真实桌面。
- Chromium 1280×900 和 WebKit 390×844 向导均通过。覆盖无横向溢出、配置编辑失效、单个 pending 请求、离开/返回与晚响应隔离；两种视口截图已实际查看。使用既有 Playwright 1.63 与现存浏览器，未安装依赖。曾发现 details 误用固定高度造成裁切，已修；移动端测试改用实际菜单而非隐藏桌面导航。
- 独立源码审查发现并修复发送锁等待期间的撤权窗口、needs_review 迟到输出废弃完成提示、probe=true 权限缺口，以及强制关闭需复核当前 instance_admin。150 项修复定向回归通过；后续 495 项受影响非浏览器/非 slow 用例通过；余下 115 项 slow/兼容用例最终全部通过。其首轮旧测试仍假定模型开关自动阻止原生能力，已改为显式设置两个独立开关，保留所有拒绝断言。数字存在重叠，不相加称全仓通过。管理员降权另有真实 Store 回归，即使 epoch 不变也不得使用旧 force 权限。
- Windows 安装下载变更：52 项相关测试及真实 PowerShell 纯下载恢复/坏摘要拒绝两例通过；未运行目标电脑完整安装。只有部署新 Hub 后面板才会分发新脚本。
- 工具用量卡简化：84 项单元测试通过；最终 11 项真实 Chromium/WebKit UI 用例通过，覆盖 1440/390/320 宽度、折叠状态保留、晚响应、设置失败恢复与短桌面。首轮发现 WebKit 嵌套 details 收起可见性差异，已用局部 CSS 修复并按原断言复验。桌面与手机截图实际查看，未发生横向溢出或数字截断；明确不含完整宿主对话上下文。
- 全仓 ruff、mypy 的 3 个受检模块、源码发布检查、Python dev/compat 锁文件审计及 npm audit 通过。已知漏洞扫描与模式扫描不证明不存在未知问题。
- 前端可重复构建、四个本地公开附件重复构建 SHA 一致；旧 1.13.0 和当前面板更新器均实际解包通过。Windows 脚本内容、安装包内副本与生成命令的脚本/包 SHA 固定链路一致。
- 完整公开包回归、两平台同提交 CI、容器及四附件公开下载校验是正式发布门禁，不能由这些定向通过替代。
- 同机 before/after 性能对照单列。已知真实桌面高负载不能称安静基准；低样本或受干扰数据不证明 P95/吞吐目标。参见 [并发验收](CONCURRENCY_ACCEPTANCE.md)。

## 不需要凭据的最小接入验收

1. 面板中选择已有授权和项目，查看分层状态。
2. MCP 客户端读取已授权的 README.md；若返回 pending，只查原 operation ID。
3. 终态成功后重新查看该授权/项目的连接诊断，确认只读证据对应同一 ID。
4. 撤权后旧证据不应作为“当前可用”证明；后续调用须拒绝。
5. 连接中断时只查询原回执和未读输出，不生成新的业务幂等键。

真实 Tunnel 创建、凭据配置、OAuth grant、宿主事件订阅或生产权限启用都需要各自单次确认。当前验收无需这些操作。

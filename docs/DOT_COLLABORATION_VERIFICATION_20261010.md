# dot 协作验收范围 · 2026-10-10

## 代码侧证据

本功能验证面板添加 dot、CPD 加入、唯一任务订阅、定向消息、真实 Hub/Agent 操作、进度与结果回原话题。原功能分支的固定快照通过 3943 项非集成、非浏览器测试，以及 72 项选定集成和浏览器测试；未选中测试不计为通过，也不将重叠的开发轮次相加。

以上是原功能快照的验收记录，不能替代合并后的发布验证。最终版本以同一提交的完整 CI、公开源码包摘要和逐项测试证据为准。发布和部署是不同步骤。

## 验证契约

- 添加时固定房主批准的项目、房间、目标、模式、有效期及预算；只读接入不能增加写入或执行权限。
- CPD 加入复用当前已授权连接，建立唯一任务订阅请求；CPJ 保持旧通知用途，不静默升级。
- 选择 @dot 后才能交办；纯文本名称和普通房间消息不构成执行授权。连续任务保留接收者，取消交办恢复普通讨论。
- 持久接入基线、分页、首次待办读取、Hub 重启、重复唤醒和原操作恢复均有覆盖。
- 缺权限、过期、跨连接、快照变更、错误租约、撤销及未完成操作提前报成功均拒绝。
- 两项连续任务分别实际执行写文件、读文件及命令；核对磁盘内容、退出码、原操作标识与原话题唯一结果。
- Chromium 桌面、手机及 WebKit 手机覆盖添加、复制加入指令、@ 选择、交办、后续任务及取消；保留移动视口和发送按钮可见性契约。
- 领取确认、主动进度和最终结果防重复，不产生互相唤醒的交办循环。

主要测试模块为 `tests/test_collaboration_dots.py`、`tests/test_collaboration_dots_flow.py`、`tests/test_collaboration_join_browser.py`，并与现有委托、目标、聊天和公开工具契约回归一起执行。临时测试 Agent 的 Shell 开关只属于测试夹具，不改变实际节点。

## 真实宿主边界

外部 dot 在自动化测试中是明确标注的接收器和消费者夹具，不是实际模型。测试证明 CodePier 侧协议、队列、浏览器、Hub、Agent 和回传链路；HTTP 2xx、签名正确、订阅注册或测试事件均不能证明真实宿主已自主消费。

真实原生 dot 的自主唤醒和执行尚未验收。完成发布后，仍需按维护授权部署相关 Hub 与前端；真实宿主通过正常确认建立原生订阅，再执行一个只读任务及第二个连续任务，核对实际领取、原操作回执、两条原话题结果和恢复。未取得这些证据时，状态保持“代码侧已验证，真实宿主与现网待验收”。

# CodePier 多智能体协作中心实施设计 v0.2

2026-10-07 · 基于《CodePier 多智能体协作中心实施设计 v0.1》（2026-10-06）的代码对照评审与首期实施

## 1. 评审结论与交付边界

原稿的三层架构成立：确定性监控底座负责持续采样，MCP Events 通知获准的消费者，Work 分析、dot 协调。原稿已经充分考虑身份、幂等、租约、撤权、故障注入和“模型完成不等于业务恢复”。本次保留这些原则，不改成模型轮询，不接隐藏聊天 API，不引入 Pi 或模型 CLI。

需要补强的主要不是继续增加模型数量，而是把抽象设计约束落到现有 CodePier 的认证、事务、协议、加密和页面生命周期中。基线为 main 的 `374379f`（v1.17.0）；项目已有 MCP 2.0、长任务、IAM、Store.run 和密钥轮换设施，不能另建一套绕过它们的运行时。

**本次交付是默认关闭、可独立验证的只读协作试点。** 已实现讨论室、结构化收件人、指令/建议审批、统一任务、固定 HTTP 探针、规则与异常、MCP Events 服务端适配及桌面/移动面板。真实 Work Cloud 与 dot 的订阅路由验收仍是上线前置条件，不能由本地接收器或浏览器测试代替。

原稿 P4 有界代码修复、P5 可选执行器，以及生产部署、服务重启、客户数据写入均不进入本次运行时。分布式 Agent 采集、主机/进程指标、生产请求聚合、复杂回归探针与长期归档自动化作为后续独立交付，不伪装成已有功能。

## 3. 服务边界与数据流

面板指令与 MCP 建议共用 CollaborationService。来源由服务端认证入口生成，不允许请求体指定 author、owner、approved 或通用命令。计划编制、异常分析、结果汇总是首期三个固定任务类型。

面板明确指令：当前会话与 CSRF/Origin 校验 → 项目权限 → 消息与目标 → 预算和用途绑定 → collaboration_jobs → 同事务 outbox。MCP 建议先停在待批准消息，不暗中创建目标任务。所有者批准同一消息时才执行同一套调度检查。

监控：固定探针登记 → 不可变计划草稿 → 所有者核对内容摘要并批准 → 确定性采样 → 封存窗口判定 → incident、job、outbox 同事务写入 → webhook → 当前消费者 claim → 结构化结果与 result_ready 同事务写入。

恢复始终由新鲜探针和连续窗口判断。模型的 recovery.verified 只是结果内容，不能更新 incident 为 resolved。目标验收也不允许跳过未完成任务或未恢复的关联异常。

## 4. 身份、授权与审批

房间边界包含 space_id、owner_user_id、project_id 和 environment_id。所有读取和变更重新解析当前项目授权。历史 grant/project 标识只是审计引用，不因数据库里仍有记录而保有权限。

只读消费者的当前 scopes 必须含 read，且只能是 read 与可选 devices.read。带 write、execute 或额外管理能力的连接不能登记进首期消费者。登记绑定有独立期限，默认 7 天，最大 30 天；它不是新凭据，不修改原 grant。

每次 claim、heartbeat、result 都检查真实 grant 与原 assignee。声明“我是 dot”、同名标签、房间成员或结果正文都不能授予权限。同一 grant 的多个聊天仍不能由 CodePier 加密区分；面板不作聊天级隔离保证。

计划 save 不是 approve。MCP 保存计划需要当前有效、类型正确的计划编制任务；激活仅经真实面板管理者、计划 digest、plan_version、binding expected_version 和明确批准动作完成。

## 5. 持久状态与并发

所有新表以兼容迁移加入既有 Store 连接；没有另开 Hub 主库连接。网络请求不在 SQLite 事务中等待。服务在已有 Store.run 工作器上执行数据库阶段，回调或探针完成后再通过 fence 检查写回。

每个项目最多两个未结束分析任务，每队列一个有效执行租约。默认每小时六个、每天二十个新分析，计划可以降低预算但不能无限提高。讨论室、grant 与消息幂等键分别有准确作用域；同键不同请求返回冲突。

领取产生 attempt、fencing_token、lease_until 和原 deadline。租约默认十五分钟，总期限最多三十分钟。心跳不能延长总期限。新世代会永久拒绝旧写入；已知旧轮次的迟到结果单独存证，不覆盖新结果或触发交接。

同一 job/attempt 只有一个有效结果。已保存结果的相同请求重试在重新鉴权后返回原回执，而不是先被“任务已完成”拒绝。blocked 不自动重排；只读超时有限退避，超过原期限/次数终止。首期没有外部执行副作用，因此取消的是内部只读任务，不声称已取消任意进程。

后续交接只有用户明确指定的一条边：分析完成后交给另一位 dot 汇总。创建子任务和结果保存共用事务与业务去重键；下一任务不会继续无限 @，并保留深度、跳数和预算上限。

## 6. 监控信号与时间语义

本版只支持已经登记的 HTTP GET：成功状态验证、合成探针错误比例、合成探针延迟 p95。它们不是实际用户请求统计，更不能证明主机、数据库和全部业务均正常。

公网回调与私网探针使用两套不同策略。探针由所有者登记不可变地址和可选 CIDR，明确允许 HTTP 才可连接相应内部地址；不接受模型直接给任意 URL、Shell、SQL、日志或请求正文。响应体不持久化。

窗口采用 UTC 半开区间和事件时间。min_samples 必须可由采样间隔达到，缺数、过期和策略拒绝不作为健康。迟到超过两个间隔的样本不参与封存窗口统计。rule watermark 防止重复评估增加连续窗口计数；跨过未评估间隔会打断连续性。

恢复阈值与触发阈值必须分离，另需新鲜恢复探针。维护时间有明确开始/结束和 IANA 时区；只是通知抑制，不停止保存真实状态。恢复后的同类故障可在复发期重开原异常并递增 episode。

计划更新后原版异常保留原证据，避免新阈值把旧问题变绿；首期不提供批量风险接受或自动迁移旧异常的捷径。运行者应在改版前核对未结束事件，这项人工过程不能称为自动恢复。

## 7. MCP Events 实现契约

按官方 MCP Events 接口实现 server/discover 的 events 能力、events/list、events/subscribe、events/unsubscribe；仅支持现代协议客户端。接口依据为 https://developers.openai.com/plugins/build/mcp-events ，本次实施前已复核。业务事件名和策略属于 CodePier 自身设计。

事件目录只有四类：任务可用、分析结果、异常变化、链路状态。队列是过滤条件，不是权限。原始订阅 arguments 参与身份摘要；对象键规范化，但缺省字段与显式 null 不合并。回调 URL 来自认证订阅请求，不拼接聊天地址。

首次需要短时 challenge。Standard Webhooks 签名覆盖实际发送字节；重试保留 eventId 与同一 delivery 的 body，重新计算时间与签名。secret 解码长度检查、有限双签轮换和加密存储均在服务端实现。回调 HTTP 2xx 只记录 accepted。

每次连接重新解析 DNS，拒绝非公网单播地址，连接到验证过的 IP 并保留原始 Host/TLS 主机名。拒绝重定向与环境代理，限制正文和返回大小。私网探针的放行配置不会传递给 webhook 客户端。

临时错误有限退避；410/413 不原样无限重试，410 也不冒充协议退订。事件正文上限 16 KiB，完整证据需授权读取。游标绑定具体订阅身份，按连续确认/明确放弃的水位推进；有效续订不会因客户端传来旧游标倒退。

七天以外的游标恢复会返回 truncated，消费者应读取当前任务与未结束异常对账。本版保留历史事件元数据用于这一水位判定；更完整的长期归档与自动删表方案没有作为首期完成项宣称。

## 8. 数据保留与首期容量限制

原始采样七天、证据正文默认十四天，清理分批运行，证据过期返回明确错误而非空白成功。当前未关闭事件的最新最小证据包不在正文清理批次中删除，但过期读取仍遵守 expires_at；不能据此承诺无限有效证据。

原稿建议的任务/结果九十天、审计一百八十天、小时聚合三十天，是后续完整数据治理目标。本次尚未自动清理全部消息、结果、幂等记录、订阅和 outbox 历史，也未实现分布式 Agent 的六小时缓冲。试点需监测数据库容量，不应未经容量验证开放为多租户无限期监控。

这些限制不会被显示为“全部监控完成”。首期计划最长三十天并需重新批准；配额限制模型任务频率。上线扩围前应补足历史归档、独立磁盘告警、保留政策和恢复演练。

## 9. 界面和双入口行为

独立「协作中心」入口包含讨论、任务、监控、智能体与订阅。项目、环境、收件人和任务类型在发送前可见。完整回调地址、签名材料、私人聊天、内部推理不进入共享面板。

桌面主内容与目标/链路侧栏并排；窄屏单列，详情内联展开，不使用大弹窗。表单草稿留在当前登录空间的内存中，离开页面不取消持久任务；重复发送使用稳定来源消息和请求键。切换页签后焦点停在相应页签，自动刷新不会覆盖正在编辑或展开的内容。

状态明确区分保存、排队、事件接收、领取、处理、结果和验证恢复。未启用事件/派发器时显示待人工领取；有效订阅不表示模型在线。未验收 Work/dot 的真实回调路由时，不显示“自动协作已验证”。

## 10. 启用、停止与回滚

四个独立环境开关均默认 false：CODEPIER_COLLABORATION_ENABLED、CODEPIER_MCP_EVENTS_ENABLED、CODEPIER_MONITOR_COLLECTOR_ENABLED、CODEPIER_ANALYSIS_DISPATCH_ENABLED。子开关不能越过主开关。

先部署兼容 schema 且不开功能，再在隔离项目验收。用户分别在真实 Work/dot 聊天选择已有只读连接并主动订阅；面板绑定用途、发送测试事件，最后执行一次可控异常与恢复闭环。只有端到端证据齐备才打开真实项目的采集与分析派发。

暂停讨论室立即阻止新任务、领取、后续结果动作并使执行租约失效。原任务恢复要在原期限/次数内明确解除，不盲目重跑。采集计划和订阅可分别暂停；总开关关闭不会删除项目或重装旧能力。

恢复旧数据库或回滚前必须先关闭全部新开关，并备份数据库及配套加密材料。**本次没有实现“任意旧快照被恢复时自动识别并安全停机”的证明**；不能让旧环境变量自动开启历史任务。运维确认原任务、水位与未完成回执后才重新启用。当前不会修改线上实例。

## 11. 验收分类

代码与真实 HTTP 验收包括身份/项目隔离、伪造 author 拒绝、提案审批、来源和请求幂等、唯一结果、迟到 fence、暂停撤权、队列与跨环境预算、独立恢复、维护结束通知、订阅签名/轮换/过期、回调错误处理、重启世代与旧客户端兼容。

浏览器验收使用真实测试 Hub 的隔离 Chromium 与 WebKit 会话，覆盖创建讨论室、登记只读消费者、双击防重、草稿保留、HTML 注入、固定探针/计划编辑、单独批准、桌面和 1024/390 像素布局。模型与外部回调不会在这些测试中真实运行。

真实 Work/dot PoC、真实生产故障、分布式离线补传、实际部署与旧快照恢复演练保持 blocked/not_run，不填 pass。测试模块、实际结果和日志位置见本次验收记录。

## 12. 提交前复核补充

2026-10-07 再次对照官方 MCP Events 文档确认发现、订阅、challenge、签名、有限 TTL 与 410/413 处理要求；该文档核对不是实际聊天 PoC。随后补上项目页「协作」快捷入口，并将使用说明与本设计加入公开源码包白名单和必需文件检查，防止 GitHub 有文档但发行源码包漏掉文档。

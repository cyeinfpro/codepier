# 面板目录授权与 SMB 文件兼容

本说明描述源码中的目录管理和网络文件系统处理。功能是否可用以目标 Agent 上报的能力及操作回执为准；Hub 源码更新、Agent 升级和具体 NAS 挂载验收是分别核对的事项。

## 在面板管理授权路径

打开 **设备节点 → 授权目录**，可以查看节点当前的目录授权、新增路径、调整读写与任务权限，或撤销某条目录授权。节点的 **完整管理** 中也有同一入口。

新增路径时填写节点实际可访问的绝对路径。例如，已在 macOS 挂载的共享目录可以填写 `/Volumes/Shared/Projects`；Linux 可填写 `/mnt/projects`；Windows 可填写 `D:/Projects`。面板不会根据一个 `smb://` 地址替用户挂载共享或保存 NAS 登录凭据。

选择文件访问权限后点击 **验证并授权**。面板会先验证目录和当前配置版本，再保存单条变更，等待 Agent 确认加载。只读授权不能同时开启任务执行。开启目录任务权限也不会自动开启全局完整 Shell、修改项目映射权限或扩大 MCP 客户端的授权范围。

在 **项目映射** 表单中可以直接展开 **新增或调整目录授权**。如果“验证并保存”发现目录未授权，表单会自动展开对应目录的授权区并保留别名、节点、路径和其他输入。用户明确提交授权并确认生效后，未改动的原映射会继续保存；如果期间换了节点或改了映射内容，则保留新输入并等待重新验证。

目录验证需要等待节点时，界面查询同一次验证并自动继续保存。关闭界面、退出登录或切换空间会停止当前界面的后续动作；已提交操作通过原回执核对。

## 权限与配置保护

- 目录配置管理是面板管理能力，要求当前身份有相应节点管理权限及有效的面板 CSRF 校验。普通项目读写权限、MCP 调用和协作消息均不能调用它来给自己扩大范围。
- 每次只新增、更新或删除一条目录记录。保存携带读取时的配置摘要；配置被另一窗口或本机进程修改时返回冲突，不覆盖后续修改。
- Agent 校验完整候选配置，保留身份、密钥、状态库、其他目录、任务与运行设置，保存前保留私有备份。
- “已保存”与“已生效”分别显示。网络中断后使用原幂等键和操作回执恢复，不因为页面刷新创建第二次授权。
- 离线、停用和旧版节点有独立状态。未经 Agent 验证的缓存目录列表不作为新的保存依据。

授权范围包括路径及其子目录，匹配时优先采用更具体的目录条目。例如父目录可写、某个子目录只读时，子目录仍为只读。撤销一个子目录条目可能恢复父目录的继承权限；因此撤销条目并不等于禁止访问该路径。面板会在撤销前显示这一点，且撤销目录授权不会删除项目文件。

任务执行与文件工具的权限语义不同。执行任务的进程仍使用 Agent 运行账号及所选运行环境的权限，目录授权本身不构成操作系统沙箱。详见 [Agent 安装与权限](AGENT_INSTALL.md)和[项目执行环境](PROJECT_RUNTIMES.md)。

## SMB 兼容的实现

NAS 挂载通常以本机路径出现，但不一定支持本机文件系统的所有操作。能够读取文件、执行命令或普通重命名，不等于支持硬链接。

新建文件、移动目标和原生文件导入共用 `shared/file_publish.py`。历史恢复经原有写入引擎使用同一发布路径。优先保留硬链接发布；只有操作明确返回能力不支持时，才尝试系统提供的“不覆盖目标”重命名：

| 平台 | 硬链接不支持时的安全发布原语 |
| --- | --- |
| macOS | `renameatx_np` 与 `RENAME_EXCL` |
| Linux | `renameat2` 与 `RENAME_NOREPLACE` |
| Windows | 拒绝覆盖已有目标的 `os.rename` |

能力由实际操作判断，不根据路径前缀或共享名称猜测，也不缓存可能在重新挂载后失效的能力结果。权限拒绝、I/O 错误和超时不会触发第二种发布尝试。成功回执包含 `publication_method`，可区分硬链接、排他重命名和已有文件替换。

新文件发布必须保留以下保证：

1. 内容先写入同目录临时文件，并在发布前完成必要的内容检查。
2. 目标已经存在、或其他进程在检查后创建了同名目标时，不覆盖它。
3. 修改已有文件继续校验原内容摘要，并保留修改前备份。
4. 权限错误和网络故障不被当作“不支持硬链接”而无条件重试。
5. 如果系统已经可能改变文件，但最终结果或持久性无法确认，返回可核查的结果和恢复信息。

当硬链接与排他重命名均明确不支持时，文件工具使用下述排他新建兼容路径。严格原子发布 API 默认仍返回能力错误。不得用无条件覆盖重命名替代新文件的防覆盖发布，也不得把目录同步失败当作完整成功。

排他重命名会消耗暂存文件名，因此移动操作在发布前记录文件身份，发布后校验目标句柄、内容及身份。发布后发生冲突、源删除失败或结果不确定时，不自动删除目标作为回滚；保留目标与可用源文件、备份及原操作回执供核查，避免检查与删除之间的竞争误删。

移动删除源文件时还有一条独立保护：网络共享可能已经完成删除，只是回复丢失。对于这种结果不确定的错误，保留已发布目标和备份，不再删除目标作为“回滚”，以免删掉最后一份数据。

## 可恢复的操作回执

| 错误或状态 | 含义与处理 |
| --- | --- |
| `ATOMIC_CREATE_UNSUPPORTED` | 严格原子 API 缺少原语，或兼容创建也缺少安全路径原语；不采用会覆盖目标的降级写法 |
| `FILESYSTEM_UNAVAILABLE` | 存储失联或读取 I/O 出错；不返回半截文件内容 |
| `WRITE_OUTCOME_UNCONFIRMED` | 共享可能已经完成写入、替换或删除，但回复不确定；保留证据，不自动重放 |
| `DURABILITY_UNCONFIRMED` | 文件系统已发生变化，但目录持久化尚未确认 |
| `STAGING_CLEANUP_UNCONFIRMED` | 暂存文件清理结果待核对，不把清理异常包装成确定完成 |
| `ROOTS_SAVE_UNCERTAIN` | 目录配置保存结果或持久性待核对，保留原授权操作编号 |

文件写入、落盘及清理结果不确定时，总操作状态为 `needs_review`。Agent 与 Hub 均通过限定工具、错误码和字段类型的白名单保留安全恢复信息，包括相对路径、备份编号、预期内容摘要和是否已开始改变文件；不会直接公开任意异常字段。

配置读回和持久保存是分别核对的事项。即使 Agent 已加载新的目录配置，只读观察到相同摘要也不能替代失败的持久化确认。界面会保留原回执和对应提示，不把这类结果当作已确认保存来重复授权或自动续提映射。

## 网络中断与排查

出现挂载失联或写入结果未确认时，先按原操作编号核对回执、目标文件内容与备份，再决定后续动作。不要用新编号反复提交同一写入。目录未挂载和目录未授权是两个不同问题：增加授权不能修复 SMB 能力不足或共享离线。

共享目录中缺少 `.git` 是独立的仓库问题，应核对迁移前位置、版本历史和远端。目录授权与 SMB 兼容处理不会自动初始化新仓库来掩盖历史缺失。

### SMB 排他新建兼容模式（2026-11-04）

部分 macOS SMB 挂载既不能创建硬链接，也不提供排他重命名。文本新建、移动目标、恢复为新文件及原生导入现在允许最后使用 O_CREAT | O_EXCL 排他创建目标，再从已完整暂存的文件复制内容。它不是原子内容发布：

- 成功回执包含 publication_method=exclusive_create、atomic=false 和 partial_content_visible=true。硬链接、排他重命名继续优先使用，并报告 atomic=true。
- 其他进程可能在完成前看到空文件或部分内容。读取者必须等写操作终态并核对 SHA；不能把文件名出现当作完成信号。
- 目标的抢占由文件系统的 O_EXCL 保证，同名文件、符号链接和目录都不会被覆盖。复制通过固定父目录的文件描述符进行，拒绝符号链接路径，结束前核对文件身份和内容。
- 复制、fsync、内容核验或目录身份核验失败后，保留目标供检查，返回 WRITE_OUTCOME_UNCONFIRMED / needs_review、mutation_started=true、retryable=false、atomic=false，以及相对路径和预期 SHA 等恢复证据。不自动重放，也不使用有竞争窗口的“检查后删除”清理目标；其他进程可能已替换它。常规暂存清理由既有调用者完成。
- 进程崩溃或被终止可留下部分目标，不能保证产生新的完成回执。重新提交“new”会冲突，不会覆盖残留目标。先核对原操作、目标内容与备份，再明确选择恢复或后续编辑。兼容模式移动即使目标复制、校验与目录同步完成，也不自动删除源文件；回执为 needs_review，source_retained=true，移动尚未完成。
- 目录同步失败仍报告 DURABILITY_UNCONFIRMED，不会把 SMB 的持久性限制伪装成成功。权限拒绝、I/O、断线或结果不确定不会触发另一种发布尝试。
- 无法保证 O_EXCL 的存储不受此模式支持。Windows 继续使用原生无覆盖重命名；本次没有引入 SMB 登录信息、挂载操作或服务端凭据。

此模式放宽的是“完整内容瞬时可见”，不是 no-clobber。需要强原子内容可见性的工作流应在支持原语的本地或服务端文件系统运行 Agent。目录授权并不能改变挂载能力。

本次验证使用隔离合成目录，覆盖六进程同名竞争、进程中途退出、部分内容可见、目标替换、目录换位、符号链接、写入/落盘失败以及写入/移动/导入回执。真实 NAS 尚未取得具体测试目录授权，因此未在用户 NAS 上创建探针；不能把合成测试当作目标 NAS 验收。

#### 并发移动与恢复边界

兼容新建现在通过目标文件描述符 fchmod 恢复暂存文件的 mode，避免进程 umask 二次裁剪执行位或读权限。设置权限失败同样是需核对结果，不能假报成功。

移动在已发布目标之后发生冲突或源删除失败时，保留目标并返回 needs_review，不再使用“验证目标未变，然后 unlink 回滚”的流程；这两步之间存在被其他进程替换的窗口。新建的暂存清理失败、移动源目录落盘失败和源删除错误均保留原子性、相对路径、备份编号及预期 SHA 等恢复信息。

O_EXCL 兼容移动只完成复制与核验，随后保留源并要求核对，不能把该回执当作完整移动成功。跨平台路径 API 没有“仅删除指定 inode”原语，额外 stat、摘要校验或进程内锁都不能关闭外部进程最后一刻替换源文件的窗口。原有硬链接/排他重命名发布的移动仍沿用既有的尽力源删除流程，其检查不是针对外部编辑器的文件系统事务；本次不扩大为所有移动都保留源，也不宣称解决了原有源删除的全部外部竞争。

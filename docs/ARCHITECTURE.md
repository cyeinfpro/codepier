# 架构与边界

浏览器和 MCP 客户端连接 Hub；Agent 主动建立到 Hub 的连接，在本机授权的项目范围内执行操作。Hub 的 Web/API、认证、OAuth、持久操作和工作流位于 `hub/`；Agent 的文件系统、命令、原生会话、集成及恢复逻辑位于 `agent/`；共享契约、迁移、执行策略和加密通道位于 `shared/`。

`web/` 提供面板、MCP Apps 和浏览器扩展资源。`scripts/` 与 `deploy/` 提供源码构建、安装、迁移和诊断；`tests/` 使用临时 Hub/Agent、假原生进程与浏览器验证核心流程。浏览器依赖由锁文件管理，分发时保留生成资源与第三方许可证，但不包含 `node_modules`。

源码版本与进程启动时加载的版本不同。`shared/build_info.py` 分别给出启动标识与磁盘指纹，源码不可完整读取时按未验证处理。`scripts/check_full_regression.py` 记录运行前后输入，测试通过但输入变化时不应接受为当前版本验收。

公开源码、私密运行状态和本机验收证据是三个独立对象。公开分发必须使用 `--public`；`RELEASE.json` 只描述源码候选，实际部署记录留在发布目录之外。旧品牌兼容入口和协议常量保留用于升级，不代表当前 UI 应继续使用旧品牌。

# Telegram 与微信协作室同步

本功能默认关闭。代码实现和合成验收不代表已经接通真实 Telegram、微信或 dot 宿主。

## 同一份讨论，独立的投递

面板、已绑定的本人微信私聊和 Telegram 私聊共享协作室的 canonical 消息、原回复关联与 dot 收件记录。跨端副本只进入 transport outbox，不重新入站、不重新建立工作项，也不重复唤醒 dot。任务执行及验收状态继续使用原任务记录；通道“已接受”不代表用户已读或任务完成。

Telegram 输入仍保留 external_channel 身份。即使本人已完成配对，外部文字、转发和附件也不自动升级为面板房主的执行授权。既有执行确认与 grant、房间范围不变。

## 安全接入

1. 部署负责人明确启用已有的协作功能和 CODEPIER_TELEGRAM_ENABLED。默认值为 false，不在升级时自动开启。
2. 房主在当前协作室的“通道与范围”安全表单登记已有机器人数字编号和 Bot Token，并当次确认加密保存凭据及供应商条款。不得在聊天正文中粘贴 Token。
3. 选择当前话题的 dot，确认私聊入站及新消息完整镜像。系统生成15分钟有效的一次性 /start 配对命令，不创建机器人。
4. 在目标 Telegram 私聊发送命令，回面板核对实际数字 user_id、chat_id 并确认这是本人。username、显示名、机器人编号及持有Token本身都不代表房主身份。
5. 已有微信的“仅对原消息回复”批准不会自动扩大。需另外确认当前原联系人是本人，并批准该绑定版本的完整镜像。改变绑定版本后重新核对，旧同意不会继承。
6. 可选择 Telegram 无声发送；这只是关闭声音，仍可能显示通知。微信协议没有对应静默字段，请在微信客户端设置免打扰。

本期仅支持明确的本人普通私聊。一个机器人与同一 Telegram 私聊只能绑定一个当前协作室；多个协作室使用不同机器人，不能靠“最后活跃房间”猜路由。群组、频道、forum/topic、其他机器人发来的消息均不进入 dot 收件箱，也不会修改群隐私模式。

## 收发与恢复

本期固定使用 getUpdates 长轮询。每次轮询先以 getMe 核对机器人，再以 getWebhookInfo 检查已有Webhook。检测到已有Webhook即阻塞并显示原因，不调用 setWebhook/deleteWebhook、不自动切换模式、不改变既有生产入口。

每批原始update加密保存至durable inbox；去重、canonical消息、dot收件、镜像队列和新offset在同一事务提交，提交成功后下一次getUpdates才使用新offset。重复update_id内容冲突会整批回滚；暂停、撤销、凭据世代或权限变化会使旧轮询fence失效。

每个目标和文本分段分别记录。发送前再次核对原账号、绑定版本、世代、消息版本、协作室、项目映射和当前grant可见范围。协作室后来新增项目不会自动获得外发批准。某一端失效不阻止另一端继续已授权投递。

发送前持久记录sending。超时、断线、取消或重启后无法确认是否被上游接受的分项进入unknown，禁止自动重发；房主可填写依据登记人工已收到或取消未发送部分。明确429按retry_after退避，并记录机器人级发送冷却；默认保守地每机器人至多约每1.1秒发送一次。不启用付费广播。不同消息和目标采用有界公平调度，未知的长消息不阻塞另一条独立消息。

连续阶段回复会在尚未发出时合并，只保留较新的进展；已经被上游接受的历史不删除。长文本使用纯文本、保守UTF-16预算分段并标明顺序，不使用Markdown/HTML解释正文，保留中文与emoji。回复优先使用目标端的原消息映射，同时显示canonical原消息尾号。

## 图片和文件

Telegram图片、文件、音频、视频先保存有序说明；允许范围内的下载使用官方API、受限大小、加密本地缓存和SHA-256完整性检查。访问缓存时再次核对当前身份、原绑定、房间和项目权限。文件token URL、file_path、file_id及凭据不会进入公开附件清单或错误文本。

完整镜像默认发送文件说明，不自动转发二进制。房主可在Telegram独立文件入口选择当前项目已有产物与原dot最终回复，预览数字收件人、完整文件名/字节数/SHA-256清单后当次确认。批准仅覆盖该清单、原收件人、原绑定版本和不可变产物，不继承微信批准。图片作为原文件发送，保留原始字节；每件最多50MB、每个原回复目标最多16件，超限回面板读取。产物分段断线可续传，摘要变化、暂停/恢复、换凭据或撤权会阻止旧批准继续。正文不会因添加附件重发，文件逐项记录429与unknown；未知结果不盲目重新上传。超过下载预算或下载失败时，原消息与附件说明保留并显示原因，不重新运行原产物任务。

## 当前上游约束

2026-10-11核对官方文档：
- Telegram更新最多保留24小时；离线超过该窗口会显示“历史可能不完整”，不宣称无遗漏。
- sendMessage正文上限4096字符；本实现使用更保守的UTF-16分段预算。
- getFile下载预算20 MB（20,000,000字节）；通用文件上传预算50 MB（50,000,000字节），使用保守十进制，服务器实际限制及响应最终兜底；本期仅通过逐文件预览与当次确认后开放。
- deep-link start参数最长64字符。这里只生成符合字符范围的短期配对命令，不用可猜身份作为参数。
- disable_notification仍会产生无声通知；private chat接收与群Privacy Mode不同。

## 验证边界

测试使用临时SQLite、合成账号、模拟Telegram/微信应答、真实HTTP认证/CSRF门禁及真实Chromium/WebKit。包括重复update冲突、撤权/改目录/换凭据、原回复映射、恢复后unknown不重发、429、文件范围、进度合并、独立投递状态、重复点击和旧房间迟到响应。

没有创建真实Bot、读取真实Token、注册Webhook、发送真实外部消息、改变生产配置或授权。真实账号接通、dot宿主订阅、生产部署和目标用户收件仍需在已确认范围内另行验收。

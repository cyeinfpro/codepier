# 协作中心

协作中心以房间组织持续对话、项目、dot 和工作。项目与成员可以分别添加；房间没有项目时也可以保存目标和聊天。面板关闭不会取消已经保存的工作。

## 从一个房间开始

打开「协作中心」，点击「新建房间」。只填写名称即可创建，也可以同时勾选已有项目。手机上点击房间名称左侧的菜单查看房间列表。

房间列表支持分页。「显示已归档」可以找回归档房间；打开房间设置可以恢复。归档保留历史，不会删除项目目录。

建房、添加成员或调整连接遇到响应丢失时，点击「核对原操作」。即使关闭并重新打开面板，当前页面会话仍保留原请求，可恢复已保存的同一结果；不要为同一个目标重新建房。

### 继续使用旧房间

旧房间首先以只读方式显示原消息、工作和回执。完成房间迁移之前，输入框不能发送新消息或附件，也不能从新界面批准、恢复或扩大工作范围。查看历史、检查连接、撤销许可和安全停止仍可使用。

先进入成员管理，逐一完成旧成员的明确连接迁移；不再使用的成员可以明确移除。准备新连接和完成某一个成员的验证，都不会立即打开整个房间的写入。旧微信路线仍可接收入站时，按页面提示先安全暂停或解除原绑定，保留原账号和投递回执。

页面确认全部迁移条件满足后，由房主点击「启用新房间界面」。提交时再次核对房间版本、当前连接和旧写入路线；有未完成项时保留只读状态，并说明需要继续的步骤。切换成功后，后续输入通过新房间入口保存，旧输入界面不能继续向同一房间创建新的业务消息。恢复微信时，仍须在当前流程核对原账号、联系人和参与范围，原工作许可不会自动扩展。

这一步保留原房间、消息、工作和操作身份，不会重新执行旧任务。版本冲突或响应未知时核对原请求，不通过复制房间或重复交办规避迁移。

## 项目与参与范围

房间顶部的「项目」统一管理关联项目。勾选后保存即可，不需要先添加 dot。取消勾选表示「移出房间」：该项目不再用于此房间的新工作，底层项目和文件保留。

移出前，页面读取当前项目影响，列出相关成员范围、待执行工作项和仍有原操作回执的任务。数量超过显示范围时明确标记未列全。保存时再次核对房间版本；运行中的操作会收到停止请求，预览与提交成功都不等于远端进程已经停止。

项目关联与成员授权分别保存。项目列表中的「项目允许：可修改 · 可执行」表示项目本身的能力上限，不表示某位 dot 已获相同权限。仅把项目加进房间，不代表所有 dot 已获执行许可。进入「成员 → 管理 → 参与范围」，为指定成员选择项目的读取、修改、执行能力及有效期。执行能力仍受项目、连接凭据和执行位置的真实权限限制。

编辑已有成员时，默认「保持原有效期」：每个项目仍沿用显示的原截止时间，新增项目持续到你撤销。未改的项目范围保持原版本，不因增加其他项目而重新连接或使原工作失效。只有明确选择重新设为「7 天」或「直到我撤销」，才统一调整本次所选项目的有效期；原限时许可不会因打开或保存面板而自动延长。

保存冲突时保留表单选择，并展示需要重新核对的状态。不要通过重建房间或成员解决版本冲突。 保存期间显示正在保存；错误会滚动到可见区域。保存成功与随后读取房间是两个阶段，若提示「项目已保存，视图刷新失败」，只需重新读取，不要重复提交。项目变动触发权限重新核验时，旧界面数据仍会清空，成功回执不会恢复未经核验的权限。

## 添加 dot

1. 点击「成员 → 添加 dot」，填写显示名称。
2. 核对参与范围与有效期；没有项目时可以先添加聊天成员。
3. 点击「添加并连接」，复制加入说明，发送给目标 dot。
4. 在原面板等待接入。刷新或离开页面后，再次打开成员管理会恢复同一接入流程。

「等待 dot 接入」只说明成员和邀请已经创建。宿主登记、原生订阅验证、真实消息读取与规范回复均完成后，才会显示「可以聊天」或「可以协作」。不要把收到通知、注册回调或手工声称收到消息当作真实往返证明。

邀请过期时刷新加入说明，成员身份保持不变。已登记的成员使用「继续连接」恢复原流程。工具目录过旧、宿主确认未完成或通知路线异常时，按该流程返回的下一步处理；不另建定时任务代替原生订阅。

在成员管理中可以设定主责、调整参与范围、暂停和移除。暂停可以沿原成员继续；移除后不会自动恢复或继承原批准。更换宿主或迁移旧连接需要使用明确的迁移流程。

### 把已有 dot 加入另一个房间

在「添加 dot」中选择「已有 dot」，从当前账号已经完成往返验证的原连接中选择。列表显示原成员名称与所属房间；没有已验证连接时先通过「新 dot」完成第一次接入。

为新房间重新确认成员名称、参与范围和有效期，再把加入说明交给所选的原 dot。新房间仍需独立的原生订阅和消息往返验证。它不会继承其他房间的项目权限、连接证明、未读进度或工作；同一房间已有该 dot 时继续原成员即可。

原连接暂停、凭据失效或更换宿主后，依赖它的复用连接会停止准入并提示恢复。需要更换宿主时在成员管理选择「更换连接」：新连接验证完成后才替换当前连接，原成员与工作身份保留。

## 聊天与工作

同一个输入框用于讨论和工作要求。默认发给房间主责，也可以选择指定成员。引用消息会保留原关联；在工作详情点击「补充说明」，下一条消息关联到原工作。

在成员尚未就绪时也可以保存消息；界面应显示真实等待状态。创建邀请不会启动模型或业务任务。已接入的主责理解意图后，在当前批准范围内建立工作；缺少关键条件时在原对话澄清。

工作详情显示验收条件、当前主责、参与成员、执行步骤和当前可见的原操作回执。「暂停」阻止后续步骤；「停止」对已启动操作发出停止请求。发出请求不等于远端进程已经停止，最终状态以原 operation 的回执为准。

工作列表可以继续加载更早的工作。分页保留原工作身份；更新较早的工作不会使它从后续页面消失。打开工作详情时，重新核对当前状态和权限。

### 恢复原工作或选择接替成员

成员更换连接后，在原工作卡点击「查看」。服务端确认原工作可以恢复时，详情会显示「恢复原成员的当前连接」；选择需要恢复的原参与成员，核对范围后点击「确认恢复原工作」。主责与执行成员都沿原工作身份恢复，原步骤及回执保留；恢复连接不会自动重跑已有操作。

原主责无法继续时，详情可显示「接替这项工作的主责」。列表仅包含当前已就绪、满足原主责批准范围的房间成员，也可以包含新的替代成员。选择成员并确认后，在同一个工作中接替原主责角色，原项目、能力、执行位置和期限不扩大，其他工作的主责保持独立。房间成员管理中的「设为主责」只负责房间后续输入的路由，不能代替原工作的接替。

尚有结果未知或未结束的原操作时，先核对回执，按详情提示等待收敛。工作版本、主责或候选连接范围变化后，界面会清除旧选择并要求重新核对。控制响应丢失时使用「核对原操作」恢复同一次请求，不重新创建工作。

发送响应丢失时，消息显示「核对原消息」。该操作按原 `client_message_id` 查询是否保存；确认未保存后才沿同一键补交。不要另发同一内容来试探任务是否开始。

### 持续上下文与纠正

房间设置中的上下文展示当前目标、决定、约束、未解决问题和已完成产物引用。每条事实都指向原消息及其版本；主责只在当前连接、消费租约与项目权限有效时更新。新加入的 dot 获得此房间当前批准范围内的上下文，不会读取其他房间或宿主的私人历史。

发现某条事实有误时，从该事实选择「纠正」，在原输入框写明新的要求。发送会保存一条规范消息，并在同一事务中撤下所指的旧事实。主责处理新消息后再写入有来源的替代事实，旧决定不会与新决定同时冒充当前事实。纠正请求保留原上下文版本；若事实已变化，先读取当前内容再核对。

纠正目标与文字草稿按房间保留在当前页面会话中。输入框上方显示所选事实和版本；取消纠正仅移除该关联，保留已写文字。上下文版本或可读范围变化时，发送按钮暂停，点击「重新核对」再选择当前事实。普通聊天不带纠正字段，页面不会根据文字关键词猜测要撤下哪条事实。点击来源可读取当前有权查看的原消息；原消息版本变化时会明确提示。

来源已修改、权限已收窄或还有未复核输入时，页面明确显示对应状态。上下文和历史均按页与内容预算读取；未读完不能解释为完整历史。摘要更新本身不会创建工作或延长旧批准。

### 附件

点击输入框左下角的「添加附件」，每条消息最多 16 个文件，每个文件须为 1 字节至 8 MiB。清单显示名称、大小和上传状态；可在发送前移除。全部上传完成后，可以随文字发送，也可以只发送附件。工作详情中的「补充说明」同样支持附件。

上传结果未知时点击「核对原上传」，系统沿原文件和原上传键恢复。切换房间不会移动草稿附件，发送确认后只移除这次已发送的文件；随后添加的附件继续留在原草稿。草稿与未完成上传只保留在当前页面会话内，刷新页面前应先确认发送结果。

消息中的附件链接下载原始文件，读取时仍核对当前房间与项目权限。文件保留 7 天，到期会显示「已过保留期限」，不会自动重新生成。附件内容提供上下文，上传文件本身不会授予执行许可。

## 连接微信

房间顶部直接提供「连接微信」。向导连续完成账号登录、本人核对和房间绑定：

- 使用已有账号，或确认加密保存与平台条款后扫码登录。
- 核对实际返回的扫码身份。需要验证码时在同一向导填写。
- 确认消息进入哪个房间、是否回复原私聊、是否允许本人在显示的范围内交办工作。
- 按配对说明在本人微信私聊发送挑战内容，再核对实际联系人。

向导顶部的四步进度依次是「登录微信 → 选择 dot 与范围 → 本人验证 → 完成」。发送配对码时：

- 可以点「复制」，或用手机微信扫配对码旁的二维码直接复制文字，粘贴到与微信机器人的私聊。大小写、空格、换行、全角破折号或省略 `CPW-` 前缀都能识别。
- 面板显示配对码剩余有效时间和收件通道最近一次同步。收到的消息不是当前配对码时会直接提示；这类消息不会进入房间，也不会创建工作。
- 房间有多个 dot 但没有主责时，向导会让你选择由哪个 dot 接收微信消息。
- 房间刚完成迁移、仍保留已暂停的旧微信连接时，向导会先列出这条旧连接，确认解除后再绑定新连接。
- 重新扫码一个你之前登记过的微信时，勾选「确认替换此微信的原连接」即可沿用原账号；它在其他房间的连接会停用或要求重新确认，由其他账号登记的微信仍不能接入。
- 旧房间在启用新房间界面之前不能新建微信连接；向导会列出需要先暂停的旧渠道并引导到迁移清单。

「扫码完成」只表示登录步骤完成；房间与联系人绑定未完成时，界面继续显示当前步骤。本人任务许可和普通收发许可分别保存。扩大项目范围、更换账号或联系人不能静默继承旧同意。

已经允许本人交办工作时，向导提供「仅撤销工作许可」。点击后保留账号、本人私聊和房间聊天连接，停止新的微信来源任务及后续步骤准入，已启动操作仍保留原回执。需要再次交办工作时，重新核对当前范围并明确批准；解除整个聊天连接使用单独的解除动作。

同一微信私聊只保留一个活跃房间路由。已有绑定时明确迁移；新消息进入新房间，原消息、原工作和原回复继续保留原绑定关系。解除后尚未投递的回复不会偷偷改发另一个房间。

消息与工作详情分别展示原微信投递分项。平台接受不等于对方已读；工作已完成但渠道待恢复时，结果仍保留在原房间。发送结果未知时先核对原投递，界面不会提供无依据重发或重跑工作的捷径。

真实微信与真实 dot 的连接最终取决于目标账号、宿主确认和平台返回。合成测试与页面状态不能代替目标宿主的真实往返证明。

## 常见状态

| 显示 | 含义 | 下一步 |
| --- | --- | --- |
| 等待 dot 接入 | 成员已保存，邀请尚未完成 | 复制加入说明到目标 dot |
| 等待在 dot 中确认 | 当前宿主或订阅尚未完成 | 继续原连接流程 |
| 正在验证回复 | 通知/读取/回复证明正在核对 | 查看连接详情 |
| 可以聊天 | 当前绑定已完成消息往返 | 在原房间发消息 |
| 可以协作 | 当前绑定与所需资源范围可用 | 交办明确工作 |
| 需要恢复连接 | 某一连接层失效 | 恢复原连接 |
| 正在核对原操作 | 结果尚不能确认 | 查看原回执，不重复执行 |
| 已完成，回复待恢复 | 工作完成，渠道投递尚未完成 | 核对原投递，不重跑工作 |

运维、迁移与故障排查见 [协作中心维护与恢复](COLLABORATION_CENTER_OPERATIONS.md)。

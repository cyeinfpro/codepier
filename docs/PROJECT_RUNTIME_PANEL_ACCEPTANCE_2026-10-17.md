# 项目执行环境面板与默认清洁模式：实施验收

日期：2026-10-17。状态：源码与前端实现完成，相关测试结果见下文；未提交、推送、发布或部署，未修改生产 Agent 配置。

## 1. 面板入口与默认行为

入口：**项目映射 → 项目卡片 → 执行环境**。选择清洁、兼容或容器模式，点击“保存并应用”，不需要手动编辑 JSON。清洁模式显示“默认 · 推荐”；高级设置提供 Shell、PATH、允许继承的变量名，以及容器运行所需的固定镜像、引擎、socket 和资源限制。

清洁模式不仅是页面的预选项：Agent `selected()` 对没有独立运行配置的项目实际返回 `project_clean_v1`。升级后未配置的新、旧项目均遵循该默认值；已有明确的兼容、清洁或容器配置继续保留，不批量覆盖显式选择。清洁模式仍使用执行账号的操作系统权限，不宣称 OS 沙箱或匿名环境。

当前代码更新不等于正在运行的服务已更新。生产面板显示新入口、Agent 使用新默认值，仍需要升级到相应实现。

## 2. 保存与生效

面板通过新增的管理员专用接口读取和保存指定项目配置，复用原操作编号、幂等记录和 Agent 配置备份机制。没有通过 Shell 修改配置，也没有另建授权或任务队列。

- 读取、保存、回执查询均检查当前面板会话、空间、管理员身份、项目和节点管理权限；写请求有 CSRF 检查。
- 保存校验绑定项目、映射和完整配置版本的修订值。冲突保留草稿，不猜测覆盖其他窗口或其他配置编辑器的修改。
- Agent 原子保存配置并保留私有备份；身份、密钥、授权根、项目文件权限、执行开关、其他项目配置均不随模式切换而扩大。
- 页面明确区分“已保存／等待重新加载”和“已生效”。Agent 短暂重连时继续核对原保存和重新连接后的实际运行配置。
- 连续点击只提交一次；请求响应丢失后通过原幂等键读取已有回执，不用新请求重复写入。关闭页面不取消已提交的操作，也不会因迟到响应重新打开旧窗口。
- 已经运行的命令不因配置切换而重启；后续新命令使用加载后的配置。原任务租约、隔离要求、fencing 和历史回执继续有效。

内部 `project_runtime_get/project_runtime_set` 不进入公共 MCP 工具目录。它们有独立的工具语义版本，旧 Agent 会被识别为需要升级，不以失败后的 Shell 降级处理。

## 3. 模式限制

兼容模式保留原终端、环境和既有 SSH 行为。清洁模式使用非登录 Shell、独立 HOME／临时目录／缓存和明确的项目工具路径，不复制整个个人环境。

容器模式保留上一轮的严格要求：固定镜像、指定项目挂载、启动前核验；必要程序或容器服务不可用时不伪造成功，不自动回退为原生执行。配置已加载不等于某次容器隔离或工作负载已经完成验收。

不同平台的默认工具路径由 Agent 提供，面板不把 Unix 路径硬套到 Windows。原生签名、Xcode、现有 SSH 转发等依赖应使用经过验证的相应配置，不承诺所有原生工作负载可无差别迁移进容器。

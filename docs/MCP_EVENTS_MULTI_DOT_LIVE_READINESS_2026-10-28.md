## 1. 历史现场检查的通用结论

此文是历史记录的公开脱敏版，不代表当前部署状态。升级前应分别验证目标运行版本、实际镜像内容、更新器状态及协作接入授权；健康检查成功不代表候选代码已安装。具体实例、部署路径、版本、连接状态和回执已从公开版移除。

## 2. 建议核查范围

只读核查运行镜像、模块与动作目录、数据布局、更新器状态及当前接入授权。发布和升级应绑定最终提交、构建产物与摘要；旧连接或失效授权不能自动转移到新房间。

## 3. 更新入口

使用项目正式更新入口与已核对的发布资产；不要手动覆盖更新事务中的运行快照。

## 5. 恢复真实 Dot 通信的具体步骤

### 5.1 先建立当前有效的接入

1. 新候选上线并通过只读检查后，在面板选择当前有效房间。
2. 由房主创建新的双向 Dot 接入，并明确当前项目、用途、执行范围、期限和预算。旧位置失效时，不应被静默恢复或升级。
3. 在实际目标 Dot 宿主中使用面板生成的完整最新加入指令。若该宿主的 CodePier 授权仍绑定已删除会话，应通过原宿主流程建立当前有效连接；不能用新加入码绕过原授权拒绝。
4. 由目标宿主刷新实际工具目录，核对本次新增动作。重扫只刷新目录，不创建订阅、消费权或执行授权。
5. 核对 `dot_connection` 返回的项目、会话、Dot、原批准范围和精确恢复/订阅请求。普通查询不会把接入自动置为成功。

历史失效位置不能推断当前授权，不能推断它已经批准新的双向通信或团队执行。新接入仍遵循 [DOT_COLLABORATION.md](DOT_COLLABORATION.md) 与 [DOT_RELAY_EXPERIENCE.md](DOT_RELAY_EXPERIENCE.md) 的范围边界。

### 5.2 明确协商 v2 统一收件箱

已获准双向通信并完成加入后，由实际消费者确认能遵循 v2 协议，再调用 `collaboration(action="dot_mailbox_configure")`。请求需要当前 `dot_id`、`protocol_version=2`、`confirm_consumer_protocol=true` 与稳定幂等键；使用当前连接返回的实际值。

配置首先进入 prepared。随后由该 Dot 的原生宿主按服务器返回的精确 `subscription_request` 建立：

```text
codepier.collaboration.inbox_dirty.v2
```

过滤条件包括项目、环境、会话、slot 与 binding_generation。回调地址、签名材料及宿主连接器标识必须来自实际宿主，不能从插件名称猜测。原生 challenge 成功才激活 v2；每个 Dot 保持自己的稳定订阅，不能为每个 Goal 新建一条。

普通测试事件不发放消费票据。完整的真实闭环必须由房主的一条真实输入触发：事件到原回调，当前 Dot 兑换票据完成 `consumer_begin`，读取并处理 Inbox，使用当前 session/fence/proof 完成受控推进，最后按 dirty revision 排空和 yield。普通读取或 webhook 2xx 都不能代替这一证据。

已经激活的 v2 绑定不允许因订阅失效而退回旧的无 fence 写入口。新房间也不能复用旧房间的票据、proof 或订阅身份。需要更换 callback 时使用明确的新绑定流程。

### 5.3 再启用多 Dot 团队

第二名 Dot 也先完成上述独立接入。由房主在面板批准团队，指定唯一主责、成员、允许项目、能力与总预算。一个用户输入只生成一个原 Goal；普通多 @ 或成员互相发言不自动扩大批准范围。

首轮选择只读任务，检查结构化交接、成员产物版本及摘要，并由当前 coordinator 对当前 intent 发表唯一汇总。测试过程中保留原工作、原 operation 和原 publication 标识；超时或响应丢失后查询原记录，不重新派发同一副作用。

上述步骤中，向目标 Dot 发送加入指令、原生订阅确认、房主批准团队及生产更新均未由本次只读审查执行。

## 6. 真实验收应收集什么

| 场景 | 需要核对的实际记录 | 不能代替的证据 |
| --- | --- | --- |
| 单 Dot 收发 | 原房主输入、精确订阅、真实 callback、consumer receipt、原话题回复 | 健康检查、测试事件、只读 Inbox、合成消费者 |
| 连续输入 | 输入分别保留；新 revision 使旧上下文无法覆盖；两条输入都有实际处理去向 | 只看页面气泡或笼统“已回复” |
| 两 Dot 协作 | 一个 Goal、精确 assignee、handoff、指定版本产物、当前主责唯一 publication | 两个独立聊天各自回答、普通多 @ |
| 响应丢失与重启 | 原 session/工作/operation/publication 标识可恢复；旧 fence 被拒；副作用次数不增加 | 重新提交一次成功、只验证新建任务 |
| 到期与撤权 | 当前批准和订阅状态变化阻止新准入；恢复仍引用原事实 | 旧 callback 可访问、HTTP 接受、静默续权 |
| 真实手机体验 | 实际设备/浏览器/输入法、输入期间更新、键盘/滚动、断网恢复的现场样本 | 桌面移动 viewport、合成 composition 事件 |

只保存必要的状态、时间、匿名引用和文件摘要。不得把票据、proof、签名密钥、原始连接配置或私人对话导出到公开验收文档。

当前会话没有取得目标 Dot 宿主原生事件源、订阅或实际模型消费的新回执。工具目录中的缺失不能反向证明目标 Dot 宿主不支持该能力；必须在实际目标宿主中验证。

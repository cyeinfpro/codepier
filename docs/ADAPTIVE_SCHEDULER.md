# 并行与队列

> 本页描述 1.24.0 源码中的自适应调度功能。可下载版本以正式 Releases 为准；1.23.0 及更早版本不包含本页的调度器。发布与源码验收不代表生产节点已升级。

## 在哪里设置

设置中心 → 任务 → 并行与队列。选择你有管理权限的节点，设置自动调节、并发上限，或展开项目配额。留空表示继承节点配置；取消改动重新读取当前值。

保存采用版本检查，其他窗口修改后不会覆盖。界面区分「等待节点确认」「已生效」「节点离线」「升级 Agent 后生效」和「节点未接受」。出现网络错误时先刷新状态核对同一次保存，不反复提交。

## 如何分配资源

- 执行、文件操作和远程命令分开分配容量。项目按运行占用与轮转顺序公平准入，可以利用空闲余量。
- 配额是各个通道内的项目运行上限；子工作区保留原项目身份，不能靠新建 worktree 绕过配额。
- 同一路径写入和显式声明的资源冲突先等待锁，再等待执行名额。不会让等待锁的任务占满执行通道。
- 对远程命令还有每个已验证目标的并发上限。任务必须通过原有 VPS 授权和项目检查。
- 一个项目默认最多保留 32 个未完成持久操作；节点仍有 64 个的总安全上限，最后 8 个名额为当前没有待完成操作的项目保留。拒绝新增请求不会妨碍查询、取消或按原幂等键找回既有回执。不要把待完成数量当成正在执行数量。
- 忙时减少后续准入，不强杀正在运行的任务。取消与超时继续使用原进程所有权、进程组和回执机制。

调用流水会分别说明等待本项目额度、远程目标额度、通道容量、资源压力或项目公平轮转。只传递固定原因枚举，不暴露其他项目的命令、目标地址或任务正文；阻塞任务仍逐条核验查看权限。旧 Agent 未提供原因时保留通用等待状态。

## 自动调节与降级

节点使用 CPU、可用内存和支持的平台 I/O 压力指标，连续健康采样后逐步扩大容量。压力升高时降低新任务准入，冷却期避免频繁振荡。严重内存压力暂停新增执行和远程任务，保留有限文件操作能力；指标缺失使用保守容量，不把未知资源当空闲。

Linux、macOS、Windows 采用各自系统计数器，不读取其他任务命令正文。并非所有平台都有 I/O 压力指标；界面不伪造缺失数据。容器资源限额会影响可用预算。已经运行的外部进程仍可能改变负载，所以这些限制不保证任意构建都不会耗尽资源。

## 本机配置与面板覆盖

Agent 原配置文件的 scheduler 对象是本机边界：

- adaptive：自动调节；false 使用 initial 固定容量，但严重内存保护保留
- minimum、initial、maximum：执行通道最低、起始和最大容量
- read_limit：文件通道上限
- remote_limit、remote_target_limit：远程通道和单目标上限
- project_limits：按项目 ID 配置的各通道上限

整数范围 1–64；未知字段、布尔冒充数字、无效上下界会拒绝。Hub 保存的是显式覆盖，Agent 计算最终运行值；面板不能提高本机已配置的容量边界或项目约束。无需新增凭据，没有增加目录、项目、命令或网络访问权限。

## 升级与恢复

先升级 Hub，再升级 Agent。旧 Agent 不支持下发时只显示待升级，不将保存称为已生效。偏好保存在 Hub 现有数据中，经既有认证连接发送，重连重新核对版本。无效配置保留最后可用值和原生连接，界面不显示假成功。

回滚到旧 Agent 会恢复旧调度行为，不会应用新偏好。回滚前等待在途任务结束，并按原升级流程保留配置和数据。新版本下若要恢复本机默认，在面板清空覆盖后保存；不要删除整个配置文件。

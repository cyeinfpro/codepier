# 协作交付上线与回退

适用于 [交付运维设计](COLLABORATION_DELIVERY_OPERATIONS_2026-11-10.md) 的兼容桥、验证和放量阶段。记录真实证据前，阶段状态为待核验。

## 部署检查

1. 记录当前 Hub 提交、镜像摘要、Hub 兼容能力、数据库读写下限及订阅版本。记录未知操作和待发送分项的原身份，备份留在受控环境。
2. 先在隔离环境升级兼容桥。覆盖活动回合、压缩回执、部分受理、未知投递和当前授权变化。按实际 reader/writer 组合记录退出码和数据库检查结果。
3. 切换写入程序前让旧 writer 停止并确认退出。面板更新器在原卷或候选卷以只读方式检查数据库下限，再用核验过的不可变镜像启动。容器和原生服务还通过 `python -m hub check-compatibility` 或 Hub 启动入口检查。
4. 只有能实时执行新安全契约的 writer，才在第一个需要该契约的效果事务内抬高持久兼容下限。普通启动和关闭新功能开关不抬高或清除该下限。当前核心 schema 的哨兵也会拒绝不认识该版本的旧程序。
5. 上线前核验恢复原回执、结果未知、旧分项有界等待、权限变化和手机上的分项状态。分阶段扩大使用范围，依据通过矩阵、有效样本和实际订阅生命周期证据决定放量。

## 证据记录

| 范围 | 记录 |
| --- | --- |
| 应用版本 | 提交、镜像摘要、兼容能力、实测环境和有效配置 |
| 定向回归 | 实际命令、退出码、通过/跳过/失败数、覆盖的 D 编号 |
| 兼容桥 | 起点数据、候选和回退版本、拒绝旧 writer 的证据、原历史可查结果 |
| 真实宿主 | 宿主类型和版本、实际订阅续期、票据兑换、输入处置、工作继续和回复路线 |
| 真实微信 | 原投递和分项是否与手机结果相符、未知核对范围、限流和重新登录结果 |
| 性能 | 硬件、数据量、并发、网络条件、有效样本数及 p50/p95/p99 |
| 工具成本 | 完整运行记录、实际尝试数、唯一业务提交数、重试数、附加读调用数和样本数 |

实例管理员可访问 `GET /api/system/collaboration-telemetry` 查看自本进程启动以来的固定标签计数和遗漏。尝试、受理、重新查询、成功创建和本人核对分别计数。跨重启或单次运行的完整证据仍从原业务账本及宿主运行记录核对。没有对应账本或完整运行记录的场景记为证据不足。公开提交中只记录脱敏结论，不写入凭据、回调地址、手机号和正文历史。

## 回退

- 功能回退先暂停新准入，保留原工作、原回执和未发送分项。既有回合遵循各自的已保存期限和授权，当前撤销闸继续执行。
- 二进制回退先核对所选镜像/程序和当前数据库兼容下限。面板更新只有在候选未承接业务写入时才可能自动恢复旧卷；候选可能已承接请求时进入恢复流程并保留两份数据。
- 灾难恢复从备份恢复后，逐项核对恢复点之后可能发生的外部效果。已受理、未知和未发送分别处理，继续使用原操作或分项身份。
- 旧协议下线须记录已迁移/停用的活跃连接、存量回合及未知操作、历史查询能力和回退窗口。先停旧入口的新领取，再考虑移除旧写入；历史记录继续按保留规则可查。

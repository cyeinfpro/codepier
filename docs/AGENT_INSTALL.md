# CodePier Agent 安装、升级与卸载

CodePier 1.9.0 的旧版命名迁移见 [完整迁移说明](CODEPIER-MIGRATION.md)。旧版更新后由独立助手在空闲时迁移默认目录和系统服务，不重新配对；旧目录只保留精确兼容入口。自定义项目、外部状态目录和原授权不改名或扩大范围。`agentctl` 是兼容命令，新入口为 `codepier-agent`。


以下说明对应本次更新后的源码。新入口需先随 Hub 源码部署；旧线上面板不会自动获得新的下载脚本。本次源码修改和测试不代表已经更新服务器或家里电脑的现用 Agent。

## 一键安装

面板 **设备节点 → 接入电脑**，填写设备名称、目标电脑能访问的面板地址、系统和一个明确的授权目录，生成安装命令后在目标电脑自己的终端执行。安装器准备独立 Python 3.13 环境、下载经 SHA-256 校验的 Agent 包、配对并配置自动启动。

安装命令包含约 15 分钟有效、成功兑换即失效的一次性票据。不要贴到聊天、公开仓库或日志中；过期时重新生成。票据和配对密钥不写入浏览器本地存储。

目标电脑需要能主动访问面板和依赖下载源，无需开放家里的入站端口。Linux/macOS 需要 Bash 和 curl；Windows 使用 PowerShell。授权目录必须已经存在并填写绝对路径，例如 `/Users/me/Projects`、`/home/me/Projects` 或 `D:\Projects`。HTTP 不保护浏览器密码和首次配对数据，请使用 HTTPS、可信网络或 SSH 转发。

默认安装目录是当前用户的 `.codepier-agent`，不是授权项目目录。请使用原安装账号；不要为解决错误随意添加 sudo 或改用管理员账号。安装完成后还需要在面板配置具体项目映射和权限。

Windows 默认配置为开机后台任务，**未登录桌面也启动，关闭安装窗口不会退出**。注册开机触发器需要接受 UAC；提权仅用于注册，Agent 保持原安装账户的普通权限。使用无窗口 `pythonw.exe`，每分钟补拉退出进程，事件循环卡死 120 秒后触发重启。网络断开持续重连，不触发卡死重启。升级和卸载期间暂停自动补拉。

Windows 后台任务采用 S4U 非交互登录，不保存 Windows 密码；它不提供交互桌面，也不支持依赖桌面登录的映射盘、Windows 集成网络认证或加密凭据。桌面控制和使用这些凭据的工具需要另外配置交互会话。

## macOS 应用身份与目录权限

macOS 服务安装会在安装根目录建立持久的 `CodePier Agent.app`，位于可替换的 `runtime` 之外。首次构建需本机已有 Apple Command Line Tools（`xcrun clang`）和 `codesign`；安装器不会静默安装开发工具。工具缺失或签名验证失败时停止，不改为绕过隐私检查。

已有应用只验证路径、所有者、签名标识及源码标记，不覆盖或重新签名；异常、符号链接或身份不符时拒绝继续。Python/runtime 更新保留应用字节。旧 direct-Python 服务只在 label、运行目录、完整参数与原安装完全匹配时受控迁移；无关服务、额外参数或未知 launchd 状态不会被接管。启动失败会恢复原服务定义及此前观察到的加载状态；若恢复本身失败，会明确报告人工恢复要求，不声称升级成功。

这不是自动授予文件夹访问或“完全磁盘访问”。首次访问受保护目录仍需你在 macOS 系统提示/隐私设置中确认；源码测试只能验证签名、进程和服务合同，不能证明每台 Mac 的 TCC 授权归属。遇权限错误请核对该应用和原授权项目目录，不要用 sudo、删隐私数据库或扩大访问范围代替确认。

## 只读目录访问的超时边界

无 `capture_baseline` 的 `open_workspace`、`project_context`、`read`、`fs_read`、`fs_read_many`、`fs_tree`、`fs_search` 将项目根目录解析、资源路径声明解析和实际读取放入可终止子进程。子进程创建后每个协议阶段的通信/读取超时为 15 秒；超时或取消时先终止并回收子进程，再释放队列。此值不是整个请求的硬性总时限，不包含系统创建进程与最终回收耗时；`fs_tree` / `fs_search` 原有 8 秒扫描预算不变。

前置根目录及资源声明探测受原 read 调度配额与项目公平策略约束。对 read/fs_read/fs_read_many/fs_tree/fs_search，只有资源与执行位能够立即、公平、原子取得时，才在同一子进程继续两次根校验与一次读取；否则先结束并回收前置进程，再进入原排队路径和独立执行进程。open_workspace/project_context 保持前置与执行两阶段。逐阶段接收当前授权配置并重新核对根目录，最多执行一次读取，不缓存授权，不持有子进程等待资源队列。父进程仍执行原授权检查、资源/调度排队、排队后的再次授权和根目录变更检测。写入、快照、受管工作区映射、Journal/控制状态及安装目录本地 I/O 不在这一隔离范围。这是防止目录读取阻塞事件循环的进程隔离，不是操作系统安全沙箱，也不保证中断不可中断的内核 I/O；合成测试不代表已复现或验证真实 TCC 权限等待。

## Windows 维护命令提示缺少 Token 参数

如果升级、卸载或归档命令在启动时报告 `MissingArgument` / 缺少 `Token` 参数，这是旧命令生成器把空的 `-Token ''` 和 `-AllowRoot ''` 传给 Windows PowerShell 子进程导致的参数绑定错误；维护操作本来就不需要这两个安装参数。脚本尚未进入维护逻辑，不能据此判断归档或卸载已完成。

修复后的面板只在新安装命令中传这些参数。必须先部署含此修复的 Hub，再重新生成命令；重复复制旧命令或只更新 Agent 不会修复面板生成器。不要添加新的配对票据来绕过维护命令错误，也不要删除本机配置。归档迁移和卸载仍须分别确认各自的影响范围。

## Windows 下载失败时

Agent 源码包直接从你填写的面板 `/agent/agent.zip` 下载；Python、uv 和 Python 依赖仍有各自的下载源。请按错误发生的阶段排查，不要把源码包超时误判为 GitHub 下载失败。

新版 Windows 引导脚本在准备好 Python 后，以分块读取下载面板安装包。瞬时断线、读取超时和可重试的 HTTP 错误最多尝试 4 次，间隔 1、2、4 秒；每次从零重下并清理本次临时片段，不复用来源未知的文件。连接/读取默认超时 30 秒，每次尝试另有 120 秒总耗时预算（正在进行的读取最多再占一个读取超时）。下载日志显示面板主机、尝试次数、接收字节数与 SHA 校验结果，不包含安装票据。源码入口可通过 `-DownloadTimeoutSec`（5–120 秒）和 `-DownloadAttempts`（1–5）调整有界重试。

只有固定 SHA-256 校验通过，才原子保存安装包并继续安装。包变化、证书错误、错误页、校验失败或重定向均停止，不绕过校验或自动换源。仍失败时检查目标电脑到面板的网络、代理和安全软件，并在面板重新生成命令；不要公开完整安装命令。此改进需部署新 Hub 才会出现在面板提供的脚本中，源码测试通过不代表目标 Windows 已安装成功。

## 执行能力默认值与旧配置

当前源码的新安装弹窗默认勾选“安装时开启 Shell 与目录任务”，可以取消。生成的安装命令会把选择传递到本机初始化；取消后，Shell 和新目录的任务能力均保持关闭。源码初始化支持 `init --shell disabled`，POSIX 一键安装入口支持 `--shell disabled`，PowerShell 安装入口支持 `-Shell disabled`。

文件工具仍限制在授权目录；完整 Shell 使用安装账号自身的系统权限，不是目录沙箱。安装完成后，面板项目仍需允许执行，客户端仍需 `execute` 授权。桌面控制不会随此选项开启。

已有 Agent 的普通升级、修复和重新配对保留原来的执行设置，不会因新安装默认值变化而扩大权限。旧版本缺少该设置或已经明确关闭时，在 **系统设置 → 已有 Agent 开启执行能力** 查看适用于默认受管安装的本机命令；自定义安装使用原运行目录、原解释器和原配置，不要重新初始化。配置生效后再次验证并保存项目映射即可，无需重新配对。

只需要具名任务、不需要 Shell 时，可仅在原配置中为对应授权目录设置 `allow_tasks=true`。关闭 Shell 不会自动删除任务或关闭单独授权的目录任务。这些当前源码行为优先于历史版本验收文档中的旧默认值。

## 已安装不再阻止升级

面板安装命令明确携带 `ExpectedDevice`，且与本机已有节点、Hub 地址和本机已保存的配对配置一致时，会自动进入原节点升级：验证受管服务、准备并检查候选运行时，再原子切换。不重新兑换安装票据，不重写原配置、密钥、授权目录或执行开关；新安装表单中的目录和 Shell 选择也不会覆盖现有设置。即使命令中的一次性票据已经过期，仍可按此路径升级；脚本和安装包摘要仍须匹配，Hub 更新后应重新生成命令。此路径保留已有凭据，不代表已经验证节点联网或修复被撤销的配对。旧命令没有明确目标节点时，不据此猜测原节点身份。

本机记录属于不同节点或不同 Hub 时，命令会在下载与配对前明确说明差异；节点不匹配时仅显示经过格式验证的本机节点 ID。后续有两个选择：继续保留原节点时，从原面板的对应节点生成安装/升级命令；确实要换节点或面板时，先明确执行归档恢复，再重新安装。不会用新票据静默接管旧节点。

不要为了升级另建节点，也不要删除 `config.json` 绕过检查。票据属于另一节点、安装目录不完整或服务不属于该目录时，安装器会停止。手工源码运行的 Agent 与受管安装不同，不能通过猜测目录强行卸载。

### Windows 提示 `Install ticket belongs to another device`

这不是 Python 依赖安装失败。通常是本机已有受管 Agent，但面板使用了**另一个节点**生成的安装票据。旧安装和配置没有被替换。不要删除 `config.json`、重新创建节点或强行覆盖；原来的项目映射和状态可能仍依赖现有身份。

1. 在**同一个 Windows 用户账号**打开 PowerShell，读取本机节点名称与 ID（不输出 secret）：

   ```powershell
   $Base = Join-Path $env:USERPROFILE '.codepier-agent'
   if (-not (Test-Path -LiteralPath $Base)) { $Base = Join-Path $env:USERPROFILE '.remote-dev-agent' }
   $Config = Join-Path $Base 'config.json'
   (Get-Content -LiteralPath $Config -Raw -Encoding UTF8 | ConvertFrom-Json) | Select-Object name, device_id
   ```

2. 在面板 **设备节点** 找到该 `device_id` 对应的**原节点**。要保留原节点续装时，从原节点的“修复 / 升级”生成**新的**命令；同节点、同 Hub 会复用已有配对。也可使用原节点“完整管理 → 命令升级 / 卸载”中的“升级”，无需安装票据，也不轮换密钥。不要在“接入电脑”里新建一个节点来覆盖旧节点。
3. 新版面板生成的 Windows 命令携带 `-ExpectedDevice`，在下载 Python、安装依赖和兑换票据之前比对本机已有身份。错节点会立即拒绝并提示如何恢复，不消费票据；Python 安装器在后续阶段仍会再次校验。已复制的**旧命令**不包含预检参数，须在已更新的面板重新生成才会有此保护。
4. 若这是**从未安装成功**的节点，且普通升级/卸载也因缺少已注册服务、已有节点身份或安装结构不完整而失败，请在新版面板的 **设备节点 → 完整管理 → 命令升级 / 卸载**，选择 Windows，使用新增的 **Windows 失败安装恢复（归档备份）**。这是独立操作，不要求旧 Agent 正常启动，也不要求旧节点在 Hub 仍然存在。命令不会把新票据用于旧节点；请在原 Windows 安装账号本机执行，并在提示时输入本机已有 `device_id`，确认将原安装目录整体归档到同级的 `.codepier-agent.recovery-时间戳-随机码` 目录。若旧配置不存在且没有无法核实的状态数据，则要求输入 `ARCHIVE INCOMPLETE`。此命令不自动启动新安装；为了避免 Windows 占用正在运行的 Python，完成验证和服务停用后，Python 先退出，再由外层 PowerShell 归档整个目录。归档成功后，再从准备保留的面板节点重新生成新安装命令。
5. 归档前会拒绝其他安装锁、活动任务或原生会话、安装目录内的授权项目，以及无法证明归属的任务计划程序服务。只有经过核实确实属于本目录的旧计划任务才会被停用并移除；如果服务身份无法确认，会保留原目录并报告错误。原 Hub 节点和目录外项目不会被删除，原配置、密钥、历史、日志都留在归档目录中。归档不等于完成新 Agent 安装，必须再次检查节点上线状态。
6. 若原节点已从 Hub 删除或当前账号找不到，仍须确认真实本机身份以及是否存在正在运行的程序，不能把不同节点票据用于自动接管。完成归档后的旧备份请先保留，不要在新节点上线前删除。

### 首次配对成功、服务注册失败的续装与归档

`service_pending` / `service_error` 的受管 Windows 安装不等于必须重新配对。如果本机保存的服务定义与真实注册任务仍能完整核验归属，即使旧 Python、启动包装器或程序文件损坏，也会先准备并校验候选运行时，再原子替换，不要求先启动损坏的旧程序。若服务尚未完整注册，但可信失败安装元数据和原运行时完整，则补齐注册后继续原节点升级。不重新初始化配置、不打开旧配置中关闭的权限；服务归属无法确认且原运行时也不完整时，保留原目录并进入明确恢复流程。已有任务注册但 `service.xml` 尚未落盘时，仅在失败安装元数据、真实任务执行路径、原账号 SID、S4U 与恢复策略全部匹配后，才从真实任务恢复定义文件。普通服务缺失不会被猜测成当前安装所属。

Windows 归档恢复从验证、等待本机确认到 PowerShell 完成改名都持有同一安装锁。交接文件只包含源/目标路径、锁随机标识以及配置和服务文件摘要，不包含连接密钥。确认期间配置或任务注册有变化，会拒绝继续。目标备份目录已存在时不覆盖、不合并。离线本机 `archive` 与面板生成的 `archive` 共用同一套延迟交接，避免正在运行的私有 Python 锁住原安装目录。

如果停止计划任务期间出错，原目录保持不动，保存的服务定义留在 `.recovery-service-<随机标识>.xml` 供检查；成功归档时保留原 `service.xml` 字节。不能确认归档锁归属、进程是否退出或服务查询结果时不会强行继续，也不要直接删锁重试。归档完成只表示旧文件已保存，不表示新节点已经上线。

安装票据兑换可携带期望设备 ID。新 Hub 在消费票据之前拒绝不匹配的 ID；安装器在新装和修复写配置之前仍做独立检查，兼容旧 Hub 时也不允许把另一节点身份写入原配置。Windows 启动/升级/卸载入口同样核对显式目标 ID。计划任务访问错误、账号信息错误和任务不存在是不同状态，不能把任意查询失败当成允许覆盖已有任务。

### 旧 Windows 节点与面板系统选择

部分旧版 Windows Agent 位于 `%USERPROFILE%\\.remote-dev-agent`，计划任务名称是 `RemoteDevAgent`；`CodePierAgent` 不存在在这种旧安装中不一定是故障。`schtasks /Query` 显示“就绪/Ready”只代表已注册且等待触发，不能证明 Agent 已连接 Hub。不要因为找不到 `CodePierAgent` 就删除旧目录或重新创建节点。

首次连接 Hub 失败的节点可能没有上报过 `info.platform`。**旧版面板会把未知系统默认为 Linux/macOS，甚至自动生成 Bash 管理命令**；该命令包含 `bash`、`mktemp`、`trap`、`&&`，直接在 Windows PowerShell 运行会产生 `ParserError`。新版面板对未知平台不再预选系统，也不自动生成维护命令；须明确选择 **Windows PowerShell** 后再复制。已有旧面板请手动切换系统并重新生成完整命令，不要试图在 PowerShell 修补 Bash 语句。

无论任务计划程序显示什么名称，面板用于**安装或升级**的 `-ExpectedDevice` 必须与该账号安装目录 `config.json` 内的 `device_id` 一致。Windows 本机卸载不按面板节点身份限制：它盘点当前 Windows 账号下可验证归属的新旧默认安装、自定义安装、已验证计划任务指向的安装，以及同目录受控归档备份，一次显示清单并确认清理。若原 Hub 节点不存在、或先前从“接入电脑”创建了另一个新节点，必须先核实旧本机身份。目标是保留原节点还是重新安装为新节点需要明确区分；后者使用受控归档恢复，保留原目录及状态以便回退，不能悄悄把旧凭据改成新设备的凭据。

`uv` 如果对锁定依赖文件里的 `--require-hashes` 输出 `Ignoring unsupported option`，同时命令行已传入 `--require-hashes` 且全部依赖安装成功，则该警告**不是**本次身份不一致错误的原因；仍应以真实命令退出状态及完整安装结果为准。

## 面板生成一键升级、卸载与 Windows 失败安装恢复命令

在设备节点点击 **完整管理 → 命令升级 / 卸载**。选择目标系统；自定义安装时填写 Agent 的绝对安装目录，默认安装可留空。复制对应命令到目标电脑的本机终端执行。

这些管理命令不需要安装票据，不重新配对、不轮换密钥。升级与 Linux/macOS 卸载检查命令所指节点是否与本机一致；Windows 卸载独立于所选节点 ID 与原 Hub，按本机所有权盘点进行。命令固定本次脚本及安装包校验值；面板后续更新导致旧校验值失效时重新生成，不要删掉校验参数。

Windows 卸载会先显示全部受管安装、计划任务及归档备份的清理摘要，然后只要求一次 `UNINSTALL CODEPIER` 确认；明确指定 `-Yes` 等价于批准该清单的删除。尚有项目、外部状态、已注册浏览器桥接、未知内容、无法确认的任务归属、活动任务或进程时，会停止并保留它们，不会按相似名称猜测删除。其它 Windows 账号不在扫描范围。

任务已缺失、服务 XML 已丢失或先前文件清理中断时，可以按保留的受管元数据继续核实清理。Python 和 PowerShell 之间保留同一维护锁；PowerShell 同步核验目录删除结果，未删除完成会明确报错且保留重试证据，不会显示成功。全部已验证目录清理完成后，重新生成新节点安装命令；安装仍不会自动覆盖另一个节点的身份。

### Windows 卸载中的 Python Junction 与 SQLite 预检查

受管旧安装的 `python/cpython-3.13-windows-x86_64-none` 可能是 uv 创建的版本入口，指向同目录的 `cpython-3.13.12-windows-x86_64-none`。卸载仅接受已证明归属的 `managed-runtime` 布局、直接位于 `python` 下的标准版本入口、同目录且版本/架构匹配的真实目标，以及无链接的 `python.exe`。符号链接、链式联接、安装目录外目标和其他重解析点仍拒绝处理。

预览、会话检查和确认阶段保留联接与 `pyvenv.cfg`，不会先拆掉正在使用的解释器。Python 完成验证并退出后，PowerShell 再次核对联接快照，仅以非递归方式移除联接入口，然后重新验证无链接目录树，继续既有清理。确认期间联接变化会停止；正式删除开始后的文件占用等失败保留卸载恢复证据，属于可重试的部分清理，不承诺恢复已经删除的安装文件。

如果提示 `Cannot verify native terminal session state` 或 `Cannot verify Agent task state`，新诊断会显示数据库路径、原始 SQLite/系统错误码，以及数据库本体、`-wal`、`-shm` 的只读可访问性检查。权限拒绝、共享/数据库锁、损坏和未知打开错误分别说明；仅本体可读不代表 SQLite 可以读取 WAL 或证明空闲。维护仍会停止，不自动提权、修改 ACL、删除辅助文件，也不以数据库副本或 `immutable` 读取绕过状态。请在原安装账号下核查具体文件与底层错误；不要只根据外层 `Agent operation did not complete` 判断原因。

不要通过正在维护的 Agent 自己的远程 Shell 执行这些命令。先结束本机任务、原生终端会话及其他生命周期操作，否则会被安全检查拒绝。

## 安装后可重复使用的本机命令

新版安装或升级会在安装目录生成管理入口。Linux/macOS：

```bash
# 从本机配置的 Hub 获取当前安装包，校验后升级
"$HOME/.codepier-agent/codepier-agent" upgrade

# 查看安装信息，不显示连接密钥
"$HOME/.codepier-agent/codepier-agent" status

# 本机卸载；终端需要输入完整节点名称确认
"$HOME/.codepier-agent/codepier-agent" uninstall
```

Windows PowerShell：

```powershell
& "$env:USERPROFILE\.codepier-agent\codepier-agent.ps1" upgrade
& "$env:USERPROFILE\.codepier-agent\codepier-agent.ps1" status
& "$env:USERPROFILE\.codepier-agent\codepier-agent.ps1" start
& "$env:USERPROFILE\.codepier-agent\codepier-agent.ps1" uninstall
```

自定义安装时将路径换成实际安装目录。旧 Agent 没有 `agentctl` 时，先在已部署新版的面板生成一次管理命令；也可以使用完整新版源码包里的入口：

```bash
bash deploy/install-from-hub.sh upgrade --install-dir "$HOME/.codepier-agent"
bash deploy/install-from-hub.sh uninstall --install-dir "$HOME/.codepier-agent"
```

升级需要访问本机配置中的 Hub；本机 `uninstall` 和 `status` 不要求面板在线，也不下载 Python 或安装包。已损坏的解释器、缺失的服务定义或非受管目录会明确报错，不会猜测并删除文件。

`upgrade` 保留设备身份、连接密钥、项目权限、任务和历史；普通升级只切换运行时。首次 CodePier 命名迁移另外调整受管目录路径字段，并保存配置原始字节备份，详见迁移说明。下载、校验或依赖安装失败不会覆盖旧运行时；新服务启动检查失败由生命周期助手回滚。上一运行时保留在 `.runtime-previous`。

## 卸载范围和确认

卸载删除本机 Agent 服务、运行时、配置、密钥、日志和位于安装目录中的状态。需要保留本机备份、检查点或日志时，请先单独备份。安装目录之外的项目文件，以及 Hub 的节点记录、项目映射和审计记录均不删除。

如果授权项目目录位于 Agent 安装目录内部，卸载会拒绝继续，避免连同项目一起删除。若配置了安装目录之外的自定义 `state_dir`，不会通过猜测路径递归删除该外部状态目录，请自行按备份策略管理。

默认必须准确输入节点名称。仅在已经确认卸载范围的自动化流程中显式使用跳过交互确认的参数：

```bash
"$HOME/.codepier-agent/codepier-agent" uninstall --yes
```

```powershell
& "$env:USERPROFILE\.codepier-agent\codepier-agent.ps1" uninstall -Yes
```

服务停止失败时保留文件，不再使用“忽略停止错误后直接 rm -rf”的卸载方式。Windows 在 Python 退出后由独立进程清理仍被占用的安装目录，PowerShell 入口检查目录确已移除才报告完成。实际卸载成功后的再次调用源码入口会提示没有安装、无需清理；已删除的 `agentctl` 文件本身当然不能再次执行。

卸载本机 Agent 不等于删除面板记录。需要删除面板记录时，在节点详情中另行操作。

## 安装完成但自启动失败

安装器保留已经配对的配置，并输出恢复命令。使用原安装账号执行，路径以实际输出为准：

```bash
"$HOME/.codepier-agent/runtime/.venv/bin/python" \
  "$HOME/.codepier-agent/runtime/scripts/install_agent.py" \
  --install-dir "$HOME/.codepier-agent" --start-service
```

```powershell
& "$env:USERPROFILE\.codepier-agent\runtime\.venv\Scripts\python.exe" `
  "$env:USERPROFILE\.codepier-agent\runtime\scripts\install_agent.py" `
  --install-dir "$env:USERPROFILE\.codepier-agent" --start-service
```

先确认没有另一个 Agent 实例。恢复仍失败时保留日志，检查目标账号、目录权限和 systemd/launchd/任务计划程序状态，不要删除密钥强行重装。

旧 Windows 受管安装在本机执行新版升级或修复命令后，会将登录触发改为开机触发；需要接受一次 UAC。面板远程更新会更新看门狗，但不能代替本机完成首次开机任务授权。源码安装则先关闭旧前台进程，再运行新版 `deploy\start-agent.cmd`，保留原配置并迁入受管运行时。默认日志目录为 `%USERPROFILE%\.codepier-agent\logs`。

Windows 原生验收可在管理员终端运行 `python scripts/check_windows_service.py --output dist/windows-service.json`。它只创建临时任务和模拟 Agent，验证启动命令退出后继续运行、进程被杀恢复、卡死恢复和维护期间不被补拉，最后删除临时任务。该测试不重启或注销电脑；实际重启且不登录时的节点在线状态仍需在目标机器验证。

## 验证边界

本轮在 macOS 的隔离测试目录执行 Python、Bash 和 Chromium 回归；真实系统服务调用通过测试替身隔离，没有停止或卸载现用 Agent。Windows PowerShell 分支有命令契约检查，但没有 Windows 实机安装、升级、卸载验收；Linux systemd 也没有本轮实机部署验收。完整记录见 [开发与验证](DEVELOPMENT.md)。

2026-10-10 的 Windows 下载专项在 macOS/Python 3.13 上通过 52 项下载与安装相关测试，覆盖断流、响应头等待超时、读取超时、有限重试、401/403/409、重定向、错误页面、包身份及 SHA 校验。另在已授权的 Windows 测试节点上，以原生 PowerShell 5.1 和现有 Python 3.14.5 执行抽取的纯下载代码，验证本地 HTTP 503 后重试成功与错误 SHA 拒绝两例；只使用临时文件和 127.0.0.1，不执行完整安装器、配对或服务操作。这不等于已复现用户另一台 Windows 的网络超时，也不替代新 Hub 部署及目标电脑安装验收。

# 知识地图自动维护

显式 `act(action="knowledge")` / `project_knowledge_build` 默认带 `auto_refresh: true`。它在同一个事务中登记独立后台维护任务；只有该次生成成功（完成或已保存分批进度）后才开始维护或续建。旧版本已经存在的地图不会因升级、打开项目或只读查询而自动登记，需要再显式生成一次。

## 工作方式与开销

- Hub 独立后台循环每 15 秒最多处理 4 个到期登记，全局最多 128 个登记，同一设备最多启用 32 张地图，避免后台轮巡超过缓存容量。每张地图默认约 120 秒检查一次，不逐次文件保存立即触发，不承诺即时或原子仓库快照。
- 正常生成默认完整读取。后台用 `incremental: true`，先走受管清单及当前路径保护检查。只有设备、inode、大小、mtime_ns、ctime_ns、mode、硬链接数和缓存摘要 SHA/结构版本均匹配，才复用已有条目，变动文件重新读取和提取。新增、删除、重命名都会通过清单刷新体现。这个方式也覆盖 IDE、Git、Shell 等工具外修改。
- 元数据缓存仅在 Agent 内存，最多 32 张地图。Agent 重启、缓存淘汰、地图版本改变或超过 900 秒时进行完整 SHA 读取。缓存没有持久化权限。元数据不等于内容新鲜证明；显式查询和自动上下文仍逐条检查当前源码 SHA，隐藏过期摘要。
- 文件总数默认不限。文件数、读取字节数和扫描时间的批次预算会产生持久化进度，后台继续下一批；单文件和地图总存储保护仍有效。后台不会调用模型、执行项目代码或请求付费服务。
- 设备离线或已有活动操作时，后台延后，不堆积扫描。每张地图只有一个在途维护操作；正常项目读写不必等待后台循环，但已获准执行的地图生成仍遵守现有项目写入排他，可能与随后到达的操作短暂串行。

## 权限与恢复

每一轮重新核对原用户/身份代次、原授权 grant、当前 read/write 权限、房间工具范围、项目设备和根目录映射，且通过普通操作准入、交付授权复核和 Agent 当前目录/敏感路径/符号链接/硬链接策略。登记不是永久授权，不扩大权限，也不会选择其他 grant。它是绑定原 grant 的持续任务，不依赖短期 OAuth access token 的刷新；原 grant 撤销、过期或范围收窄仍会暂停。用户身份或项目映射变化后，必须显式重新生成才能恢复。

Hub 重启恢复同一登记、代次、在途 operation ID 和提交幂等键；不会把未确定结果当失败重放。Agent 重启丢弃优化缓存，下一轮完整核验。首次生成失败不启用维护。后续明确失败按 240 秒起步指数退避、最多 3600 秒；未确定或需要审阅的结果暂停。文件持续变化或超预算时保留上一张完整地图，查询继续隐藏过期内容。

自动增量刷新必须已有当前根目录身份对应的地图，或具有该根目录显式构建返回的精确 cursor；不能为新目录或被替换的根目录隐式创建地图。分批进度、扫描路径和排除范围在 Hub/Agent 重启后保留；设备忙或离线不会丢失续建位置。building 状态不更新最近完整成功时间。

## 控制与状态

使用新的幂等键显式生成：

- `args: {"auto_refresh": true}`：生成并启用/恢复维护。默认值为 true。
- `args: {"auto_refresh": false}`：生成一次并停止后续调度。尚未交付的后台操作会被代次围栏阻止；已经交付并开始执行的操作可能完成，不伪装为已取消。
- `args: {"auto_refresh": null}`：仅生成，保留现有维护设置。
- `args: {"incremental": true}`：对已有地图使用有界增量优化，仍受完整复核周期限制。一般无需手动指定。

正常生成/查询回执附带 `auto_refresh` 状态：`initializing`、`building`、`watching`、`submitting`、`refreshing`、`offline`、`deferred_busy`、`backoff`、`paused`、`needs_review`、`initial_build_failed` 或 `disabled`，以及下一次检查、最近成功、错误码。状态为调度状态，不是全仓源码已核验最新的证明。返回 pending 时仍用原 operation ID 查询，不重新提交；独立 job 回执不一定带该调度状态。

只读查询不创建登记、缓存或表，不触发任何刷新，不能开启或恢复维护。后台数据库表由 Hub 生命周期或显式写操作创建。

生成 wire epoch 为 4，查询保持 2。Hub/Agent 需要对应版本，不回退到旧 Agent、不转 Shell。源码测试通过不表示已部署或完成真实平台长期运行验收。

默认新增的批次、路径和 cursor 字段不改变原幂等指纹。旧请求恢复时须保留原 max_files（旧默认 2000），新默认 0 表示不同的扫描总量；原终态也可直接按 operation ID 查询。同一旧键只恢复原操作，不补建后台登记。启用自动维护需要一个新的显式生成键。旧终态仍通过原 operation ID 查询；未执行的旧 wire 请求可能要求升级/重新核查，不自动换键重放。

自动更新只重新提取确定性结构摘要，不调用模型。人工或 agent 补充的语义摘要仅在源 SHA 不变时保留；源码变化后改用新提取的结构摘要，不自动改写原人工语义说明。

后台登记只支持绑定可持续复核原 grant 的主体。panel/admin 或其他无 grant 主体仍可正常手动生成，但不能据此启用长期后台维护；生成回执以 `auto_refresh_request.state: unsupported_subject` 说明未登记。既有无 grant 后台登记会暂停，不将旧管理员或会话快照当作持续授权。已有其他有效登记的状态仍独立返回。

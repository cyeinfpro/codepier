# ChatGPT 内任务工作台 · 2026-09-17

本轮是源码、静态组件和测试的更新，不是现用 Hub/Agent 已部署的证明。实际验证记录由各次发布单独保存；历史本机证据不随公开源码分发。发布门槛见 [发布清单](RELEASING.md)。

## 从项目入口到任务结果

`open_workspace` 仍打开明确项目，不自动把“最近任务”当作当前聊天。卡片增加任务选择器，展示当前凭据可访问的已保存任务。完整工具模式下，`workflows_get` 的结果直接绑定该任务并显示同一工作台。

主区域显示任务目标、保存的步骤状态、验收条件与真实关联回执；完成步骤数不是估计的执行百分比。四个结果入口分别为执行记录、固定改动、验证、交付物。

执行记录按原操作编号读取状态、退出码和最多 8,000 字符的日志尾部。失败操作的日志仍可查看，刷新不重新执行命令。命令及工作目录可以展开查看；环境变量不在摘要中展示。结果不明的操作不会被报告为成功。

固定改动始终读取同一个 `review_ref`。文件及差异按需分页；过期、失败、覆盖不完整会明确显示，绝不把当前目录重新拍摄后冒充原快照。

验证列表先显示历史结果；点击“核对源码与报告”才调用 `validations_get` 检查源码是否仍一致。只有命令通过、源码一致且扫描覆盖完整，才显示核对时通过。通过不等于所有验收条件满足，也不等于已经部署。

交付物必须由 `artifacts_register` 明确登记，并把该操作编号关联到任务。界面显示原文件名、大小、SHA-256、有效期；下载前重新核对登记信息，只打开当前面板域名下的原文件鉴权下载入口。外部浏览器需要登录同一管理面板；“请求打开下载”不代表下载完成。文件过期或设备离线时不会假装成功或自动重建。

项目近期操作单独放在“未自动归属所选任务”区域。它们不会被合并成该任务的测试或改动证据。任务选择只切换视图，不会替模型启动、接管或继续工作。

## 如何让任务持续有内容

对于需要多步骤执行的工作，完整工具模式应沿用既有流程：

1. 使用 `workflows_list` 找回任务，或在用户授权的新任务开始时 `workflows_create`。
2. 实际操作提交后，使用 `workflows_update` 保存步骤和原操作编号。排队/执行中的回执也可以关联，不能把提交当成完成。
3. 完成修改后冻结 `show_changes`，执行 `validation_run`，登记明确交付物；把这些原始操作编号写入任务证据。
4. 以 `workflows_get` 显示该任务的卡片。声明完成前核实实际结果，部署证明单独说明。

本轮已将上述关联规则加入服务器说明。服务器不会读取 ChatGPT 隐藏推理或完整聊天历史来自动编造任务；没有保存任务或关联证据时，卡片会显示相应空态。

编码精简目录保留 27 个模型可见工具；新增一个只对卡片使用的 `workspace_status` 读取工具。完整目录也将该工具标为 app-only。支持工具的 UI 可见性只是宿主展示信息，不是授权边界。

## 次级区域

“项目与权限”收纳目录、权限标签和中文就绪检查。标签不是授权开关，也不证明实际能力已经实测。“修改前基线覆盖”可以展开查看捕获文件数、容量预算、已记录的跳过原因；扫描未遍历的文件没有完整清单。基线不是全盘备份，事后重拍不能补回修改前遗漏。

“附件导入”提供文件名路径建议、现有目录选择和分页，以及保存后的大小和 SHA-256。只允许项目内目标路径，不自动建目录、覆盖、解压或执行。依赖宿主实际提供文件上传接口：不支持时禁用保存并说明聊天附件或管理面板替代路径。未使用不存在的“读取全部聊天附件”接口。

文件上传期间锁定目标；结果不明时只用原参数、原幂等键恢复，拿到原操作编号后继续查询。明确的执行前拒绝或已核实失败才允许用户修正后另开请求。单纯超时不自动生成新写入。

“高级管理”只保留已验证协议的原面板地址。验收接受、权限修改、Agent 升级/卸载仍要求管理员身份和原有确认，不新增越权按钮。

## 刷新、隐私与范围

任务摘要有活动任务或未结束操作时约每 6 秒读取一次；打开的原操作日志约每 2 秒读取一次。自动跟踪最多 10 分钟，可手动继续。页面不可见时不安排新的自动查询；错误、取消显示或组件销毁会停止相关循环。取消卡片显示不等于取消后台命令。

切换任务或组件输入时停止旧显示生命周期，过期响应不会覆盖新选择；日志和差异还有独立的详情生命周期。新卡片优先绑定返回的项目 ID，避免别名更名造成误读。所有服务器调用重新验证项目、凭据及所需权限。

任务是项目级保存记录；操作按卡片的原目录/精确 `workspace_id` 筛选。隔离工作区应从对应的 `open_workspace(workspace_id=...)` 卡片查看。旧任务的项目目录或设备映射变化时，旧证据不关联到新目录。

每页默认 12 条关联引用；可继续加载。近期操作只扫描最近 50 条操作窗口；任务事件最多读取最近 100 条，再加当前步骤引用。达到边界会明确提示，不把有上限的结果当作完整历史。Dashboard 摘要不返回原始日志、环境、源码差异或桌面/浏览器媒体；这些内容不会借 read 汇总接口绕过额外权限。

## 构建与生效

组件仍使用已锁定的 `@modelcontextprotocol/ext-apps` 依赖，未新增外部资源域名、CDN、字体或网络连接域名。源码拆分为 `app.js`、`dashboard.js`、`review.js`、`workspace-tools.js`、`ui.js`；构建输出仍是两张自包含 HTML 和校验 manifest。

```sh
cd web/mcp-apps
npm ci --ignore-scripts
npm run build
cd ../..
.venv/bin/python -m pytest -q tests/test_workspace_status.py tests/test_workspace_dashboard.py tests/test_mcp_apps_host.py tests/test_coding_workflow.py
```

源码包带已构建的 HTML；部署时同时更新 Hub 代码和 `web/mcp-apps` 静态资源，保留原数据、配对、授权与项目。新汇总工具运行在 Hub；本轮没有新增 Agent 执行器。生产 Agent 仍需具备原有工作区/验证/交付能力。

更新服务后，刷新宿主的连接器工具与资源信息，再重新打开项目或任务卡片验收。旧消息里已实例化的卡片、缓存的工具目录，以及没有升级的 Hub 不保证自动变成新版。更新静态页面而不更新 Hub 会出现明确的接口不可用提示。

实际 ChatGPT 宿主文件传输、现用生产部署、全部客户端/操作系统兼容性，必须分别做端到端验收，不能由 SDK 沙箱或临时项目测试代替。

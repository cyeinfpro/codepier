# VPS 管理、Web SSH 与 SSH 调用

## 保存连接

打开面板 **VPS 管理 → 添加 VPS**，填写名称、IP / 域名、SSH 端口、账号和密码。可补充服务商、地区、系统 / 配置与备注，方便识别面板、边缘节点和业务服务器。不要把密码填进备注；备注属于可读取的连接信息。

名称唯一；相同地址、端口、账号的连接不能重复创建。同一 IP 的不同端口或账号可以分别建档。IPv6 地址在保存时规范化。

新建必须填写密码。编辑时密码框始终为空；留空保留原密码，填写新密码才会替换。保存接口不返回密码，也没有密码读取接口。本版支持保存密码认证，未新增私钥导入或跳板机配置。

已保存 VPS 的受管连接使用 `vps_ssh_v2` 时不核验历史主机指纹。SSH 加密和账号认证仍在；登录不等于核实目标身份。保存的地址错误或网络不可信时，密码可能被错误的主机接收。只在可信网络使用，并核对目标。普通系统 SSH 和通用工具的主机信任规则不变。

## 项目多对多分配

在 VPS 卡片点击 **分配项目**，可勾选多个项目。也可在 **项目映射 → VPS 分配** 中给一个项目勾选多台服务器。调整一个项目不会清除其他项目的分配。

项目命令通过所选项目所属的 Agent 发起，不要求在 VPS 安装 Agent。批量环境检查仍由 Hub 按现有空间授权执行。两条路径的网络可达性和权限分别核对。

已有项目执行权限的客户端可使用分配的连接；仍需要项目为可写、允许任务，且 Agent 本机启用 Shell 并明确允许该项目。项目分配不是远程操作系统沙箱：命令拥有保存的 SSH 账号权限，不会只被限制在某个远程目录。

其他窗口改动配置或分配后，旧表单不能覆盖新配置；重新打开、核对再保存。删除项目时，其 VPS 分配自动移除，服务器连接本身保留。

## 在浏览器中使用 SSH

在 **VPS 管理** 的服务器卡片点击 **SSH 终端**，选择已经分配且允许执行的项目。连接由该项目所属的 Agent 发起，VPS 不需要安装 CodePier Agent。Agent 必须在线、支持新版 Web SSH 并安装锁定的 AsyncSSH 依赖；旧节点会显示升级提示。正式访问使用同源 HTTPS，HTTP 仅允许 localhost 回环测试。

终端提供多标签、独立双分屏、搜索、复制粘贴、全屏、字体与主题设置、中文输入和手机辅助按键。切换面板页面保留终端实例与滚动位置；注销、切换 Space 或权限失效会清理当前身份的终端状态。多行、大段和包含控制字符的粘贴先预览；输入和输出不保存到浏览器持久存储。

默认自动探测 VPS 的 tmux：可用时建立本功能专属的持久会话，不可用且尚未创建 shell 时进入普通 SSH 模式。刷新后持久会话重新 attach 并重绘，恢复不会偷偷新建 shell。普通 SSH 只在原 Agent/SSH 仍存在时恢复；新页面的历史重放有明确边界，超过保留范围会提示历史缺口。不会自动安装 tmux 或修改用户既有 tmux 会话。

短暂断网时，仍保留的原 renderer 从已实际渲染的字节位置续接。**输入结果未知时不自动重发按键或命令**，避免把有副作用的命令执行两次。另一个窗口需要明确接管，旧窗口随即失去写入权。关闭标签、暂时离开与明确结束会话的区别，以及 direct/tmux 的保留时限，见 [Web SSH 运维与故障处理](WEB_SSH_OPERATIONS.md)。

已保存 VPS 的 Web SSH 使用保存的密码，不转发目标主机要求的其他认证提示。新版入口会显示实际终端能力；缺少新版能力时先更新相应组件，不另开未获授权的入口。

交互流走独立的加密 Agent 通道，终端正文不写入操作审计、操作回执或 AI 上下文。Hub 只保存会话归属、目标引用、状态、字节计数和必要审计。终端会忠实显示远端字节，不在交互输出中替换字符串，以免破坏全屏应用、控制序列或输出偏移；请按 SSH 账号的真实权限操作。

完整设计与本轮实现记录保留在项目内的 `WEB_SSH_DESIGN_IMPLEMENTATION_20261122.md` 和 `WEB_SSH_IMPLEMENTATION_20261122.md`，不随公开源码包分发。公开使用说明见上方的 Web SSH 运维与故障处理手册；这些说明与构建结果不等同于生产环境已经升级。

## 批量终端环境

批量结果覆盖当前空间的已启用 VPS；按项目筛选只改变下面的列表。「扫描全部 SSH」只检查连接及 tmux。只有最近一次扫描确认缺少 tmux 的记录，才能由管理员通过「一键安装」提交。

连接中断或检查超时会按队列退避复查。只有准备发送包管理命令时才记录安装开始；如果回执丢失，后续尝试只读检查 tmux，不重发安装。仍显示结果未确认时，可检查目标机的包管理器和安装状态，确认 tmux 可用后复扫。包管理失败、安装权限不足和版本或路径不受支持分别显示原因。

一键安装使用目标上现有的 APT 或受当前账号管理的 Homebrew。macOS 已手动装在当前 SSH 账号的 `~/.local/bin/tmux` 时，检查与持久终端共用这一路径；文件和父目录须属于当前账号，且不能是符号链接。不会通过任意 PATH 位置执行 tmux。

## 在 ChatGPT 中调用

部署新版 Hub 并刷新连接工具目录后，所有 MCP 目录统一使用 `vps` 查询、`exec` 执行；旧名字已移除。详见 [九个 MCP 工具](CORE_TOOLS.md)。

`vps` 参数示例：

    {"project":"ProjectAlpha","query":"广州"}

返回已授权项目关联的名称、IP、端口、账号、启停状态及可见项目。不返回密码，不暴露未授权项目的名称或编号。支持 offset / limit 分页，按 next_offset 继续。

`exec` 参数示例：

    {"project":"ProjectAlpha","target":"vps:<列表返回的连接编号>","command":"df -h","timeout_seconds":30,"idempotency_key":"unique-intent-example-001"}

使用列表返回的精确 `target`，不再按名称或 IP 隐式选择。多个端口或账号要先从列表中选定连接，不能覆盖已保存配置。

执行使用面板保存的密码；聊天里提供新密码不会自动覆盖保存的连接。需要更换密码时，在 VPS 管理中编辑并保存。

可以直接说：**“SSH 到 ProjectAlpha 的广州面板，检查磁盘。”** 或 **“连接已保存的这台 IP，检查服务状态。”** 客户端先查询授权连接，确定项目和目标后执行，不需要再次发送密码。工具调用仍受客户端正常的执行确认与授权约束。

## 传送本地构建产物，再部署

1. 在该项目构建完成后，用 `write(operation="artifact")` 登记不可变产物，取得 `artifact_id` 和 `sha256`。用 `vps` 取得同一项目的准确 `target`。
2. 调用 `exec` 的传包模式，不能同时传 `command`。例如：

        {"project":"ProjectAlpha","target":"vps:<精确连接编号>","stage_artifact":{"artifact_id":"<已登记产物编号>","sha256":"<64 位摘要>"},"timeout_seconds":600,"idempotency_key":"release-stage-intent-001"}

3. 查询同一个 `operation_id`。仅在返回 `stage_state=verified` 时使用 `remote_path`；`install_state=not_started` 明确表示只传了包。获得该部署的授权后，再对同一个 VPS 执行项目现有的安装步骤；安装前复核摘要，结束后核对版本和健康检查。确认成功后按项目规程清理这一个临时包及其空目录，不删除其他任务的文件。
4. 连接失败、写入失败、摘要不匹配、最终提交回执未知是不同结果。回执未知时查询原操作，不换新键重传，也不猜测路径执行安装。没有 SFTP 则明确报错，不以 Shell/Base64 绕过，不要求把包公开。

传包使用目标已有的 SSH 端口和已授权连接，不需要公开下载 URL。Hub 和 Agent 都需支持该能力。需要同一项目的读产物和执行权限；只接受指定的不可变产物（至多 512 MiB），不接受任意本地或远端路径。VPS 需有 root 所有、有 sticky bit 的真实 `/tmp`；暂存目录与文件使用 0700 / 0600。数据分块发送，回读文件逐字节核对大小和 SHA-256 后才原子改名。请预留至少一个文件大小的远端临时空间；此路径不是长期存储。传包沿用已保存 VPS 的连接信任策略，SHA-256 校验包内容、不验证主机身份。对公网高敏产物应使用经身份验证的受控连接。

## 检查连接与执行结果

卡片的 **已启用** 是配置开关，不代表服务器在线。点击 **检查连接**，选择已分配且允许执行的项目，再点击开始。固定检查只读取主机名、账号、系统和根目录磁盘信息，不修改远程服务器。

Agent 离线时，操作进入原有持久队列；关闭弹窗不取消已提交操作，结果可在 **操作审计** 中按 operation_id 查询。恢复使用原幂等键与回执，不重复创建命令。

提交命令后，用 `process(operation="wait"/"get", operation_ids=[...])` 查询原回执。相同请求重试保留原幂等键；不同命令使用同一键会被拒绝。超时、认证失败、主机密钥问题和非零退出均保留真实结果，不把失败当成功。

同一次操作内部最多尝试 **3 次 SSH 连接**。只在业务命令确认尚未进入发送阶段、且允许重试的连接故障发生时复试；认证、协商失败或未知结果按原回执真实记录。所有尝试共用原总超时，不自动重放已进入发送阶段的命令。

VPS 的 `exec` 默认同步等待最多 10 秒，通常可在短暂故障恢复后直接返回最终结果。显式 `yield_seconds=0` 仍立即返回回执；超出同步等待窗口的操作返回 `pending`，继续查询同一操作即可，不需要重新提交。后台重试期间不会把第一次认证失败当作操作的最终失败。

结果中的 `ssh_diagnostics.attempt_count` 和 `attempts` 记录 SSH 尝试次数及逐次结果；顶层 `attempts` 仍表示 Hub 投递次数，不能混用。`credential_source` 区分保存的 VPS 凭据与显式密码，`retry_stop_reason` 说明因成功、上限、超时、取消或不可安全重试而停止。`transport_runtime` 表明使用的是 SSH 传输，不把项目本地运行环境当作远端环境。客户端日志与远程输出分开采集，避免远程程序打印的 `Permission denied` 被误判为这次 SSH 登录失败；日志在返回前脱敏，临时文件在结束时清理。

这些回执描述 CodePier 实际执行的情况。若调用平台在提交前拒绝工具调用且没有操作 ID，CodePier 无法替它判定审核来源，也不会把它计为一次 SSH 尝试。内部重试规则不授予新的权限。

取消会停止本地 SSH 传输，但不保证远程进程停止或回滚。不要因断线就用新键重跑结果不明的写命令。

## 凭据与撤销

密码使用 Hub 现有主密钥加密保存在数据库。排队只保存连接 ID、配置修订号与项目分配标识；发送到 Agent 前才解密，通过已有加密 Agent 通道传送。Agent 用子进程环境变量供给 SSH，不把密码放进命令参数。

工具返回、参数摘要、公开连接列表和审计不返回密码。现有 SSH 执行器对输出中的实际密码进行流式脱敏，包括跨分块的情况。浏览器不将密码写入 localStorage 或 sessionStorage，关闭表单后丢弃输入。

停用、删除、改换地址 / 账号 / 密码或取消分配，会阻止尚未下发的旧请求。取消再重新分配不会使旧队列复活。仅修改名称、说明不改变固定执行目标。已经发出且结果不明的请求恢复原 Agent 账本，不宣称远程命令没有执行；已下发或被 Agent 接收的操作（包括 Agent 本地等待执行的任务）不会因取消分配或删除连接自动停止，需查询原回执；需要停止时单独取消原操作，但仍不保证远端进程停止。

同时备份 **hub.sqlite3 与对应 master.key**。缺失密钥时不会生成新密钥覆盖已有加密数据，应恢复配套备份。Hub 主机管理员仍有解密能力，需保护账号、数据目录和备份。生产面板宜使用可信 HTTPS。

## 更新与验证范围

本功能需要更新 Hub 服务端和静态页面。Hub 和 Agent 都需要更新到支持新 exec 工具契约的版本，受管 VPS v2 入口使用锁定的 AsyncSSH 依赖。旧 Agent 会返回明确的升级提示，不会猜测新参数的含义。本功能不会自动重启或停止生产 Agent。

自动化测试使用隔离 Hub、Agent 和模拟 SSH 可执行程序，实际验证子进程、加密通道、回执与输出处理；Chromium/WebKit 测试实际操作面板。这不等同于已经登录真实 VPS，也不代表已经部署生产。

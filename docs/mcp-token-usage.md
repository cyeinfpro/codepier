# MCP Token 与上下文情景估算

此功能提供两层独立参考：已授权项目的工具参数/返回文本统计，以及在这些记录上重放的滚动上下文情景估算。首页默认显示含上下文的参考总量与费用，工具文本留在详情；两者都不是实际 usage 或账单。

## 工具文本可见范围

- input：本次公开工具调用提交的参数，经确定性 JSON 规范化后的文本。不加入服务端默认值。
- output：最终结果中的文本内容；没有文本内容时才使用 structuredContent。同一结果的 content 与其镜像 structuredContent 不重复计数。
- gateway、全局工具、协作工具、initialize、工具目录、提示词、资源读取及独立 tasks 协议暂不覆盖；未指定项目的状态查询也不覆盖。
- 不计系统提示、完整聊天、模型思考、缓存、宿主重发上下文、图片/音频 token、附件与文件传输字节。
- 原生 Claude 对话返回的实际 usage 属于另一个模型执行链路，不能加到外部 MCP 宿主估算中。客户端 _meta 不能宣称实际计费用量，也不能授予读取权限。

所有 actual_usage 字段固定为 null。没有宿主官方可信用量来源时，应显示“实际宿主用量未知”。

### 滚动上下文情景

`codepier-context-v1` 每轮模型输入 = 固定底座 + 保留历史 + 新可用工具返回 + 少量不可见用户文字；模型输出 = 工具参数 + 少量不可见助手文字。工具结果首次进入输入后，后续历史重读再计入上下文；不能另外把工具文本总量再加一次。

默认固定底座12K，近8轮完整保留，更早历史每轮保留98%；约64K触发已读历史压缩，留出继续增长的空间。64K是默认情景阈值，不是模型真实窗口规格。新返回的可见文本即使超过阈值也先保留，不以假设阈值默默截掉。低/中/高分别采用6K/12K/24K底座、32K/64K/128K阈值，并改变保留、压缩、隐藏文字和分轮假设。区间是情景包络，不是统计置信区间。

相近开始时间或重叠工具、短时间poll会启发式归轮；高情景保留每次调用均为独立模型轮次的可能。有匿名window时按相关流重放，无window时按15/30/120分钟空闲间隔切分，不能声称识别到真实会话。Hub重启会改变匿名key；跨午夜不会人为清空同一流。最后一次工具返回加一次临时收尾读取，新活动来后重算替代旧预测，不能累加历次重放总计。

默认输入缓存90%只是一项价格假设：上下文模型输入 × [10%普通输入价 + 90%缓存输入价] + 模型输出 × 输出价。缓存不减少Token数，也不折扣输出。系统提示和工具定义没有真实观测时属于固定底座假设；不会采集对话正文、凭据或新增模型调用。

例如10轮串行工具，每轮参数100、返回1000，可见工具文本11K；在默认情景下含上下文约206.49K，情景范围约131.85K–363.30K。这是合成算法验算，不能用作真实误差校准。实际保留记录有缺失或截断时同时保留覆盖标记；全部工具指标未知时不只凭调用次数展示一个看似已测量的总量。

## 估算与精度

codepier-text-v1 是无 tokenizer 依赖、未经任何特定模型校准的字符启发式：

- ASCII 字母和数字权重 0.28，空白 0.10，标点 0.60
- 宽字符（含多数中文）1.30；宽字符表情 2.50；其他非 ASCII 0.90
- estimated_tokens 是权重和向上取整；low/high 为 0.5/2 倍权重和向上取整

low/high 仅是展示不确定性的启发式范围，不是置信区间或保证范围。中英混合、代码、JSON 的真实 tokenizer 结果会不同。可以使用下述价格假设做工具文本等价成本参考，不能据此认定实际费用。

characters 和 utf8_bytes 是实际纳入统计的规范化文本的精确 Unicode 字符数与 UTF-8 字节数，不是 HTTP 报文大小。JSON 按紧凑形式统计，包含保留字段的键与分隔符；敏感字段排除后不计其键和值。多段文本相加，不人为插入分隔符。无法严格编码为 UTF-8 的异常代理项文本返回 unavailable/null，不用替代字符的字节数冒充精确值。

## 排除项与隐私

持久化只有整数指标、状态、估算版本及已有活动 ID，不保存参数、输出原文或内容哈希。已识别的授权/凭据字段、请求头、_meta、工具 schema、原生附件对象、显式 base64 字段、图片和音频块均排除；上传分块的 data 排除。为避免误判签名格式，所有 HTTP(S) URL 和 data URI 都排除。长编码片段会保守排除，可能低估长标识符。该功能不是用于其他日志的通用机密清洗器，无法保证识别未标记的自由文本中的所有秘密。只持久化数字仍确保不会为用量分析保存该原文。

## 空值、截断与聚合

- 历史活动没有原始正文可供追溯，其 token_usage 保持 null，不按调用次数乘常数补齐。
- 某方向未观察到内容时，state 为 unavailable，数值为 null。
- 已观察到空文本或仅媒体时，可得 0；0 不等于未知。
- 估算每方向最多 262,144 个字符、10,000 个节点、32 层嵌套。超限返回 partial/truncated，只报告已处理部分，不外推完整量。超限 JSON 字符串优先使用已物化的 structuredContent；没有可用对象时不扫描可能含认证字段的原文前缀，返回 partial 与已计入的零字符。
- source_truncated 表示工具自己已截断原始输出；实际交给宿主的已返回部分仍可完整统计。它与估算器截断不同。
- token_usage_summary 的 scope 为 returned_activity_page，只汇总当前返回页。多页展示应先按 activity.id 去重，再累加已测量指标，同时保留缺失/partial 计数。
- wire_attempts 计本页活动行；同一幂等操作的重试请求、重复读取同一个输出片段，都会再次把输入输出交给宿主，应分别累加。单次响应的重复完成回调不会产生重复行。
- distinct_server_operation_ids 只是当前页引用的不同服务端 ID 个数；有些 ID 是被查询对象，不能当作逻辑调用数或用于 token 去重。
- 全部未知时合计为 null；混合页的和只含已测量部分，应同时展示未知次数，不能暗示总量完整。

## 权限、存储与故障

查询复用活动列表的项目、当前 root/device、grant/actor/Space 过滤，查询时重新刷新原凭据和当前 IAM 权限。指标表只使用授权过滤后得到的活动 ID。撤销的 token、不可见项目、重映射项目不能继续读取旧指标。

独立指标表最多保留 10,000 行、30 天，每行上限 4 KiB；删除父活动时指标随之清理。建表、采集、写入或查询指标失败不会改变工具执行或授权结果，活动接口显示未知并增加 write_errors。


## 工作区总览与只读统计 API

首页“工作区概览”卡默认显示“含上下文 Token”、参考 USD 费用、调用次数、参考模型及90%输入缓存假设，并以一行范围/历史可能不完整说明收尾。工具文本独立保留在详情。缺失显示“未记录”，不把未知显示为0。数字按十进制K/M/B转换，最多两位小数，并在舍入跨单位时继续进位。旧服务未提供已识别的上下文契约时，前端明确回退“工具文本 Token”，不会把旧传输数暗称上下文。

“查看详情”默认收起。展开后，“筛选与估价设置”“请求与响应明细”“用量趋势”“统计说明”仍分别收起，避免一次展开全部表单、图表和长说明；计价依据再按需展开。JSON 导出保留在详情内。筛选、参考模型和缓存率变化后保留当前展开状态，离开页面或权限主体切换重置。今日零点与既有今日操作统计使用同一个 Hub 配置时区，时区和起止时间在统计说明中保留。

GET /api/token-usage 使用当前面板会话认证，并在 Store 数据库 worker 的同一次当前权限读取范围内完成取数。period 只接受 today、7d、30d；project、connection、session 是可选过滤条件。选项仅从当前可见项目及其授权活动产生，输入别人的连接或匿名窗口编号不能扩大访问。服务先按当前项目/root/device 和既有 grant/actor/user/space 规则筛选活动，再读取这些活动 ID 的数字指标。连接名只是授权标签，不用于推断宿主产品。

summary.scope 为 retained_authorized_project_activity，区别于活动分页的 returned_activity_page。它只汇总所选时间段内仍保留的授权记录，受活动 10,000 行及指标 30 天/10,000 行上限约束；coverage.complete_history 始终 false，不代表完整历史或账单。API 不新建持久化访问日志，不保存参数或输出，也不在 GET 时执行清理删除。

上下文先用最多30天/10,000条当前授权记录预热，再按所选日期和小时/日桶汇总模型读取贡献，避免午夜从零重算。每个匿名流按时间前缀独立确认已有数字依据：已测参数或此前已返回结果可以支持该流后续情景；其他窗口、未来才出现的指标和未返回结果不能把当前未知桶变成数字费用。全缺失流不加入已测部分的总量，coverage 另列 observed_rounds/unmeasured_rounds；同流真实跨日历史仍可预热。旧工具文本字段仍只计所选期内的可见传输。趋势默认展示模型输入（含上下文）和模型输出；只返回有授权活动或相关上下文贡献的桶，空白时段不插入0。没有指标时方向合计仍为null；真正观察到的空文本可以为0。近7天/30天按Hub时区日历日期计算。

项目明细仍按 activity.id 合并分页，标出已加载行起止范围（UTC），不伪装成全时间段。重试仍有传输文本成本；文件/图片二进制字节不计入工具文本。


### API v3 与旧字段兼容

`schema_version=3` 仅增加独立嵌套字段。原 `summary.input/output/total/reference_cost` 和对应趋势字段仍是工具文本，方向和价格含义不变，旧客户端可继续读取；参数验证与400/404/422错误结构不变。新增 `summary.context_estimate` 与 `trend[].context_estimate`：

- `kind=context_scenario`、`version=codepier-context-v1`、`scope=retained_authorized_context_estimate`
- `total/input/output` 各含 `estimated_tokens/low/high/partial`；此处input/output是模型方向，区别于旧工具方向
- `reference_cost.scope=context_scenario_equivalent`，使用同一参考模型和缓存假设；不能与旧工具文本费用相加
- `estimated_model_rounds/grouped_tool_rounds/provisional_tails` 只是假设轮数
- `coverage` 包含保留历史、预热、缺失/截断和匿名流推断计数；`complete_history=false`、`range_is_error_bound=false`
- `actual_usage/billing_total` 及未知缓存写入/推理字段保持null

每次请求，包括缓存命中，都先刷新原凭据和当前IAM/项目映射。数字指标用授权范围内的批量join读取，没有逐活动查询。最多8份只读聚合缓存，最长30秒，key含上下文/价格版本、当前权限指纹、访问修订及SQLite本连接/外部连接数据修订。撤权、映射变化、迟到指标或数据修改不能复用旧结果；缓存不会跨日期或指标保留期限。缓存中不保存原始正文，也不写数据库。

## MCP 工具文本参考估价

价格版本 `gpt6-standard-tool-text-2026-10-10-v2`，于 2026-10-10 核对 [官方模型页](https://developers.openai.com/api/docs/models/gpt-6-astra) 与 [官方计价页](https://developers.openai.com/api/docs/pricing)。Standard 短上下文每 1M Token：输入 $10、缓存读取 $1、缓存写入 $12.50、输出 $50。

- MCP input 是模型生成的工具参数，映射模型输出价；MCP output 是工具返回的文本，映射后续模型输入价，不能按相同方向名称直接相乘。
- 默认模型输入缓存读取假设 90%，输入综合参考单价 $1.90/M。公式：MCP 请求 Token × $50/M + MCP 响应 Token × ((1−缓存率)×$10 + 缓存率×$1)/M。缓存读取属于输入子集，不再加到总 Token。
- `/api/token-usage?cache_read_percent=90` 允许整数 0–100，仅影响本次只读参考值；不是生产模型配置，也不修改其他用户的假设。首页展开后可调整，筛选/刷新保留，离开页面或权限切换重置。
- 已加载活动明细由后端为每条授权记录计算默认情景，前端先按 activity.id 合并再相加整数 pico-USD，不能累加分页 summary 或使用不同版本价格混算。全范围首页与已加载分页仍分开标记。
- 没有真实缓存命中、缓存写入或完整模型 usage；重复文本不证明命中，不能复制其他截图的缓存量。缓存写入价格仅供说明，未知用量不凭空收费。当前 actual_usage 保持 null；未来可信真实 usage 应独立显示并优先用于其对应模型链路，不能与此工具文本估算重复相加。
- 完整模型请求输入超过 272K 时，整请求按输入 $20/M、缓存读取 $2/M、缓存写入 $25/M、输出 $75/M；Fast 为适用价 2 倍。当前仅 GPT-6.1 Sol 的官方模型页明确列出 Ultrafast 6 倍，不能把它套到 Astra 或 Luna。单条 MCP 文本不能推断完整请求上下文，本功能固定短上下文 Standard 参考，不擅自切档。
- 合计仅包含已记录部分。全部未知仍为 null，已观察到 0 才显示 0；有缺失时主卡标出“仅已记录部分”，展开显示每方向覆盖。价格范围沿用文本粗略范围，不是置信区间。

`summary.total` 是请求与响应文本之和。`summary.reference_cost` 携带金额、普通输入/缓存读取/输出拆分、模型方向映射、假设、币种、版本和价格来源日期；所有价格计算统一在服务端，采集数据仍只保存原数字，不保存价格或推断缓存状态。它只用于可见工具文本等价成本比较，不代表完整会话、真实调用档位或实际账单。

### 参考模型、精确合计与导出

默认仍为 GPT-6 Astra，可在详情选择 GPT-6.1 Sol 或 GPT-6 Luna。官方 Standard 短上下文单价（USD / 1M Token；输入/缓存读取/缓存写入/输出）分别为 Sol 2/0.10/2.50/10、Luna 0.10/0.01/0.125/0.50，来源同上官方计价页，各模型详情链接随选择变化。每个模型都沿用默认90%模型输入缓存读取假设；不把该选择宣称为识别到的宿主模型。

GET /api/token-usage 的 reference_model 参数仅接受 gpt-6-astra、gpt-6.1-sol、gpt-6-luna，其他值返回400；它只影响本次只读情景，筛选、趋势与总计采用同一模型。调整百分比/模型保留在当前页面，权限主体变化或离开页面重置。不会更改生产执行模型、凭据或价格设置。

amount_pico_usd 与 amount_pico_usd_exact 是同一精确整数金额（1 USD = 10^12 pico-USD），后者为十进制字符串，供JavaScript跨安全整数范围无损合计。amount_nano_usd 是为兼容展示而向下截至1 nano-USD的投影；不得逐行累加该舍入投影。单价和百分比运算使用整数/Decimal，先合计再显示。缓存比例不减少总Token，也不折扣输出。普通输入与缓存读取是同一输入的两部分；缓存写入、reasoning_tokens、实际命中率及账单没有可信来源时保持null。

“导出当前统计 JSON”只下载当前已授权聚合结果、时间、筛选、覆盖范围和价格版本；不包含参数/响应正文、凭据、项目路径或连接名称，不联网发送。数据保留期限和缺失仍在导出中说明，不能用于恢复已过期正文或完整账单。

这些是公开API参考价。ChatGPT/Codex订阅、额度和缓存写入/长上下文规则可能不同，本功能不计算CLI原生会话费用，也不把API参考金额当作该产品实收账单。没有宿主可信官方计费usage接口时，不推算真实缓存写入或推理用量，也不把上下文情景估算宣称为完整上下文真实用量。

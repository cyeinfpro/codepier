# 设置中心

设置中心把个人偏好、空间管理、项目与节点、文件入站、开发控制、MCP 接入、协作和实例运维集中到一个可搜索目录。它不是新的配置存储。

## 现在可以做什么

- 在中心保存全站外观、自己的 MCP 授权预选和有权管理的实例对外地址。
- 个人预选只影响以后授权页面；不会自动扩大现有连接。
- 对外地址与预选保存沿用原 API，并可传原值做条件更新。旧客户端仍兼容。
- 搜索字段名或功能名，查看作用域、管理者、来源、生效方式和对应安全管理入口。
- 选择已授权项目，主动检查文件入站链：Hub、原生转发、节点接收、项目写入。
- 检查只读取就绪状态，不上传文件、不调用模型、不更改本机权限。实际附件传输仍须单独验证。

## 配置权威与来源

- 环境变量、Hub 现有数据库记录、Agent 本地 JSON、原生 CLI 会话、浏览器外观各自继续权威。
- `shared/settings_catalog.py` 只描述字段；`hub/settings_snapshot.py` 只投影有效值。
- 不提供任意 key PATCH，也不把环境变量复制到数据库。
- 只有真实支持编辑的项显示可修改；本机能力和部署绑定项明确显示配置入口。
- 未设置、false、空列表分别保留。命名来源 provider 不自动开启，读取根目录不扩大。
- 本机只报告运行有效值时，不能推断它是显式设置还是默认，更不能声称配置文件已生效。

## 节点检查与隔离

`GET /api/settings/catalog?project=<id>` 与 `GET /api/settings/node?project=<id>` 每次都验证当前账号、空间和项目。缺失或不可访问的项目返回相同 404。目录快照不返回节点根路径或凭据；非实例管理员看不到部署目录与来源列表。

节点检查复用 `readiness_get`，同一权限和映射范围共享进行中的检查，完成结果缓存 30 秒。pending 保留 operation_id，下次查询原回执，不重复发起检查。缓存有 128 项上限。权限、项目映射和身份变化后再次校验；离线、失败或老 Agent 未报告的能力显示未知，不当成 false。

服务端对节点响应按字段、类型和长度做白名单投影，禁止环境值、执行命令、本地路径和任意嵌套返回进入设置快照。

## 生效与维护

普通 Agent 配置校验后热载并重连；state_dir、设备身份和密钥需维护停启。本地 browser/local_control 监听首次启用需正常重启。语言服务和桌面会话的已有实例不应假设已采用新配置。

本机 integrations 继续使用 `python -m agent.setup_integrations --config "<现有配置>" configure --settings "<片段>"` 先预览；只有明确添加 --apply 才应用。不要替换整份 Agent 配置。configure --shell full 会授权所有允许项目，不能当单项目修复。

## 交互保证与限制

未保存草稿离开、切换项目或空间时受保护；取消不提交；旧响应不会覆盖新账号、空间或页面。409 保留草稿，保存成功须重新读取有效值。

尚未把每项部署和本机设置变成远程可写表单。凭据、角色扩权、OIDC、网关工具发布、协作计划启用仍走各自安全入口。工具文本 Token 估算不是宿主完整对话用量或账单，历史未采集的调用不补算。

## 文件入站的显式覆盖

实例管理员可在文件入站表单预览四个有类型的设置：字节接收、原生附件转发、精确主机和命名 Provider。GET /api/settings/file-import 返回当前修订和有效/显式/继承值。POST /api/settings/file-import/preview 只校验和预览；第二次明确点击确认才以相同 expected_revision、patch 和 confirmation 调用 PUT。

null 表示删除面板显式覆盖、恢复继承；false 与空数组保留明确含义。界面修改任一字段即作废旧预览。保存后重新 GET 核对显式值。部署环境变化同样使旧修订失效；没有通用配置写接口。面板覆盖保存在 Hub 原有 meta 存储，由同一 resolver 供真实入站与设置页使用。

新调用立即使用新准入策略；已获准进入最后发布的上传存在完成窗口，已开始来源下载保留原逐跳策略快照。任何开关都不扩大项目、grant 或本机目录权限。已有 OAuth 批量范围扩展是另外的高级表单，需额外确认，绝不随个人预选保存触发。

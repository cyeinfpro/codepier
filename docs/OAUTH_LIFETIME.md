# OAuth 授权期限与无感迁移

适用版本：1.33.23 起。所有 OAuth 客户端使用同一套规则，不按客户端名称切换 PAT、有效期或刷新策略。

## 授权与凭据使用同一期限

授权码、S256 PKCE、DCR、精确回调 URI 和资源绑定继续使用。换码成功仅返回 access_token、token_type 和 scope；有限期授权另返回剩余秒数 expires_in，无限期省略 expires_in。不再为新授权签发 refresh_token，也不使用 0、null 或极大秒数表示无限期。到期点由用户选定的授权期限决定，不能通过兑换凭据向后推延。

凭据是需要保密的 Bearer credential。长期有效会增加泄露后的可用时间，因此服务端每次请求仍检查授权撤销、授权期限、当前账号和空间状态、实时角色/权限及资源受众。撤销立即拒绝后续请求；选择有限期限仍可限制暴露窗口。此次调整不声称已实现发送方约束凭据。

## 原连接如何跨版本接续

Hub 开始接受请求前，以单个 BEGIN IMMEDIATE 事务进行迁移：

1. 保留现有 grant_id、client_id、授权范围、所属空间和原绝对截止时间；没有显式期限记录的历史连接沿用其剩余刷新期限，不能重置为新的 30 天。
2. 仍有效的 access token 延续到同一授权截止时间。只登记这批有效凭据，后续修改期限也不复活迁移前已过期的历史 access token。
3. 当时仍有效且未消费的 refresh token 登记为迁移入口。旧客户端无需更新，下次正常刷新会拿到该授权唯一的稳定 access token；响应不签发新 refresh token。
4. 迁移入口与授权同寿命；重试、响应丢失、并发进程和休眠进程稍后继续兑换，均返回相同 access token。有限期的 expires_in 随剩余时间递减，不承诺整个 JSON 逐字相同。
5. 稳定结果加密存储，数据库仅保存凭据摘要用于鉴权；密文纳入 Hub 的备份、密钥完整性检查及离线轮换清单。事务失败不消费旧入口，也不留下半个结果。
6. 迁移标记和加密结果持久化，重启不重新发证。若结果凭据已被明确删除，其记录作为防重建标记保留，旧入口不能把它重新创建。

旧入口仍按原 client_id、resource、授权 scope 和实时授权状态检查。新旧请求最终都落到同一授权记录；入口不是第二套授权政策。为满足旧客户端不改配置的兼容要求，旧 refresh token 作为可重复的迁移凭据保留，这是持久 Bearer 凭据的兼容取舍，不应声称继续具有一次性刷新令牌的重放检测语义。

## 不自动恢复失效状态

已撤销或删除的授权、已过期凭据、已消费的 refresh_used 和无对应登记的随机凭据均拒绝。旧已消费凭据的迟到请求不会再撤销其他仍有效的凭据。错误客户端、错误资源、越权 scope 不创建或替换结果。

此前已经被旧版本撤销的连接不能通过本次升级恢复。用户明确重新授权后按统一新规则运行。管理员在面板明确延长或重新激活授权属于另一项用户操作，继续遵守原有确认与审计规则。

## 部署与回滚

迁移提高既有持久状态合同的最低读写版本到 1.33.23，镜像 hub-state-epoch 为 2。这样旧程序不能重新打开升级后的数据并轮换迁移入口。只允许单个 Hub 持有状态目录实例锁，不能让旧实例和新实例同时写同一份数据库。

升级前保留数据库、主密钥/密钥环及相关状态的一致备份；停止旧实例后启动新版本，迁移成功才提供服务。事务中断后可重启重试。降级必须使用兼容实现，或恢复升级前的完整一致快照；回退旧快照会回退之后的撤销等变更，不能视作无损回滚。详见 [发布流程](RELEASING.md)。

## 验证范围

自动化用合成凭据覆盖新授权、旧连接保留、重复及并发兑换、独立数据库连接、故障回滚、重启、离线重加密、有限期到期、无限期时间推进、撤销、权限缩减和不兼容旧版本拦截。不会在测试中使用生产令牌。

有限期客户端可能缓存最初返回的到期时间；在服务端延长期限不等于强制更新所有第三方客户端缓存。无限期响应省略 expires_in，仍须在实际客户端版本验证是否遵循此语义。自动化通过只证明被测服务和合成客户端行为，不等同真实 Antigravity/agy、Codex 或其他平台已升级验收。

安全参考：OAuth 2.0 RFC 6749 第 5.1 节定义令牌响应及期限说明；RFC 9700 讨论凭据泄露与公共客户端刷新凭据保护。长期 Bearer 与旧迁移入口的取舍应与选定授权期限一并理解。

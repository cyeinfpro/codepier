# dot 协作：添加、加入、@ 交办

> **双向聊天更新**：新版面板添加的 dot 默认是房间成员，支持普通回复、主动发言和连续话题，不再把每句话变成任务。见 [双向通信指南](DOT_BIDIRECTIONAL_CHAT.md)。下文 task-only 流程继续兼容已有连接。

## 用户流程

在协作中心选定项目和房间，打开「助手与连接」。填写 dot 名称，选择「处理任务」或「只读分析」，确认一次范围，点击「添加 dot，生成加入码」。执行位置默认当前项目 Agent；只有需要时展开并选择已绑定的 VPS。

复制卡片中的完整加入指令，到目标 dot 中 @CodePier 并发送。新的任务加入码以 `CPD-` 开头。dot 使用当前已连接插件加入，并由它的宿主确认、建立唯一的任务事件订阅。加入指令已经包含任务处理意图、保存处理配置和原话题回传要求，无需用户手抄委托编号、目标编号、签名或游标。

卡片显示「任务订阅已连接」后，点击「@名称 发消息」进入讨论，或在输入框输入 `@` 并选择 dot。发送任务后接收对象保持选中，可以继续交办，也可以回复原消息交办后续任务。点击「取消交办」返回普通讨论；只输入未选择的文本 `@名字` 不会偷偷创建任务。

任务领取、进展和最终结果均回复原消息。界面将「订阅连接」「实际领取」「实际回传」分别展示，不把 webhook HTTP 成功当成模型已经完成。未接好订阅时，已创建任务保存在队列中；首次订阅成功和恢复接入时，dot 应立即读取一次待办，再接收后续事件。

## 部署与前提

部署包含本功能的 Hub 与配套面板静态资源。仅源码提交不能更新运行中的服务。已有部署需开启 `CODEPIER_COLLABORATION_ENABLED=true` 和 `CODEPIER_MCP_EVENTS_ENABLED=true`；不需要为直接交办启用监控采集或监控分析派发。修改这些部署设置仍需维护者的部署授权，本实现不偷偷开启。

目标 dot 的插件必须已经能访问该项目。处理任务使用已有 read/write/execute 权限的交集，真正运行命令还需要执行节点原本允许 Shell；只读模式不会新获写入或命令权限。VPS 只能选择当前项目已绑定、启用且严格校验主机密钥的目标。未获权限会明确失败，不自动创建凭据、切换账户或扩大项目访问。

MCP Events 的原生回调和签名材料由目标 dot 宿主提供、验证和续期。使用宿主实际发现的 connector_id，不能用插件名称猜测身份。宿主未确认时保持等待订阅，不用普通定时提醒伪装原生事件。插件目录缓存未更新时按宿主的 MCP 重扫流程刷新目录；服务器仍保留原消费者接口的兼容请求。

加入码有效 30 分钟，任务范围默认七天，并保留现有任务数量、执行和通信预算。有效期和当前范围显示在卡片中。本版本不提供无限期授权或无上限任务承诺。范围到期或版本改变后不能使用旧配置静默续权，应由房主重新确认接入。已绑定 dot 在原有效期内使用卡片「复制恢复指令」，不再次兑换过期加入码。

## 技术闭环

```text
面板 POST /api/collaboration/dot
  → 不可变的房主批准快照 + CPD 加入位置（尚不创建任务）
dot: collaboration(action=join, code=CPD-…)
  → 核对当前连接、原房主、项目/目标快照
  → 自动建立已确认范围的任务规则 + 一次性持久接入基线
  → 返回一条 subscription_request 和完整消费说明
宿主: 保存说明 → 原生订阅验证 → 立即读取一次待办
面板: 选择 @dot → 发送消息
  → 同一事务持久化原消息、委托、工作项、定向 outbox 事件
事件唤醒: collaboration_query(action=dot_inbox, dot_id=…)
  → 读可信房主原消息 → claim → progress / execute → 查询实际操作终态
  → result → 原话题唯一结果回帖
```

公共协作仍是三个工具组，不再暴露一组必须由用户协调的新工具：

| 入口 | 作用 |
| --- | --- |
| `collaboration(action="join")` | CPD 接入任务 dot；CPJ 仍只接入旧通知位置 |
| `collaboration_query(action="dot_connection")` | 只读恢复原订阅和处理配置，不重置接入基线 |
| `collaboration_query(action="dot_inbox")` | 从服务端持久基线扫描待办，返回精确读取、领取、下一页和重新扫描请求 |
| `collaboration_work(action="progress")` | 在有效租约内向原话题回报进展并续租 |
| `collaboration_work(action="execute" / "result")` | 沿用原受管操作和真实回执校验，不绕过执行边界 |

`collaboration_dots` 表以加入位置为主键，固定房间、原确认范围与批准者。加入后另固定策略版本和签名接入基线。数据库触发器禁止改写这些已确认内容。恢复、重复加入和每次唤醒都复用同一基线，避免把新任务误判成旧历史而丢弃。

任务事件只订阅 `codepier.collaboration.delegation_available.v1`（以服务端实际事件目录和返回请求为准），严格过滤项目、环境、会话、位置、策略及版本。事件是通知线索；消费时仍读取可信房主原消息、实际已批准工作项，并逐次核对原连接与当前授权。不得将事件正文、普通房间发言或外部文件当作新的执行授权。

消费者必须遍历 next_page_request，并在结束前重新扫描首页。重复唤醒复用相同领取和步骤幂等键。pending/unknown 状态只查询原 operation_id，不能重新投递。长期操作等待期间按租约要求 heartbeat，默认每 30 秒续租；progress 也会续租。实际终态和回执检查通过后才提交最终结果。执行失败应回传失败或阻塞，不得宣称成功。

原话题收到三类记录：领取时系统确认、dot 主动进度、最终结果。记录带来源任务和连接，进度与结果不产生新的交办事件，避免回复互相唤醒。自动领取回执、主动进度和最终结果都防重复。

## 兼容与撤销

CPJ 仍保持旧通知模式；已安装的监控订阅、通用发言许可、目标和 Work 用途不升级。新默认入口下，旧 CPJ / Work 接入收进高级区；只有已有旧连接的房间继续展开它，避免旧用户失去入口。

直接任务结果不要求额外的通用聊天发言许可。新 dot 的成员和接入卡片限定当前会话，不会因为同项目存在其他聊天而全房间展示。

「移除 dot 并停止新任务」撤销位置、停用原任务规则和相关投递；当前已开始操作保留原记录和实际回执，不能因撤销再执行一遍。其他授权、项目映射或目标主机密钥变更同样使原接入失效。共享同一个 MCP grant 的多个宿主不能仅凭名称或加入码获得密码学聊天身份；界面不作此承诺。

## 验证与真实宿主验收

新增测试 `tests/test_collaboration_dots.py` 覆盖一次接入、唯一订阅、权限不增加、快照变更、跨连接拒绝、旧 CPJ、不可变基线、分页、重放、进度、结果、撤销、签名验证、投递重试与重复唤醒。

`tests/test_collaboration_dots_flow.py` 实际启动隔离 Hub 和 Agent，并通过真实 MCP 请求创建、读取文件和运行命令；重启 Hub 后处理连续两项任务，核对磁盘文件、六个原始操作和原话题回传。浏览器用 Chromium 桌面/手机及 WebKit 手机执行添加、复制、@ 选择、连续交办、同话题后续任务及取消交办。测试仅给一次性测试 Agent 打开 Shell，不修改任何实际部署节点。

外部 dot 宿主在自动化测试中是明确标注的接收器/消费者夹具，不是实际模型。测试成功证明 CodePier 侧协议、持久队列、浏览器、Hub、Agent 和回传链路；不等于证明真实 dot 已建立原生订阅并自主调用插件。

真实宿主最终验收须在升级后的面板创建一个 CPD 位置，到真实 dot 发送它的加入指令并完成宿主确认；先发一个只读验证任务，再发第二个连续任务，核对真实领取、原操作回执及两条原话题结果。未取得这些证据时，不将状态写成「原生 dot 端到端已验收」。
